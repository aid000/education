Quick Overview

Comparison-based sorting algorithms that rearrange a sequence by comparing elements. The two most quizbowl-tested are quicksort (in-place, pivot-based, divide-and-conquer) and mergesort (stable, divide-and-conquer, guaranteed O(n log n)).

Quicksort invented byTony Hoare, 1959–1960
Mergesort invented byJohn von Neumann, 1945
ParadigmDivide and conquer (both)
Comparison lower boundΩ(n log n) for any comparison sort
Quicksort complexity
Best / Avg: O(n log n)  |  Worst: O(n²)
Worst case occurs when pivot is always the smallest or largest element (already-sorted input with naive pivot choice).
Mergesort complexity
All cases: O(n log n)  |  Space: O(n) auxiliary
Guaranteed — no bad pivot choices. Extra memory is the trade-off; standard implementation is stable.

Core shared idea

  • Both use divide and conquer: split the problem, recurse, combine.
  • Quicksort does the work before recursing (partitioning); mergesort does the work after recursing (merging).
  • Both achieve O(n log n) average / best case — mergesort guarantees it, quicksort does not.
  • The O(n log n) lower bound is proven by decision-tree argument: any comparison sort must make at least log₂(n!) comparisons.

High-Yield Concepts (Very Common)

The most frequently tested facts. power = hard early clue to buzz on. recog = recognition / mid-clue.

Quicksort
Tony Hoare · 1959–1960 · in-place · not stable by default
powerInvented by C. A. R. (Tony) Hoare while working on machine translation at Moscow State University, 1959–60; published 1962 in The Computer Journal.
recogSelects a pivot element; partitions the array into elements ≤ pivot (left) and > pivot (right); recurses on each subarray.
recogAverage-case O(n log n); worst case O(n²) when pivot is always the extreme element.
recogIn-place partitioning — uses O(log n) stack space on average (no extra array needed).
recogDespite O(n²) worst case, fastest in practice on random data due to small constant factors and cache friendliness.
recogNot stable in standard form — equal elements may be reordered.
recogPivot selection strategies: first element, last element, median-of-three, random — random pivot reduces worst-case probability to nearly zero.
Mergesort
John von Neumann · 1945 · stable · O(n) extra space
powerConceived by John von Neumann in 1945 — one of the earliest algorithms ever designed for a stored-program computer (EDVAC context).
recogDivides array in half, recursively sorts each half, then merges the two sorted halves — the merge step is the key operation.
recogGuaranteed O(n log n) in all cases — best, average, and worst.
recogRequires O(n) auxiliary space (extra array for merging) — main practical disadvantage vs. quicksort.
recogStable sort — equal elements preserve their original relative order.
recogPreferred for linked lists (no random-access penalty) and external sorting (data too large to fit in memory — sort chunks on disk, merge).
recogThe recurrence T(n) = 2T(n/2) + O(n) solves to O(n log n) by the Master Theorem.
Hoare Partition Scheme
The original quicksort partition · two-pointer approach
powerUses two pointers starting from each end, moving inward until they find a pair to swap; fewer swaps than Lomuto's scheme on average.
recogThe alternate Lomuto partition scheme (pivot = last element, single scan left-to-right) is simpler to code but performs slightly worse.
Comparison-Sort Lower Bound
Decision-tree argument · Ω(n log n) is tight
powerAny algorithm that sorts by comparing element pairs must make at least log₂(n!) comparisons in the worst case; by Stirling's approximation, log₂(n!) = Θ(n log n).
recogThe decision tree has n! leaves (all permutations); height ≥ log₂(n!) — this proves no comparison sort beats O(n log n).
recogNon-comparison sorts (radix, counting, bucket) can beat O(n log n) by exploiting structure of keys — they are NOT comparison-based.

Deeper Cuts (Hard Clues)

Related algorithms and results that appear as hard early clues. One-line identifiers.

Heapsort In-place O(n log n) worst-case; uses a max-heap; not stable; worse cache performance than quicksort.
Timsort Hybrid mergesort + insertion sort; default in Python and Java; exploits natural runs; stable; O(n log n) worst, O(n) best.
Introsort Quicksort + heapsort fallback when recursion depth exceeds 2·log n; used in C++ STL std::sort; guarantees O(n log n).
Insertion sort O(n²) but O(n) on nearly sorted data; used as base case in Timsort and recursive cutoffs; stable; in-place.
Bubble sort Repeatedly swaps adjacent out-of-order pairs; O(n²) always; stable; famous as worst practical algorithm for large n.
Selection sort Finds minimum, places it at front, repeats; O(n²) always; minimizes swaps (O(n)); not stable in standard form.
Radix sort Sorts integers digit by digit using counting sort; O(d·n) where d = digits; beats O(n log n) for fixed-width integers.
Counting sort Creates frequency array; O(n + k) where k = range; only for integer keys in bounded range; stable; linear time.
Bucket sort Distributes elements into buckets, sorts each; O(n + k) average for uniform distribution; good for floating-point data.
Master Theorem Solves recurrences of form T(n) = aT(n/b) + f(n); quicksort and mergesort are canonical textbook examples.
Shellsort Generalization of insertion sort using gap sequences; O(n log² n) with Hibbard gaps; not stable; in-place.
k-way mergesort Splits into k parts instead of 2; used in external sorting; merge step uses a min-heap of size k.

Recognition / Clue Bank

Key people

  • Tony Hoare — quicksort (1959); also Hoare logic, CSP, Turing Award 1980
  • John von Neumann — mergesort (1945); also EDVAC architecture, game theory, quantum mechanics
  • Donald Knuth — analyzed sorting algorithms exhaustively in The Art of Computer Programming vol. 3 (Sorting and Searching)

Key terms

  • Pivot — element chosen to partition around (quicksort)
  • Partition — rearrange so left ≤ pivot ≤ right
  • Merge — combine two sorted sequences into one
  • Stable sort — equal elements keep original order
  • In-place — O(1) extra space (ignoring recursion stack)
  • Divide and conquer — split, recurse, combine
  • Recurrence relation — T(n) = 2T(n/2) + O(n)

Complexity cheat sheet

  • Mergesort: O(n log n) all cases, O(n) space
  • Quicksort avg: O(n log n), O(log n) stack space
  • Quicksort worst: O(n²) — sorted input + bad pivot
  • Heapsort: O(n log n) all cases, O(1) space
  • Insertion sort: O(n²) worst, O(n) best (nearly sorted)
  • Lower bound: Ω(n log n) for any comparison sort

Practical / "also appears in"

  • Python's list.sort() and sorted() use Timsort
  • C++ std::sort uses Introsort (quicksort + heapsort)
  • Java Arrays.sort(Object[]) uses Timsort
  • External sorting on disk uses mergesort (sequential I/O)
  • Quicksort's worst case triggers on already-sorted data with naive pivot
  • Mergesort is preferred for linked lists — no random access needed

Comparison Traps

Don't confuseHow to tell them apart
Quicksort vs. MergesortQuicksort: in-place, not stable, O(n²) worst case, fastest in practice. Mergesort: stable, O(n) space, guaranteed O(n log n). Key: "guaranteed" = mergesort; "worst case O(n²)" = quicksort.
Mergesort vs. HeapsortBoth O(n log n) worst case. Mergesort is stable and needs O(n) space; heapsort is in-place and not stable. Heapsort uses a heap data structure; mergesort does not.
Quicksort vs. QuickselectQuickselect uses quicksort's partition to find the k-th smallest element in O(n) average — it does NOT fully sort. Same partition logic, different recursion choice (only one side).
Stable vs. unstable sortA sort is stable if equal-key elements keep their original relative order. Mergesort, Timsort, insertion sort, counting sort = stable. Quicksort (standard), heapsort, selection sort = NOT stable.
Comparison sorts vs. radix/countingComparison sorts have Ω(n log n) lower bound. Radix and counting sorts bypass this by not comparing elements directly — they exploit structure of integer keys and run in O(n·d) or O(n+k).
Hoare vs. Lomuto partitionHoare: two pointers from both ends, fewer swaps, pivot ends up somewhere in the middle. Lomuto: single pointer, pivot = last element, simpler but slower. Both are for quicksort.
Mergesort recurrence vs. binary searchBoth give T(n) = T(n/2) + O(something), but mergesort is 2T(n/2) + O(n) → O(n log n), while binary search is T(n/2) + O(1) → O(log n).

🔗 Big picture: why sorting algorithms matter in quizbowl Sorting sits at the intersection of CS theory (decision trees, information theory, recurrences), algorithm design (divide-and-conquer, the Master Theorem), and practical systems (every language's standard library). The O(n log n) lower bound is a canonical application of information-theoretic arguments — log₂(n!) comes from the number of bits needed to encode a permutation. Quicksort's inventor Tony Hoare later developed Hoare logic (formal program verification) and CSP (communicating sequential processes), so his name appears across theory tossups. Von Neumann's mergesort connects to the broader EDVAC/stored-program computer history. On the math side, the Master Theorem that solves mergesort's recurrence is itself a frequent answer.
