Week 4 · Lecture 4

Combinational Logic Design

Writing RTL for stateless logic — and the inferred-latch trap that catches everyone.

🎯 Learning Objectives

  • Describe combinational outputs as pure functions of current inputs using assign or always @(*).
  • Recognize how RTL operators map to real hardware — + builds an adder, * builds a (large) multiplier.
  • Avoid inferred latches by assigning every output in every branch (an else or a default).
  • Explain how synthesis maps RTL onto a gate-level netlist from a standard-cell library.
  • Build a 4:1 multiplexer with a case statement and spot the missing-default latch bug.

4.1Combinational RTL

Combinational logic is stateless: the output is a pure function of the current inputs, with no memory of the past. In RTL you describe it two ways — a continuous assign statement, or a procedural always @(*) block whose sensitivity list (the *) automatically includes every signal it reads.

assign y = a & b;  ·  always @(*) y = a & b;Both describe the same combinational AND gate — output follows inputs the instant they change.

This style covers the workhorses of any chip: gates (AND/OR/NOT), adders, multiplexers, and decoders. You write what the output equals; you never wire up individual transistors.

AnalogyCombinational RTL is like a spreadsheet formula in a cell: it recomputes instantly the moment any of its inputs change. You type what the cell equals (=A1+B1); the spreadsheet decides how to evaluate it. In RTL you write what the logic equals, and the synthesizer decides which gates to build it from.

4.2Arithmetic in RTL

The big payoff of RTL: arithmetic operators map directly onto real hardware. You describe the operation at a high level and the synthesis tool builds the actual circuit. The most common mappings:

assign sum = a + b;  ⟹  a hardware adderAnd assign prod = a * b; ⟹ a hardware multiplier — correct, but physically large and slow.

This is why a single + is cheap but a * is something you think twice about: a multiplier can be hundreds of times the area of an adder. You describe the operation; the tool builds it — but the operator you choose has direct, sometimes expensive, hardware consequences.

4.3Avoiding Inferred Latches

Here is the trap that catches everyone. In a combinational always @(*) block, you must assign every output in EVERY branch. If some path through the block leaves an output unassigned, the synthesizer assumes you want it to hold its old value — and the only hardware that holds a value is a latch. You get a storage element you never asked for.

incomplete if (no else) ⟹ inferred latch  ·  complete if/else ⟹ pure logic (a mux)

The fix is simple and mechanical: give every if an else, give every case a default, or assign a default value to the output at the top of the block before any branching.

Common mistakeAn incomplete combinational assignment — a missing else or default — makes the synthesizer infer an UNWANTED LATCH. Always cover every branch. Remember too that + and * in RTL become real adders and multipliers that cost silicon area, and that combinational logic has no clock — its output simply follows the inputs.

4.4From RTL to Gates

RTL is a description, not a circuit. The step that turns it into hardware is synthesis: the tool reads your combinational RTL and maps it onto a gate-level netlist — a connected list of concrete cells (AND2, OR3, MUX2, FA, …) drawn from a standard-cell library supplied by the foundry.

combinational RTL  —(synthesis)→  gate-level netlist of standard cells

Each cell in the library is a pre-characterized layout with known area, delay, and power. Synthesis picks and connects them to realize exactly the function you described, while trying to meet your timing and area constraints. The netlist is what later flows into place-and-route to become a physical layout.

✦ Worked Example

Describe a 4:1 multiplexer that routes one of four data inputs (d0..d3) to y based on a 2-bit select s, using a case statement. Show why the default matters.

// 4:1 mux — combinational always block
always @(*) begin
  case (s)
    2'b00: y = d0;
    2'b01: y = d1;
    2'b10: y = d2;
    2'b11: y = d3;
    default: y = d0;   // covers any unlisted value
  endcase
end
  1. All cases covered: the four explicit cases (plus the default) assign y on every possible path, so the block is purely combinational.
  2. What it synthesizes to: a clean mux tree — a 2-level network of 2:1 muxes steered by the two select bits. No storage, no clock.
  3. The classic bug: if you omit the default (and didn't list all values), an unlisted select leaves y unassigned on that path — so the tool infers a latch on y to hold its old value.
  4. Lesson: for a 2-bit select all four values are listed, so it's safe here — but adding a default is the habit that protects you whenever a select is wider or branches are incomplete.

🛠️ Hands-On: simulate, then synthesize the netlist

Write a mux and an adder, verify them in simulation with Icarus Verilog, then synthesize with Yosys and inspect the resulting gate netlist.

// comb.v — a 4:1 mux and a 4-bit adder
module mux41(input [3:0] d, input [1:0] s, output reg y);
  always @(*) begin
    case (s)
      2'b00: y = d[0];
      2'b01: y = d[1];
      2'b10: y = d[2];
      default: y = d[3];   // covers 2'b11 — no latch
    endcase
  end
endmodule

module add4(input [3:0] a, b, output [4:0] sum);
  assign sum = a + b;       // synthesizes an adder
endmodule

Simulate with Icarus: iverilog -o comb comb.v tb.v && vvp comb. Then synthesize with Yosys: yosys -p "read_verilog comb.v; synth; stat" and read the stat report. Expected: the adder shows up as full-adder / arithmetic cells and the mux as a small tree of mux cells — with zero latches or flip-flops, confirming the logic is fully combinational. Now delete the default and re-run synth: Yosys will warn about an inferred latch.

C. Combinational logic is stateless and clockless — the output is a pure function of the current inputs and changes whenever they do.
