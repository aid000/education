Week 5 · Lecture 5

Sequential Logic & Memory

Registers, finite state machines, and on-chip memory in RTL — plus the timing constraint that ties them together.

🎯 Learning Objectives

  • Infer flip-flops in RTL with an always @(posedge clk) block, and add a reset.
  • Describe the classic finite-state-machine structure: state register + next-state logic + output logic.
  • Choose the right on-chip storage: register files for small state, SRAM macros for large memory.
  • State the register-to-register timing constraint and compute the maximum clock frequency.
  • Use nonblocking assignments for clocked logic — and avoid the classic sequential RTL mistakes.

5.1Registers in RTL

Combinational logic (last lecture) had no memory — its output depended only on the present inputs. Sequential logic remembers. The element that holds a value across time is the flip-flop (a 1-bit register); a bus of them is a register.

In RTL (register-transfer level) you don't instantiate flip-flops by hand — you infer them. A synthesis tool sees an always block triggered on the rising clock edge and builds the flops for you:

always @(posedge clk)  ⟹  flip-flops inferredThe signals assigned inside the clocked block become register outputs.

A reset sets the registers to a known initial state. It can be synchronous (the reset only takes effect on a clock edge) or asynchronous (it takes effect immediately, in the sensitivity list):

// synchronous reset
always @(posedge clk)
  if (rst) q <= 0; else q <= d;Async reset adds or posedge rst to the sensitivity list.

5.2Finite State Machines in RTL

A finite state machine (FSM) is the workhorse for control: traffic-light controllers, bus protocols, instruction decoders. In RTL an FSM has three pieces that always appear together:

The three blocks

1. State register — a clocked block that holds the current state. 2. Next-state logic — combinational logic that, from the current state and the inputs, computes which state to enter next. 3. Output logic — combinational logic that drives the outputs from the current state (and, in a Mealy machine, the inputs).

The split is deliberate: only the state register is clocked (nonblocking, edge-triggered); the next-state and output logic are pure combinational blocks. This separation is what makes FSMs easy to read, simulate, and synthesize.

5.3On-Chip Memory

Storage on a chip comes in two flavors, and choosing the wrong one wastes huge amounts of area.

Small storage → register files

A handful of words — a CPU's register file, a small FIFO, FSM state — is built from flip-flops. Flops are flexible: any port count, easy to read/write combinationally, and they synthesize from ordinary RTL. The cost is area: each bit is a full flip-flop.

Large storage → SRAM macros

For kilobytes or megabytes (caches, buffers, frame stores), you do not build memory from flip-flops. You drop in a compiled SRAM macro — a dense, pre-laid-out memory block generated by a memory compiler. An SRAM bit cell is a tight 6-transistor structure, far denser than a flip-flop, so a macro stores far more bits per unit area.

small / fast-access state → register file (flops)
large bulk storage → SRAM macro (compiled)SRAM macros are dramatically denser per bit than flip-flop arrays.
AnalogySequential RTL is a board game. The clock is each "turn"; the registers hold the current state of the board; and the next-state logic works out the move. Nothing changes mid-turn — the whole board updates at once, exactly at the turn boundary (the clock edge). Players don't move pieces one at a time between turns; everyone resolves simultaneously when the turn ticks over.

5.4Timing Constraints

Registers update simultaneously on the clock edge — but only if the data has had time to arrive. The clock is therefore a constraint: its period must be long enough to cover the slowest path between two registers.

Trace one register-to-register path. After a clock edge, the launching flip-flop takes clock-to-Q (tcq) to present its output; the signal then propagates through combinational logic (tlogic); and it must arrive at the capturing flip-flop a setup time (tsetup) before the next edge. So:

Tclk ≥ tcq + tlogic + tsetupThe period must cover the worst (slowest) register-to-register path on the chip.

This is the heart of static timing analysis — checking every register-to-register path against the clock period — which you'll study systematically in Week 7.

✦ Worked Example

A register-to-register path has clock-to-Q of 0.1 ns, combinational logic delay of 1.5 ns, and setup time of 0.2 ns. Find (a) the minimum clock period and (b) the maximum clock frequency.

  1. Sum the path delays: Tclk ≥ tcq + tlogic + tsetup = 0.1 + 1.5 + 0.2 = 1.8 ns.
  2. Minimum period: the clock can be no faster than 1.8 ns per cycle.
  3. Maximum frequency: fmax = 1 / Tclk = 1 / (1.8 × 10⁻⁹ s) ≈ 556 MHz.
  4. Takeaway: shrink the logic delay (fewer levels, faster gates) to push the frequency higher.
Common mistakesThree sequential-RTL traps: (1) use nonblocking <= for clocked (sequential) logic — blocking = in a clocked block causes simulation race bugs. (2) Build large memories from SRAM macros, not flip-flop arrays — flops are far less dense and will blow your area budget. (3) The clock period must satisfy the slowest register-to-register path, not the average — one slow path limits the whole chip.

🛠️ Hands-On: write, simulate, and synthesize an FSM

This is your Week-5 project checkpoint: your RTL should be written and simulated by the end of the week. Write a small FSM or counter in Verilog, simulate it with Icarus + GTKWave, then synthesize it with Yosys.

// 2-bit counter — Lecture 5 checkpoint (counter.v)
module counter(input clk, input rst, output reg [1:0] q);
  always @(posedge clk)        // infers 2 flip-flops
    if (rst) q <= 2'b00;       // synchronous reset
    else     q <= q + 1'b1;    // nonblocking assignment
endmodule

Simulate: compile with iverilog -o counter.vvp counter.v tb.v, run vvp counter.vvp (dump a VCD), then open the waveform in gtkwave dump.vcd and confirm q advances on each clock edge and resets to 0. Synthesize: yosys -p "read_verilog counter.v; synth; stat" and check the report shows 2 inferred flip-flops (DFFs).

A. An edge-triggered clocked block infers flip-flops — the signals assigned inside it become register outputs that update on the clock edge.

Q2. A classic RTL finite state machine has…
A. only an adder
B. a state register, next-state logic, and output logic
C. a single wire
D. no clock
Show answer

B. The canonical FSM has three parts: a clocked state register, combinational next-state logic, and combinational output logic.

Q3. Large on-chip memory is best built from…
A. flip-flop arrays
B. DRAM on-chip
C. dedicated SRAM macros (denser than flip-flop arrays)
D. the register file only
Show answer

C. Compiled SRAM macros pack far more bits per unit area than flip-flops. Flop-based register files are only for small storage.

Q4. The clock period must be at least…
A. the average path delay
B. one gate delay
C. the reset time
D. the slowest register-to-register path delay plus setup
Show answer

D. T_clk ≥ t_cq + t_logic + t_setup for the worst path. One slow path limits the whole chip's frequency.

Q5. For clocked sequential logic you should use…
A. blocking (=) assignments
B. nonblocking (<=) assignments
C. continuous assign
D. no assignment
Show answer

B. Nonblocking <= models the simultaneous edge update correctly. Blocking = in a clocked block causes simulation races.

✓ What you learned

  • An always @(posedge clk) block infers flip-flops; a reset (sync or async) sets their initial state.
  • The RTL FSM = state register + next-state logic + output logic, with the state fed back.
  • On-chip storage: small → register files (flops); large → dense SRAM macros, never flop arrays.
  • The clock is a constraint: T_clk ≥ t_cq + t_logic + t_setup on the slowest path (worked: 1.8 ns ⟹ ~556 MHz).
  • Used nonblocking <= for clocked logic, and ran the Icarus → GTKWave → Yosys flow.
