VLSI Overview & Design Flow

How a chip goes from an idea to a manufacturable layout — and the open-source tools for each step.

🎯 Learning Objectives

  • Define VLSI and explain why abstraction is the only way to manage millions–billions of transistors.
  • List the abstraction levels: behavioral/RTL → logic gates → transistors → physical layout.
  • Walk the RTL-to-GDSII flow stage by stage, and explain what "tape-out" means.
  • Contrast full-custom, standard-cell ASIC, and FPGA design styles.
  • Name the recurring design challenges — timing, power, area, verification — and the open tool for each flow stage.

1.1What VLSI Is

VLSI — Very-Large-Scale Integration — is the practice of integrating millions to billions of transistors onto a single chip. A modern processor has more transistors than there are stars in the Milky Way, and no human could place them one at a time. The only way to manage that scale is abstraction: working at a high level and letting tools fill in the detail below.

VLSI is where two earlier threads of this track meet. The fabrication physics from C2 tells you what a transistor is and how it's manufactured; the architecture ideas from C3 tell you what the chip should compute. VLSI design is the discipline that turns an architectural intent into a pattern of transistors a fab can actually build.

AnalogyVLSI design is like building a city from a master plan. You don't lay every brick by hand. You work first at the level of zoning (what goes where — this is your RTL), then blueprints (the gate-level structure of each building), then actual construction (the physical layout). Each level abstracts away the one below it, so the city planner never has to think about individual bricks.

1.2Abstraction Levels

A chip is described at several levels, each hiding the detail of the one beneath it. You design at the top and the tools translate downward:

behavioral / RTL  →  logic gates  →  transistors  →  physical layout (GDSII)

At the behavioral/RTL level you describe what the circuit does — register transfers and logic — in a language like Verilog, without saying which gates implement it. At the logic-gate level the design is a netlist of ANDs, ORs, flip-flops. At the transistor level each gate becomes a handful of MOSFETs. Finally the physical-layout level is the actual geometry of polygons on each mask layer, stored as a GDSII file. Each step down adds detail; each step up hides it so a human can reason about the design.

1.3The RTL-to-GDSII Flow

The heart of digital VLSI is a pipeline that turns hand-written RTL into a finished GDSII layout. It is a sequence of mostly automated tool steps:

RTL → synthesis → netlist → floorplan → placement → CTS → routing → signoff → GDSII

Starting from RTL (Verilog), synthesis compiles it into a gate netlist. Floorplanning decides the chip outline and where big blocks and I/O go; placement drops each standard cell into a row. Clock-tree synthesis (CTS) builds a balanced network that delivers the clock to every flip-flop with minimal skew. Routing connects every pin with metal wires. Signoff is the final round of timing, DRC and LVS checks. The output is the GDSII file — and shipping it to the fab is called tape-out.

1.4ASIC vs FPGA & the Design Challenges

There's more than one way to realize a digital design in silicon:

Full-custom

Every transistor and wire is hand-tuned for maximum performance and density. Used for the most demanding blocks (memories, analog, top-end CPUs) — but enormously labor-intensive.

Standard-cell ASIC

The design is built from a library of pre-characterized cells (the RTL-to-GDSII flow above). Far less effort than full-custom, near-custom efficiency. This is how most chips are made — but a fabricated ASIC is fixed forever.

FPGA

A field-programmable gate array is a pre-fabricated chip of configurable logic blocks you program after manufacturing. No fab run, instant turnaround — at the cost of speed, power, and per-unit price compared to an ASIC.

Common mistakeThe RTL→GDSII flow is a sequence of (largely automated) tool steps — you are not hand-drawing transistors. And "tape-out" means releasing the final GDSII to the fab (the name comes from the era when layouts shipped on magnetic tape). It does not mean testing the finished chip.

Across all of these, the same four design challenges recur and trade off against one another: timing (does it run at the target clock?), power (does it fit the energy budget?), area (does it fit the die?), and verification (does it actually do what the spec says?).

✦ Worked Example

Map each stage of the RTL-to-GDSII flow to the open-source tool that performs it in the OpenLane flow:

  1. RTL simulation (check the Verilog behaves) → Icarus Verilog or Verilator.
  2. Logic synthesis (RTL → gate netlist) → Yosys.
  3. Floorplan / placement / CTS / routing → OpenROAD (driven end-to-end by OpenLane).
  4. Layout viewing / editing → KLayout or Magic.
  5. Signoff DRC / LVS (design-rule & layout-vs-schematic checks) → Magic (DRC) and Netgen (LVS).

OpenLane is the orchestration script that chains these together so a single command takes Verilog all the way to a GDSII.

🛠️ Hands-On: run the OpenLane flow end to end

This is the Week-1 project setup. Install the Docker-based OpenLane flow — which bundles Yosys, OpenROAD, and KLayout/Magic — and run its built-in example design all the way to a GDSII.

# clone OpenLane and pull the Docker image + PDK
git clone https://github.com/The-OpenROAD-Project/OpenLane
cd OpenLane
make            # pulls the prebuilt Docker image and Sky130 PDK
make test       # runs the built-in spm example: RTL → GDSII

A clean make test ends with "Basic test passed" and writes a GDSII under designs/spm/runs/. Open that .gds in KLayout to see your first hand-run layout. Then peek at the run logs to spot each stage — synthesis, placement, CTS, routing, signoff — in order.

❓ Lecture 1 Quiz

5 questions · click "Show answer" to check yourself.

Q1. The VLSI design flow proceeds as…
A. RTL → synthesis → place & route → signoff → GDSII
B. GDSII → RTL → test
C. layout → synthesis → RTL
D. fab → RTL → tape-out
Show answer

A. You start from RTL, synthesize to gates, then place & route, run signoff checks, and emit the GDSII. The other orderings run the pipeline backwards.

Q2. "Tape-out" means…
A. testing the finished chip
B. sending the final GDSII layout to the fab for manufacturing
C. simulating the RTL
D. installing the tools
Show answer

B. Tape-out is the release of the finished GDSII to the fab. The name dates from when layouts were shipped on magnetic tape — it is not the testing step.

Q3. Abstraction in VLSI…
A. makes chips slower
B. lets designers manage complexity by hiding lower-level detail
C. removes the need for layout
D. is only for FPGAs
Show answer

B. Abstraction is the only way to manage billions of transistors — you work at a high level (RTL) and tools handle the detail beneath. Layout is still required.

Q4. In the open-source flow, logic synthesis (RTL → gates) is done by…
A. KLayout
B. GTKWave
C. Yosys
D. Magic
Show answer

C. Yosys is the open-source synthesis tool. KLayout/Magic are for layout, and GTKWave views simulation waveforms.

Q5. GDSII is…
A. a Verilog dialect
B. a simulation waveform
C. the layout file format describing the physical mask geometry
D. a timing report
Show answer

C. GDSII is the binary format that stores the chip's physical mask polygons — the file you send to the fab at tape-out.

✓ What you learned

  • VLSI integrates millions–billions of transistors; abstraction is the only way to manage that complexity.
  • The abstraction levels: behavioral/RTL → logic gates → transistors → physical layout (GDSII).
  • The RTL-to-GDSII flow: RTL → synthesis → netlist → floorplan → placement → CTS → routing → signoff → GDSII, then tape-out to the fab.
  • Design styles — full-custom, standard-cell ASIC, FPGA — and the four recurring challenges: timing, power, area, verification.
  • The open tools per stage: Yosys (synthesis), OpenROAD/OpenLane (place & route), KLayout/Magic (layout), Magic/Netgen (signoff).
