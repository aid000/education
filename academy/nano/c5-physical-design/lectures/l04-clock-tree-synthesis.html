Clock Tree Synthesis

Getting one clock edge to millions of flip-flops at the same instant.

🎯 Learning Objectives

  • Explain why a chip needs clock tree synthesis (CTS) to distribute the clock.
  • Define clock skew (arrival-time difference) and insertion delay / latency (source-to-leaf delay).
  • Describe clock tree structures — H-trees, meshes, and buffered trees — and how CTS balances branches.
  • Account for on-chip variation (OCV) and corners, and recognize deliberate "useful skew."
  • Show how skew eats into the timing budget available to the data path.

4.1Why CTS

Every synchronous chip runs off a clock, and that single clock signal must reach every flip-flop on the die — anywhere from thousands to millions of them. You cannot drive that many loads from one source: the signal would be hopelessly weak and slow, and different flops would see the edge at wildly different times.

Clock tree synthesis (CTS) is the step that builds a buffered distribution network from the clock source out to all those flip-flops. Its goal is that the active clock edge arrives at all of them nearly simultaneously — with low skew — while keeping the total source-to-leaf delay (the latency) controlled.

CTS happens after placement: the flops already have locations, so the tool knows where the leaves are and can build a tree that physically reaches them. The clock is special — it is not routed like an ordinary signal net; it gets its own carefully balanced, buffered tree.

AnalogyCTS is like conducting a huge choir spread across an entire stadium. One conductor at the podium can't be seen by every singer in time, so you place relay conductors (the clock buffers) throughout the stands, each relaying the beat onward. Done well, every singer gets the downbeat at the same instant. Skew is just how badly out-of-time the worst singer is.

4.2Skew & Latency

Two numbers describe how well the clock tree does its job:

skew = max difference in clock-arrival times between flip-flopsHow far apart, in time, the earliest and latest flops receive the same edge. Lower is better.
insertion delay (latency) = source-to-leaf delayHow long the edge takes to travel from the clock source all the way out to a leaf flip-flop.

Skew is the quantity CTS works hardest to minimize: if two flops that talk to each other see the edge at different times, that mismatch directly attacks the timing margin between them. Insertion delay is a different metric — it is the absolute latency through the tree. CTS minimizes skew while managing latency (deeper trees with more buffer levels tend to have more latency).

Common mistakeKeep three things straight. (1) CTS minimizes SKEW — the goal is simultaneous arrival; latency/insertion-delay is a separate metric, not the same thing as skew. (2) The clock buffers are inserted during CTS — the clock is special, built after placement as its own balanced tree, not routed like an ordinary signal first. (3) Because of OCV (next section), you cannot assume every buffer delivers its nominal delay.

4.3Clock Tree Structures

CTS can build the distribution network in several shapes, trading area and power against how tightly skew is controlled:

H-trees

A geometrically symmetric, recursively-branching layout (it looks like nested letter "H"s). Because every path from the source to a leaf is the same length, an H-tree gives naturally balanced delays and very low skew — at the cost of area and routing discipline.

Meshes (grids)

A dense grid of clock wire shorted together, driven from many points. The mesh averages out local differences, giving excellent skew, but it burns a lot of power and metal.

Buffered trees

The common, automated approach: CTS inserts clock buffers and inverters at successive levels, fanning the signal out and re-driving it so each branch stays strong. The tool sizes and places these buffers to balance the branches so all leaves see the edge at nearly the same time.

4.4OCV & Corners

In an ideal world every clock buffer would have exactly its nominal delay, and a balanced tree would have zero skew. Reality is messier. On-chip variation (OCV) means two identical buffers, placed at different spots on the die, run at slightly different speeds — because of small differences in transistor doping, metal thickness, local supply voltage, and temperature across the chip.

So CTS must be robust across corners — the combinations of process, voltage, and temperature (e.g. slow/cold, fast/hot) the chip might experience. A tree that is balanced only at the nominal corner can still violate timing once OCV pushes one branch faster and another slower.

Useful skew

Skew is not always the enemy. Sometimes CTS deliberately delivers the edge earlier or later to specific flops — useful skew — to "borrow" time for a tight data path. By launching a path slightly early or capturing it slightly late, the tool can fix a timing violation that perfectly-zero skew could not.

✦ Worked Example

A block runs on a 2 ns clock period. CTS leaves 0.2 ns of clock skew between the launching flip-flop and the capturing flip-flop. How much time is actually available for the data path between them, and what does better CTS buy back?

  1. Nominal budget: with zero skew, the data path would have the full clock period, T = 2 ns.
  2. Subtract the skew: the capturing edge arrives 0.2 ns "off," so the effective time available = T − skew = 2 − 0.2 = 1.8 ns.
  3. Interpretation: skew directly eats the timing budget — the logic must finish in 1.8 ns, not 2 ns.
  4. Payoff of better CTS: driving skew toward 0 hands that 0.2 ns back to the logic, giving the data path more margin (or allowing a faster clock).

🛠️ Hands-On: run CTS in OpenROAD

OpenROAD performs clock tree synthesis with its clock_tree_synthesis command (the TritonCTS engine), then reports the skew and insertion delay so you can see what the tree achieved. Run it on a placed block, then read the clock report.

# OpenROAD Tcl — CTS on a placed block
read_db placed.odb           ; load the placed design
clock_tree_synthesis \
  -buf_list CLKBUF_X1        ; clock buffer cell(s) to insert
set_propagated_clock [all_clocks]
report_clock_skew            ; max skew between leaf flops
report_clock_latency         ; source-to-leaf insertion delay

Read the report: report_clock_skew gives you the worst-case skew, and report_clock_latency gives the insertion delay (latency) from source to leaves. Re-run with a different buffer list or target skew and watch how skew and latency trade off.

A. CTS builds a buffered distribution tree so the clock edge reaches all flip-flops with minimal skew. Power grid, signal routing, and floorplanning are separate steps.

C. the total wire length

B. Skew is the maximum difference in when the same clock edge arrives at different flops. It is distinct from frequency, wire length, and voltage.

Q3. CTS inserts…

B. antenna diodes

C. CTS inserts clock buffers and inverters at successive levels to re-drive the signal and balance the branches so all leaves arrive together.

C. delays vary across the die, so CTS must be robust to it

C. OCV means identical buffers run at slightly different delays across the die, so CTS must hold up across corners — you can't assume every buffer hits its nominal delay.

Q5. Clock skew effectively…
A. increases the clock period
