Floorplanning

The first and most consequential physical-design decision — where everything goes before a single standard cell is placed.

🎯 Learning Objectives

  • Define floorplanning as the first step of physical design and list what it fixes.
  • Pick a die size from a target core utilization (~60–75%) and explain why headroom matters.
  • Place large hard macros sensibly — at edges/corners, pins facing the logic that uses them.
  • Explain why the power grid (rings + straps) must be planned early.
  • Recognize why a bad floorplan is the costliest mistake to fix downstream.

1.1What Floorplanning Is

Floorplanning is the first step of physical design — it happens after logic synthesis hands you a netlist of gates, and before any standard cells are placed. In this step you make the big, structural decisions: you fix the die size and shape, place the I/O pads around the boundary, drop the large hard macros (SRAMs, IP blocks) into position, and define the core area and power grid.

Crucially, all of this is decided before the tool places the thousands of tiny standard cells. The floorplan is the empty stage; placement and routing then fill it in. Everything downstream — placement quality, routing congestion, timing closure — inherits the constraints you set here.

netlist → floorplan → placement → clock tree → routing → signoffFloorplanning is step one: die, I/O, macros, and power grid come first.

1.2Die Size & Utilization

You size the die to fit the design at a target core utilization — the fraction of the core area actually occupied by standard cells. Typical targets land around 60–75%. The leftover space isn't waste: it leaves room for routing tracks, buffer insertion, and timing fixes later.

utilization = (cell area) / (core area)Target ~60–75%. Higher leaves no room to route; lower wastes silicon.

The aspect ratio (width ÷ height of the core) matters too. A near-square core is often easiest to route, but a tall or wide block may be forced by I/O placement, macro shapes, or how the block must abut its neighbors at the chip level.

Watch the ceilingPush utilization toward 100% and the design becomes unroutable — there's literally no track space left for wires. The headroom is the budget the router spends.

1.3Macro Placement

Large hard macros — SRAM arrays, analog IP, pre-built blocks — are placed first, before standard cells. They're big, fixed-shape, and can't be reshaped by the tool, so they dictate where everything else can go. Convention is to push them to the edges and corners of the core, keeping the center open as a clean field for standard-cell placement.

Orientation matters: a macro should be flipped/rotated so its pins face the logic that talks to it, shortening the nets and easing routing. And you must leave channels — gaps between and around macros — so signal and power routing can pass through rather than dead-ending.

1.4Power-Grid Planning

Every gate on the chip needs VDD and VSS. The power grid delivers them as a mesh of rings (around the core and macros) and straps — wide metal lines running across the chip on the upper metal layers, dropping down through vias to the cell rows below.

You plan this grid early, during floorplanning, for one blunt reason: those straps occupy real routing tracks. Every track the power grid claims is a track signals can't use. If you skip the grid until later, you risk a design that can't be powered or routed — or worse, IR-drop problems that quietly slow down or break the chip.

AnalogyFloorplanning is like laying out a building's floor plan before any furniture arrives. First you fix the footprint of the building (the die). Then you install the big, immovable structures — the elevator shafts and the server room (your hard macros) — and run the electrical risers and conduit (the power grid). Only once those are locked in do you arrange the desks, chairs, and partitions (the standard cells) in whatever space is left. Get the elevators and risers wrong and no amount of clever desk-shuffling will save the building.
Common mistakeFloorplanning is done first and is the hardest step to undo. A bad floorplan dooms everything downstream — placement, routing, and timing all inherit its constraints, and fixing it usually means starting over. Two specific traps: setting utilization too high leaves no track space and makes the design unroutable; and skipping the power grid early bites you because it steals routing tracks you'll have already promised to signals.
✦ Worked Example

A block has a total standard-cell area of 1.0 mm². Targeting a core utilization of 70%, estimate the core area, then the die size after adding margin for macros and the I/O ring.

  1. Core area from utilization: utilization = cell area / core area, so core area = cell area / utilization = 1.0 / 0.70 ≈ 1.43 mm².
  2. Add macro + I/O margin: the core must also host hard macros and sit inside an I/O pad ring, so add headroom — roughly +10–15%.
  3. Die size: 1.43 mm² + margin ≈ 1.6 mm² total. A square die would be about √1.6 ≈ 1.26 mm on a side.
  4. Sanity check: at 70% utilization, ~30% of the core stays open for routing — exactly the headroom the router needs.

🛠️ Hands-On: run the floorplan step in OpenROAD

This is the Week-1 project setup. Install OpenROAD/OpenLane (the Docker image is easiest), then run a flow up through the floorplan step — set a die area and a target utilization — and open the result in KLayout.

# Pull the OpenLane Docker image and enter it
docker pull efabless/openlane:latest
docker run -it -v $(pwd):/work efabless/openlane:latest

# In the config, set the floorplan controls:
# FP_CORE_UTIL = 70        ; target core utilization (%)
# DIE_AREA = "0 0 1260 1260" ; or let util drive the size

# Run just the floorplan stage, then view it
flow.tcl -design my_design -to floorplan
klayout runs/.../results/floorplan/my_design.def

Inspect the result: you should see the die outline, the core area, and the power ring. Try changing FP_CORE_UTIL to 90 and re-running — note how much tighter (and harder to route) the core becomes.

Q1. Floorplanning is…
A. the last signoff step of the flow
B. the first physical-design step (die size, I/O, macros, power grid)
C. a logic-synthesis step
D. a simulation step
Show answer

B. Floorplanning is the first physical-design step — it fixes the die size and shape, places I/O and hard macros, and defines the core area and power grid, all before standard cells are placed.

Q2. Target core utilization is typically…
A. 100%
B. about 60–75% (leaving room for routing)
C. under 10%
D. exactly 50% always
Show answer

B. Around 60–75% is typical. The leftover space gives the router, buffer insertion, and timing fixes the headroom they need; 100% would be unroutable.

Q3. Large hard macros (SRAM/IP) are placed…
A. last, in the center of the core
B. randomly
C. first, usually at edges/corners with pins facing the logic
D. only after routing
Show answer

C. Macros are big and fixed-shape, so they go first — pushed to edges/corners, oriented so their pins face the logic that uses them, with channels left for routing.

Q4. The power grid should be planned…
A. after detailed routing
B. early, because it consumes routing resources
C. only if timing fails
D. never
Show answer

B. The grid's rings and straps occupy routing tracks, so it must be planned early — otherwise you risk an unroutable or unpowerable design with IR-drop problems.

Q5. A bad floorplan…
A. has no downstream effect
B. is fixed automatically by the router
C. only affects power
D. propagates to placement/routing/timing and is costly to fix later
Show answer

D. Floorplanning is first and hardest to undo — placement, routing, and timing all inherit its constraints, so a bad floorplan usually means starting over.

✓ What you learned

  • Floorplanning is the first physical-design step — it fixes die size/shape, I/O, macros, and power grid before any standard cell is placed.
  • Size the die from a target utilization (~60–75%), leaving routing headroom; aspect ratio matters too.
  • Hard macros go first, at edges/corners, pins facing the logic, with channels left for routing.
  • The power grid (rings + straps) is planned early because it consumes routing tracks.
  • A bad floorplan propagates to placement, routing, and timing — and is the costliest mistake to fix.
