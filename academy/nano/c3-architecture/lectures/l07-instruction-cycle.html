Week 7 · Lecture 7

Instruction Set & Execution Cycle

The CPU's language, and the fetch-decode-execute loop that runs it.

🎯 Learning Objectives

  • Define the instruction set architecture (ISA) as the hardware/software contract.
  • Contrast RISC (small, regular, fixed-length) with CISC (large, complex, variable-length).
  • Read an instruction as an opcode plus operand fields, and tell R-type from I-type formats.
  • Walk an instruction through the fetch → decode → execute → write-back → PC-update cycle.
  • Distinguish the ISA (the interface) from the microarchitecture (the implementation).

7.1The ISA

The instruction set architecture (ISA) is the contract between software and hardware. It defines everything a program can ask the CPU to do: the instructions (their opcodes), the registers available, and the formats used to encode each instruction in memory. A compiler emits only instructions the ISA promises; the CPU promises to carry every one of them out.

Two broad philosophies divide ISAs. RISC (Reduced Instruction Set Computer) keeps the set small and regular — few instructions, fixed length, simple addressing — so each is easy to decode and run fast (ARM, RISC-V). CISC (Complex Instruction Set Computer) offers a large, complex set with variable-length, multi-step instructions that do more per instruction (x86).

RISC → small · regular · fixed-length  ·  CISC → large · complex · variable-length
AnalogyThe ISA is the CPU's menu — the language it speaks. A program orders only dishes the menu lists, and the kitchen guarantees it can cook every one. RISC is a short menu of simple dishes done quickly; CISC is a long menu with elaborate combination plates.

7.2Instruction Formats

Every instruction is just a binary word split into fields. The first field is the opcode — it says what to do. The remaining operand fields say what to do it to: which registers, or an immediate constant. RISC uses a handful of fixed-length formats so the decoder always knows where each field sits.

R-type (register-register)

An R-type instruction operates on registers only: an opcode, a destination register rd, and two source registers rs1 and rs2. ADD R1, R2, R3 is R-type.

opcode | rd | rs1 | rs2All operands are registers — nothing is read from the instruction word as data.

I-type (immediate)

An I-type instruction replaces one source register with an immediate — a constant baked into the instruction itself: an opcode, rd, one source rs1, and the immediate. ADDI R1, R2, #4 is I-type.

opcode | rd | rs1 | immediate

7.3The Fetch-Decode-Execute Cycle

The CPU runs a program by repeating one loop, once for every instruction. The program counter (PC) holds the address of the instruction to run. The four core steps:

FETCH → DECODE → EXECUTE → WRITE-BACK → (update PC) → FETCH…

Fetch — read the instruction stored at the address in the PC. Decode — the control unit reads the opcode and generates the control signals that steer the datapath. Execute — the datapath/ALU performs the operation. Write-back — the result is written into the destination register (or memory). Update the PC — increment it to the next instruction, or load a branch target. Then the loop repeats.

Common mistakeThe ISA is the interface — what software sees — and is distinct from the microarchitecture, which is how the hardware actually implements it (two chips can share an ISA yet differ wildly inside). Also: the fetch-decode-execute cycle repeats for every instruction, and updating the PC (increment, or load a branch target) is part of the cycle — not an afterthought.

7.4A Simple RISC Example

The same cycle handles every instruction; only the execute and PC-update steps differ. Watch four common RISC instructions move through it:

ADD R1, R2, R3

Fetch the word; decode as an R-type add; the ALU computes R2 + R3; write the sum to R1; PC increments to the next instruction.

LOAD R1, [R2]

Fetch and decode; execute computes the memory address from R2; the value is read from memory and written back into R1; PC increments.

STORE R1, [R2]

Fetch and decode; execute computes the address from R2; R1's value is written to memory — there is no register write-back; PC increments.

BRANCH (e.g. BEQ R1, R2, target)

Fetch and decode; execute compares R1 and R2; if equal, the PC is set to the branch target instead of simply incrementing — this is how the PC-update step changes the flow of control.

✦ Worked Example

Trace ADD R1, R2, R3 (compute R1 = R2 + R3) through the full cycle, naming what happens at each step.

  1. Fetch: the CPU reads the instruction word stored at the address in the PC.
  2. Decode: the control unit recognizes the ADD opcode and sets the control signals — ALU-op = add and register-write = on.
  3. Execute: the ALU adds the contents of R2 and R3.
  4. Write-back: the resulting sum is written into register R1.
  5. Update PC: the PC increments to point at the next instruction, and the cycle repeats.

🛠️ Hands-On: a tiny instruction decoder in Verilog

The decode step is pure combinational logic: opcode in, control signals out. Build a minimal decoder and check that each opcode lights up the right signals — or, on paper, trace the cycle for a couple of instructions step by step.

// tiny instruction decoder — opcode -> control signals
module decoder(input [3:0] opcode,
               output reg alu_add, output reg reg_write,
               output reg mem_read, output reg is_branch);
  always @(*) begin
    {alu_add, reg_write, mem_read, is_branch} = 4'b0000;
    case (opcode)
      4'h0: begin alu_add=1; reg_write=1; end // ADD
      4'h1: begin reg_write=1; mem_read=1; end // LOAD
      4'h2: begin /* store: no reg_write */ end // STORE
      4'h3: begin is_branch=1; end             // BRANCH
    endcase
  end
endmodule

Drive opcode = 4'h0 (ADD) and confirm reg_write and alu_add are high while mem_read and is_branch stay low. Then try 4'h1 (LOAD) and predict the outputs before simulating.

❓ Lecture 7 Quiz

5 questions · click "Show answer" to check yourself.

Q1. The ISA defines…
A. the transistor layout of the chip
B. the clock speed
C. the instructions, registers, and formats the CPU understands (the hardware/software contract)
D. the cache size
Show answer

C. The ISA is the contract between software and hardware: the set of instructions, the registers, and the encoding formats. Transistor layout, clock speed, and cache size are microarchitecture/implementation details.

Q2. In the FETCH step…
A. the instruction at the PC's address is read
B. the ALU computes the result
C. the result is stored
D. the PC is reset
Show answer

A. Fetch reads the instruction word at the address held in the PC. Computing (execute), storing (write-back), and changing the PC happen in later steps.

Q3. RISC instruction sets favor…
A. many complex variable-length instructions
B. a small, regular, fixed-length instruction set
C. no registers
D. microcode only
Show answer

B. RISC means a small, regular, fixed-length set that's easy to decode and run fast. Large, complex, variable-length instructions are the CISC style.

Q4. After executing a non-branch instruction, the PC…
A. increments to the next instruction
B. stays the same
C. jumps to zero
D. decrements
Show answer

A. Updating the PC is part of every cycle. For a normal instruction it increments to the next one; only a taken branch loads a different target.

Q5. The ISA is distinct from…
A. the assembly language
B. the compiler
C. the microarchitecture (the specific hardware implementation)
D. the operating system
Show answer

C. The ISA is the interface (what software sees); the microarchitecture is how a particular chip implements it. Different microarchitectures can share one ISA.

✓ What you learned

  • The ISA is the hardware/software contract — the instructions, registers, and formats the CPU understands.
  • RISC (small, regular, fixed-length) vs CISC (large, complex, variable-length).
  • An instruction is an opcode plus operand fields — R-type (three registers) and I-type (an immediate).
  • The fetch → decode → execute → write-back → update-PC cycle repeats for every instruction.
  • The ISA (interface) is distinct from the microarchitecture (implementation).
