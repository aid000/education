Memory Hierarchy

Bridging the gap between a fast CPU and slow, cheap memory.

🎯 Learning Objectives

  • Explain the "memory wall" — why CPUs vastly outrun main memory.
  • Lay out the memory hierarchy from registers down to disk and state how each level trades speed for size and cost.
  • Define temporal and spatial locality and explain why they make caching work.
  • Contrast SRAM and DRAM cells and where each is used.
  • Compute average memory access time (AMAT) and reason about the cache-coherence problem.

9.1The Memory Wall

Over decades, CPU speed grew far faster than the speed of DRAM, the cheap, dense memory that holds main memory. The result is the memory wall: a modern processor can execute many instructions in the time it takes a single access to main memory to return. If every load and store had to wait on DRAM, a fast CPU would sit idle most of the time.

The fix is not one perfect memory — no technology is simultaneously fast, large, and cheap. Instead we stack several memories of different speeds and sizes into a hierarchy, keeping the data the CPU is actively using in the fast levels and the rest in the slow, cheap levels. The hierarchy bridges the speed gap so the CPU rarely stalls.

9.2The Hierarchy

Reading from the CPU outward, each level is larger, slower, and cheaper per bit than the one before it:

Registers (inside the datapath, a handful of bytes, ~1 cycle) → L1 / L2 / L3 cache (SRAM, kilobytes to megabytes, a few cycles) → main memory (DRAM, gigabytes, ~100 ns) → disk / SSD (terabytes, microseconds to milliseconds). Moving toward the CPU buys speed at huge cost per bit; moving away buys capacity for almost nothing.

9.3Locality & Caching

A hierarchy only helps if the fast levels usually hold what the CPU wants. They do, because real programs exhibit locality. Temporal locality: data used recently is likely to be used again soon (loop counters, hot variables). Spatial locality: data near a recent access is likely to be used soon (array elements, the next instruction).

A cache exploits both. When the CPU requests an address, it either hits (the data is already in cache — fast) or misses (the data must be fetched from a slower level). On a miss, the cache pulls in a whole cache line — a block of nearby bytes, not just the one requested — so that spatial locality turns the next several accesses into hits.

AnalogyThe memory hierarchy is a desk, a shelf, and a library. What you use constantly sits on the desk (cache) within arm's reach; the rest lives on shelves across the room (main memory); everything else is at the library downtown (disk). You keep recently and soon-needed items closest, and fetch a whole folder at once rather than one page at a time.

9.4SRAM vs DRAM & Coherence

The fast and slow levels are built from different cells. SRAM (static RAM) stores each bit in about 6 transistors arranged as a latch: fast, no refresh needed, but bulky and power-hungry per bit — so it's used for on-chip cache. DRAM (dynamic RAM) stores a bit in just 1 transistor + 1 capacitor: tiny and cheap, so it packs the gigabytes of main memory — but the capacitor leaks, so DRAM must be periodically refreshed, and it's slower and lives off-chip.

One more wrinkle: in a multicore chip, several cores each have their own cache, and they may hold copies of the same memory location. If one core writes its copy, the others must not keep using stale data. Keeping all those copies consistent is the cache-coherence problem, solved by hardware protocols that track and invalidate shared lines.

Common mistakeDon't swap SRAM and DRAM. SRAM is fast but large and expensive per bit, which is exactly why it's reserved for cache; DRAM is dense and cheap but slower and needs refresh, which is why it's main memory. And remember caches help because of locality, not magic — without reuse and nearby access, a cache buys you nothing.
✦ Worked Example

Average memory access time models how the hierarchy hides slow DRAM. With an L1 hit time of 1 ns, a miss rate of 5%, and a miss penalty of 100 ns, find the AMAT.

  1. Formula: AMAT = hit_time + miss_rate × miss_penalty.
  2. Plug in: AMAT = 1 + 0.05 × 100.
  3. Compute: 0.05 × 100 = 5, so AMAT = 1 + 5 = 6 ns.
  4. Read it: even though a miss costs 100 ns, a 95% hit rate keeps the average near the 1 ns hit time. A high hit rate hides most of the slow DRAM latency.

🛠️ Hands-On: AMAT & hit-rate trade-offs

On paper, compute the average memory access time for a couple of different miss rates using the same numbers from the worked example (hit time 1 ns, miss penalty 100 ns).

* AMAT = hit_time + miss_rate * miss_penalty
hit_time     = 1 ns
miss_penalty = 100 ns

; miss_rate = 2%   AMAT = 1 + 0.02 * 100 = 3 ns
; miss_rate = 5%   AMAT = 1 + 0.05 * 100 = 6 ns
; miss_rate = 10%  AMAT = 1 + 0.10 * 100 = 11 ns

Notice how fast AMAT climbs as the miss rate rises — halving the miss rate from 10% to 5% nearly halves the average access time. That's why architects fight hard for a few extra percent of hit rate.

SRAM stores each bit with ~6 transistors, so it's large in area, expensive, and power-hungry per bit, though very fast. DRAM stores a bit with just 1 transistor and 1 capacitor, so it's dense and cheap but slower and must be refreshed because the capacitor leaks. So we use a small, fast SRAM cache close to the CPU plus large, cheap DRAM for main memory, and rely on locality so the cache catches the great majority of accesses — giving roughly the speed of SRAM at roughly the cost of DRAM. That cost/speed/density trade-off is exactly what creates the memory hierarchy.
