Week 5 · Lecture 5

Processor Datapath

The plumbing data flows through — registers, buses, the ALU, and the program counter.

🎯 Learning Objectives

  • Describe the datapath as the ALU + register file + buses + program counter — the components data physically flows through.
  • Explain what a register file is and how its read/write ports operate each cycle.
  • Show how buses and multiplexers route operands into the ALU and results back out.
  • State the role of the program counter (PC) and how it advances each cycle.
  • Trace a single ADD instruction through the datapath, port by port.

5.1Tying It Together

The last lecture built the ALU — the block that actually crunches numbers. But an ALU on its own is useless: it needs operands delivered to its inputs and a place to put its result. The datapath is everything that handles that plumbing. It is the ALU plus the register file, the buses, and the program counter (PC) — the set of components that data physically flows through as an instruction executes.

datapath = ALU + register file + buses + program counterThe physical paths data travels — operands in, result out, next instruction fetched.

Think of the datapath as the body of the processor: it has the hands (ALU), the workbenches (registers), and the conveyor belts (buses). What it lacks is a brain telling it what to do each cycle — that comes from the control unit in the next lecture.

5.2The Register File

The register file is a small, fast, multi-port store built right onto the chip. Where main memory holds millions of locations far away, the register file holds only a handful — typically 16 or 32 — but the ALU can reach them in a single cycle. It is the processor's scratch pad: the operands an instruction works on, and the result it produces, live here.

"Multi-port" is the key feature. In one clock cycle the register file can normally read two operands and write one result — exactly what a binary operation like ADD needs. Each port has its own address lines, so the two reads and the write happen simultaneously.

per cycle: read port A + read port B → ALU  ·  write port ← ALU resultTwo operands out, one result back, every cycle.

5.3Buses & Multiplexers

The register file's outputs have to get to the ALU's inputs, and the ALU's output has to get back. The wires that carry these multi-bit values are buses — a bus is just a bundle of parallel wires carrying one word at a time. The diagram in 5.1 shows three: read-A to the ALU, read-B to the ALU, and the result back to the write port.

But operands don't always come from a register. Sometimes one input is an immediate value encoded in the instruction itself. To handle "pick this source or that one," the datapath uses a multiplexer (mux) — a selector switch that passes exactly one of its inputs through to its output, chosen by a select signal.

mux: select line picks one input → forwards it to the outpute.g. ALU input B = register read B, OR an immediate from the instruction.

Muxes appear both before the ALU (which source feeds an input?) and after it (where does the result go?). The mux routes data; it does not compute anything. The actual choice of select signal is set by the control unit — the datapath just obeys.

AnalogyThe datapath is a factory floor. The registers are workbenches where parts sit ready, the buses are conveyor belts moving parts around, and the ALU is the machine that does the work. The multiplexers are the switch-points on the belts that decide which line a part travels down. The control unit — coming next lecture — is the foreman who decides what moves where and when. The floor can build anything, but only once the foreman calls the steps.

5.4The PC & Instruction Flow

Something has to keep track of which instruction runs next. That is the job of the program counter (PC) — a special register holding the memory address of the current instruction. At the start of a cycle the PC's address is sent to instruction memory, the instruction there is fetched, and the datapath executes it.

By default the PC then increments to point at the next instruction in sequence (for a typical fixed-width instruction set, that means adding the instruction size, e.g. PC + 4). This steady march is what makes a program run top to bottom.

normal: PC ← PC + (instruction size)  ·  branch/jump: PC ← target addressIncrement to go to the next instruction, or load a new address to jump.

When the program needs to branch or jump, the PC is instead loaded with a target address rather than simply incremented — that is how loops and conditionals redirect the flow. Either way, the PC always names the instruction the processor is about to run.

Common mistakeThe datapath does the work but does not decide what to do — that decision belongs to the control unit (Lecture 6). The datapath is the muscle; the control unit is the brain that drives the select lines and write enables. Also keep storage straight: the register file is fast, on-chip storage with only a handful of slots, separate from main memory, which is large and off-chip. Don't confuse the two.
✦ Worked Example

Trace the instruction ADD R3 = R1 + R2 as it flows through the datapath, step by step.

  1. Fetch: the PC holds the address of this ADD instruction and sends it to instruction memory, which returns the instruction word.
  2. Read operands: the register file reads R1 onto read port A and R2 onto read port B — both in the same cycle.
  3. Compute: the two operands travel the buses (through the input muxes, which here select the register sources) into the ALU, which adds them.
  4. Write back: the ALU result is routed back over the result bus and stored into R3 via the write port.
  5. Advance: the PC increments to the next instruction's address, and the cycle repeats.

🛠️ Hands-On: a minimal datapath in Verilog

Sketch a tiny register file (or a minimal datapath) in Verilog and simulate a single ADD with iverilog + gtkwave. Save the design as rf.v and a stimulus as tb.v, then compile and view the waveform.

// rf.v — 4-entry register file, 2 read ports + 1 write port
module regfile(input clk, we,
               input [1:0] ra, rb, wa,
               input [7:0] wd,
               output [7:0] qa, qb);
  reg [7:0] r[0:3];
  assign qa = r[ra];
  assign qb = r[rb];
  always @(posedge clk) if (we) r[wa] <= wd;  // write port
endmodule
// tb.v — preload R1, R2; do ADD R3 = R1 + R2
module tb;
  reg clk=0, we=0; reg [1:0] ra,rb,wa; reg [7:0] wd;
  wire [7:0] qa,qb;
  regfile dut(clk,we,ra,rb,wa,wd,qa,qb);
  always #5 clk = ~clk;
  initial begin
    $dumpfile("rf.vcd"); $dumpvars;
    we=1; wa=1; wd=8'd7;  #10;   // R1 = 7
    wa=2; wd=8'd5;        #10;   // R2 = 5
    we=0; ra=1; rb=2;     #10;   // read R1, R2
    we=1; wa=3; wd=qa+qb; #10;   // R3 = R1 + R2 = 12
    $finish;
  end
endmodule

Build and view with iverilog -o rf rf.v tb.v && vvp rf, then gtkwave rf.vcd. Expected: qa = 7, qb = 5, and r[3] becomes 12 after the final clock edge.

❓ Lecture 5 Quiz

5 questions · click "Show answer" to check yourself.

Q1. The datapath consists of…
A. the ALU, register file, buses, and PC — the parts data flows through
B. the control unit and the clock
C. the cache only
D. the instruction decoder
Show answer

A. The datapath is the set of components data physically travels through: the ALU, the register file, the buses, and the program counter.

Q2. The register file…
A. is the main memory
B. holds operands in fast on-chip storage, read and written each cycle
C. stores the program
D. decodes instructions
Show answer

B. It is a small, fast, multi-port on-chip store — typically two operands read and one result written per cycle. It is separate from large, off-chip main memory.

Q3. Multiplexers in the datapath…
A. add numbers
B. store state
C. select which source feeds the ALU (or where a result goes)
D. generate the clock
Show answer

C. A mux is a selector: its select line chooses which input (e.g. a register read vs. an immediate) is routed onward. It routes data, it does not compute.

Q4. The program counter (PC)…
A. counts clock cycles only
B. holds the address of the current/next instruction
C. stores the ALU result
D. selects registers
Show answer

B. The PC holds the memory address of the instruction to run. It increments each cycle, or is loaded with a branch/jump target.

Q5. The datapath by itself…
A. decides and executes everything
B. only stores data
C. generates instructions
D. executes operations but does not decide which ones (that's the control unit)
Show answer

D. The datapath is the muscle that performs operations; the control unit (Lecture 6) is the brain that decides which operations happen and drives the select lines.

✓ What you learned

  • The datapath = ALU + register file + buses + PC — the components data physically flows through.
  • The register file is fast, multi-port, on-chip storage: read two operands and write one result per cycle — separate from main memory.
  • Buses carry words between blocks, and multiplexers select which source feeds the ALU (or where a result goes).
  • The program counter (PC) holds the current instruction's address and increments each cycle, or loads a branch target.
  • Traced ADD R3 = R1 + R2 from fetch → read → compute → write-back → PC increment.
