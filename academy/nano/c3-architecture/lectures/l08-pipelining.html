Week 8 · Lecture 8

Pipelining

Overlapping instructions like an assembly line to boost throughput.

🎯 Learning Objectives

  • Explain how a pipeline overlaps the stages of consecutive instructions.
  • Name the classic 5 stages: IF, ID, EX, MEM, WB.
  • Distinguish throughput from latency and explain why pipelining raises one but not the other.
  • Identify the three hazard types: structural, data, and control.
  • Describe how forwarding, stalls/bubbles, and branch prediction cope with hazards.

8.1The Idea

A single instruction passes through several stages on its way through the processor. Run them strictly one-at-a-time and the hardware for most stages sits idle most of the time. Pipelining overlaps the stages of consecutive instructions — like an assembly line — so that while one instruction is executing, the next is being decoded and the one after that is being fetched.

The classic textbook pipeline has 5 stages:

IF → ID → EX → MEM → WBIF = instruction fetch · ID = decode · EX = execute · MEM = memory access · WB = write-back

Each stage hands its result to the next through pipeline registers, so all five pieces of hardware do useful work at the same time on different instructions.

8.2Throughput vs Latency

Here is the subtlety that trips most people up. Pipelining does not make any single instruction finish faster. An individual instruction still passes through all five stages — its latency (start-to-finish time) is unchanged, and may even rise slightly because of the register overhead between stages.

What pipelining buys you is throughput — how many instructions complete per unit time. Once the pipe is full, an instruction completes on every clock cycle, even though each one took five cycles to travel through.

latency = time for ONE instruction (unchanged)
throughput = instructions completed PER cycle (↑ toward 1)
AnalogyThink of a laundromat assembly line. While one load is in the dryer, the next is in the washer, and the one after that is being loaded. A single load doesn't dry any faster — its time is the same — but you finish far more loads per hour because every machine stays busy. That's throughput, not latency.

8.3Hazards

The clean staircase assumes every instruction can advance every cycle. Real programs create hazards — situations that prevent the next instruction from executing in its scheduled slot. There are three kinds:

Structural hazard

Two instructions need the same hardware resource in the same cycle (a resource conflict). For example, if there is only one memory port and both IF and MEM want it at once. Fixed by duplicating or splitting the resource.

Data hazard

An instruction needs a result that an earlier instruction has not yet produced. If I1 computes a value that I2 reads, but I1 hasn't reached write-back yet, I2 would read stale data.

Control hazard

A branch changes which instruction comes next, but the processor has already fetched the instructions that follow the branch before knowing whether the branch is taken. The wrong instructions may be sitting in the pipe.

8.4Forwarding & Stalls

The processor doesn't have to passively wait for write-back. With forwarding (also called bypassing), a result computed in one stage is routed directly to a later instruction's input as soon as it exists — usually straight from one EX output to the next EX input — avoiding the delay entirely.

When forwarding can't supply the data in time — the classic case is a load whose value isn't ready until MEM but is needed by the very next instruction's EX — the pipeline must insert a stall (a "bubble"): a do-nothing cycle that holds later instructions back until the data is available.

forwarding ⟹ route result early, no wait  ·  stall/bubble ⟹ insert idle cycle when forwarding can't help

For control hazards, branch prediction guesses whether a branch will be taken and keeps fetching down the predicted path. A correct guess costs nothing; a wrong guess flushes the wrongly-fetched instructions and refetches — so good prediction sharply reduces the control-hazard penalty.

Common mistakePipelining improves throughput, not single-instruction latency — one instruction does not finish faster. Hazards (especially data and control) can force stalls that eat into the ideal speedup. And forwarding reduces data-hazard stalls but does not always eliminate them (a load-use hazard still needs a bubble).
✦ Worked Example

A 5-stage pipeline runs N instructions with no hazards. Compare the cycle count to running them unpipelined (each instruction taking its full 5 cycles before the next begins). Evaluate for N = 100 and find the speedup.

  1. Fill the pipe: the first instruction takes 5 cycles to reach the end (cycles to fill = 5).
  2. After that: one new instruction completes every cycle, so the remaining N − 1 instructions add N − 1 cycles.
  3. Pipelined total: 5 + (N − 1) = N + 4 cycles.
  4. Unpipelined total: each instruction occupies all 5 cycles alone ⟹ 5N cycles.
  5. For N = 100: pipelined = 100 + 4 = 104 cycles vs unpipelined = 5 × 100 = 500 cycles.
  6. Speedup: 500 / 104 ≈ 4.8× — approaching the ideal 5× as N grows (the fixed 4-cycle fill cost is amortized away).

🛠️ Hands-On: diagram the pipeline occupancy

On paper (or with Verilog pipeline registers), take a short instruction sequence containing one data hazard, e.g.:

; I1 produces a result that I2 immediately needs
I1:  ADD  r3, r1, r2      ; r3 = r1 + r2
I2:  SUB  r5, r3, r4      ; needs r3 from I1
I3:  AND  r6, r1, r7

Draw the staircase grid (cycles across the top, instructions down the side) and fill in IF ID EX MEM WB for each. Mark the cycle where I2 needs r3 in its EX stage and the cycle where I1 produces it. Then show how a forward (EX→EX arrow) satisfies the dependency with no stall — and contrast with a load-use case where you must insert a bubble instead.

❓ Lecture 8 Quiz

5 questions · click "Show answer" to check yourself.

Q1. Pipelining primarily improves…
A. single-instruction latency
B. throughput (instructions completed per unit time)
C. clock frequency only
D. memory size
Show answer

B. Pipelining raises throughput — once the pipe is full, an instruction completes every cycle. Any single instruction's latency is unchanged (it still passes through all stages).

Q2. The classic 5 pipeline stages are…
A. IF, ID, EX, MEM, WB
B. fetch, add, store, branch, halt
C. read, write, refresh, sync, idle
D. decode only
Show answer

A. Instruction Fetch, Instruction Decode, Execute, Memory access, and Write-Back.

Q3. A data hazard occurs when…
A. two instructions use different registers
B. an instruction needs a result not yet produced by an earlier instruction
C. the clock is too slow
D. memory is full
Show answer

B. A data hazard arises from a dependency: a later instruction reads a value that an earlier instruction hasn't finished computing/writing yet.

Q4. Forwarding (bypassing)…
A. deletes an instruction
B. routes a result to a later stage early to avoid a stall
C. doubles the clock
D. flushes the cache
Show answer

B. Forwarding sends a result directly to a waiting instruction's input as soon as it's computed, rather than waiting for write-back — avoiding (most) data-hazard stalls.

Q5. A control hazard arises from…
A. arithmetic overflow
B. a full register file
C. branches (the address of the next instruction isn't known yet)
D. a cache miss only
Show answer

C. A branch changes which instruction comes next, but the pipeline has already fetched the following instructions before knowing the outcome. Branch prediction reduces the penalty.

✓ What you learned

  • Pipelining overlaps the stages of consecutive instructions like an assembly line; the classic 5 stages are IF, ID, EX, MEM, WB.
  • It raises throughput (one instruction completes per cycle once full) but leaves single-instruction latency unchanged.
  • Three hazard types: structural (resource conflict), data (needed result not ready), and control (branches).
  • Forwarding routes results early to avoid stalls; when it can't, a stall/bubble is inserted; branch prediction reduces control-hazard cost.
  • Quantified the speedup: N instructions take N + 4 cycles pipelined vs 5N unpipelined — about 4.8× for N = 100, approaching 5×.
