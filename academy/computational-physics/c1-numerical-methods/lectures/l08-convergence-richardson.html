Week 8 · Lecture 8

Convergence, Order & Richardson Extrapolation

If you know how fast a method's error shrinks, you can predict the answer you'd get at zero step size — without ever taking it.

🎯 Learning Objectives

  • Measure the empirical order of a numerical method from the slope of an error-vs-step-size log-log plot.
  • Estimate error without the exact answer by halving the step and comparing successive approximations.
  • Derive Richardson extrapolation and use it to cancel a method's leading error term.
  • Build the Romberg integration table as repeated Richardson on the trapezoidal rule.
  • Assemble an error budget that separates truncation, round-off, and modelling error in a computation.

8.1Measuring Order from a Log-Log Slope

In Lecture 1 we wrote that a method's truncation error obeys error ≈ C·hp, where p is the order of convergence. So far p has been something you read off a derivation. But in practice you often do not know p — you have a black-box routine, or a scheme whose analysis is messy. The good news: order is something you can measure directly from numerical output.

Take the log of error ≈ C·hp:

log(error) ≈ log(C) + p · log(h)On axes of log(error) vs log(h) this is a straight line of slope p — the order is the slope.

Plot your measured error against the step size h on log-log axes. If the method has a clean order, the points fall on a line, and its slope is p. A first-order method climbs at slope 1; the trapezoidal rule and central differences sit at slope 2; Simpson's rule at slope 4. This is the single most useful diagnostic in the whole course: it tells you whether your code is actually doing what the theory promised.

If you have two errors at steps h and h/2, you don't even need a plot — the slope between two points gives a numerical order estimate:

p ≈ log2( E(h) / E(h/2) )The factor by which error drops on halving h, read as a power of 2. E(h)/E(h/2) ≈ 4 means p ≈ 2.
AnalogyOrder is the fuel economy of a method. A first-order method is a gas-guzzler: halve the step (double the work) and you only halve the error. A fourth-order method is a hybrid: the same halving cuts error by 16. The log-log slope is the sticker on the window — it tells you, before you commit to a long run, how much accuracy you buy per unit of extra computation.

8.2Richardson Extrapolation: Cancelling the Leading Error

Knowing the order does more than diagnose code — it lets you improve the answer for free. Suppose a method A(h) approximates a true value A with a known leading order p:

A(h) = A + C·hp + O(hq),   q > pThe error is dominated by one term C·h^p; everything else is higher-order and smaller.

Now compute the same thing at half the step. The leading error shrinks by 2p:

A(h/2) = A + C·(h/2)p + ... = A + C·hp/2p + ...

We have two equations and want to eliminate the unknown C·hp. Multiply the second by 2p, subtract the first, and divide out: the leading term vanishes, leaving a far more accurate estimate. This is Richardson extrapolation:

A_better = ( 2p·A(h/2) − A(h) ) / ( 2p − 1 )A weighted combination of two cheap estimates whose leading error term exactly cancels — accuracy is now at least order q.

You computed two ordinary approximations and combined them with a couple of multiplications; in return the error jumped from O(hp) to O(hq). For a method with only even-power error terms (like the trapezoidal rule, where q = p + 2), each extrapolation raises the order by two. This is the engine behind Romberg integration in the next section, and behind adaptive step doubling in ODE solvers in Course 2.

Common mistakeRichardson only works if you use the correct p. Plug p = 2 into a method that is really first-order and the leading term does not cancel — you get garbage that can be worse than either input. Always confirm the order first (Section 8.1) or, in production code, estimate p from three step sizes. A second trap: pushing h so small that round-off (Lecture 1) already dominates A(h) — extrapolating noise just gives a cleaner-looking noise.

8.3Romberg Integration: Richardson on the Trapezoidal Rule

The trapezoidal rule from Week 6 has a beautiful property: its error expansion (the Euler–Maclaurin formula) contains only even powers of h — h², h⁴, h⁶, and so on. That makes it the perfect target for Richardson extrapolation applied repeatedly. The result is Romberg integration.

Start by computing the composite trapezoidal estimate at successively halved steps. Call R(i, 0) the trapezoidal value using 2i intervals. Each row reuses the previous function evaluations, so doubling the points is cheap. Then build extra columns by Richardson, where each column kills the next even-power error term:

R(i, j) = R(i, j−1) + ( R(i, j−1) − R(i−1, j−1) ) / ( 4j − 1 )Here 2^p = 4^j because column j cancels the h^(2j) term. Column 0 is trapezoidal (order 2), column 1 is Simpson's rule (order 4), column 2 is order 6, ...

The first Richardson step (column 1) is exactly Simpson's rule — a satisfying confirmation that these methods are all relatives. Each subsequent column adds two more orders of accuracy. The diagonal entry R(n, n) is your best estimate, and the difference between the last two diagonal entries is a reliable error estimate — the basis of how SciPy decides when to stop.

8.4Building an Error Budget

A trustworthy result is not just a number — it comes with a defensible statement of how wrong it might be. Professionals build an error budget: a line-item list of every error source and its size, just as an accountant lists expenses. For a typical computation three terms dominate:

  • Truncation (discretization) error — from finite h or a finite series. You now know how to estimate it: order p tells you it falls like hp, and Richardson gives a concrete number.
  • Round-off error — from finite precision, ~ε per operation (Lecture 1). It sets a floor: refining h below the point where round-off dominates is wasted effort.
  • Modelling / input error — uncertainty in the physics, parameters, or measured data feeding the computation. Often the largest term, and the one numerics can never fix.

The total is bounded by the sum, but it is rarely worth driving one term far below the others. The art is balance:

E_total ≲ E_trunc(h) + E_roundoff + E_modelSpend effort where it pays. If the data is only known to 1%, computing the integral to 10^-12 is theatre.

This single idea — match your numerical precision to the precision you actually need and the precision your inputs allow — separates a working scientist from someone who burns a week of compute chasing digits that mean nothing.

AnalogyAn error budget is like the tolerance stack-up an engineer does before machining a part. Each dimension has a tolerance; you add them to see whether the assembly still fits. If one loose tolerance dominates, tightening the others is wasted money. Numerics is the same: find the dominant error term and put your effort there.
✦ Worked Example — Richardson on a trapezoidal integral

Estimate the integral of f(x) = ex from 0 to 1. The exact value is e − 1 ≈ 1.7182818. Use the trapezoidal rule at two step sizes, measure the order, then apply Richardson.

  1. Coarse, h = 1 (one interval): T(1) = (1/2)(f(0) + f(1)) = (1/2)(1 + 2.7182818) = 1.8591409. Error = +0.1408591.
  2. Fine, h = 0.5 (two intervals): T(0.5) = (0.5/2)(f(0) + 2f(0.5) + f(1)) = 0.25(1 + 2·1.6487213 + 2.7182818) = 1.7539311. Error = +0.0356493.
  3. Measure the order: the error ratio is 0.1408591 / 0.0356493 ≈ 3.95 ≈ 4, so p ≈ log₂(3.95) ≈ 2. The trapezoidal rule is second order, as advertised.
  4. Apply Richardson with p = 2 (so 2p = 4): A_better = (4·T(0.5) − T(1)) / (4 − 1) = (4·1.7539311 − 1.8591409) / 3 = (7.0157244 − 1.8591409)/3 = 5.1565835/3 = 1.7188612.
  5. Check the payoff: the extrapolated error is 1.7188612 − 1.7182818 = +0.00058 — about 60× smaller than the fine trapezoidal estimate, and (no coincidence) this combination is exactly Simpson's rule on those three points. One subtraction bought two orders of accuracy.

🛠️ Hands-On: measure order, then Romberg-integrate

Uses the free Python + NumPy/SciPy/Matplotlib stack from the Week 1 setup (the install details in Lecture 1). No new tools needed — scipy.integrate ships with SciPy. First we measure a method's order from a log-log fit, then we let Richardson do its magic via Romberg.

# convergence_richardson.py — Lecture 8
import numpy as np
from scipy import integrate

f = np.exp                       # integrand
a, b, exact = 0.0, 1.0, np.e - 1.0

# --- 1. composite trapezoid at halved steps, measure order ---
def trap(n):
    x = np.linspace(a, b, n + 1)
    return np.trapz(f(x), x)

ns = [1, 2, 4, 8, 16, 32]
errs = [abs(trap(n) - exact) for n in ns]
hs   = [(b - a) / n for n in ns]

# slope of log(err) vs log(h) is the order p
p, logC = np.polyfit(np.log(hs), np.log(errs), 1)
print(f"measured order p = {p:.2f}")          # ~2.00

# pairwise order estimate from successive halvings
for i in range(1, len(errs)):
    print(f"h={hs[i]:.3f}  p_est={np.log2(errs[i-1]/errs[i]):.2f}")

# --- 2. Richardson by hand: combine the two coarsest steps ---
better = (4 * trap(2) - trap(1)) / 3        # 2^p = 4 for p=2
print("Richardson error:", abs(better - exact))   # ~6e-4

# --- 3. Romberg = repeated Richardson on trapezoid ---
R = integrate.romberg(f, a, b, show=True)   # prints the table
print("Romberg error:", abs(R - exact))     # ~1e-13, near round-off floor

Try integrate.romberg(f, a, b, show=True) and read the printed triangular table: watch each column gain ~2 orders. Then replace f = np.exp with a function that has a kink (e.g. np.abs): the smooth even-power error expansion breaks, the measured order drops, and Romberg stops helping — a vivid lesson that extrapolation assumes smoothness.

🔗 Where this is heading

Richardson extrapolation is one of the most reused ideas in the field. In Course 2 (ODEs), step-doubling and the Bulirsch–Stoer method are Richardson extrapolation in time, and embedded Runge–Kutta pairs estimate per-step error exactly as we estimated order here. In Course 4 (PDEs), grid-convergence studies use the measured log-log slope to certify that a simulation is in its "asymptotic range" — a required step in any credible numerical experiment. Project checkpoint (Week 8): your capstone deliverable this week is a convergence study for your chosen solver — a log-log error-vs-h plot with a fitted slope confirming the expected order, plus a one-paragraph error budget identifying which term (truncation, round-off, or input) dominates your final number. Bring that plot to Week 9, where conditioning will explain why some problems resist all of this.

5 questions · click "Show answer" to check yourself.

Q1. You plot log(error) against log(h) and the points lie on a straight line. What does the slope of that line tell you?
A. the round-off floor of the computation
B. the order of convergence p of the method
C. the machine epsilon
D. the total runtime of the code
Show answer

B. Since log(error) ≈ log(C) + p·log(h), the slope is exactly p. The round-off floor (A) shows up as the plot flattening at very small h, not as the slope; machine epsilon (C) and runtime (D) are unrelated to this slope.

Q2. A method's error drops by a factor of 4 each time you halve the step size h. Its order of convergence is approximately…
A. p = 1
B. p = 4
C. p = 2
D. p = 0.5
Show answer

C. p = log₂(E(h)/E(h/2)) = log₂(4) = 2. A factor of 2 per halving would be p = 1 (A); a factor of 16 would be p = 4 (B); p = 0.5 (D) would mean error barely changes.

Q3. Richardson extrapolation combines A(h) and A(h/2) for a method of order p as A_better = (2ᵖ·A(h/2) − A(h)) / (2ᵖ − 1). Its purpose is to…
A. cancel the leading C·hᵖ error term, raising the order
B. average two estimates to reduce round-off noise
C. make the computation run faster
D. guarantee the answer is exact
Show answer

A. The weights are chosen precisely so the leading C·hᵖ terms cancel, leaving higher-order error. It is not a simple average (B), it does extra work rather than less (C), and the higher-order remainder means it is more accurate but not exact (D).

Q4. Romberg integration is best described as…
A. Gaussian quadrature with optimal node placement
B. a Monte-Carlo integral with random samples
C. repeated Richardson extrapolation applied to the trapezoidal rule
D. the midpoint rule on a uniform grid
Show answer

C. Romberg builds a table whose first column is trapezoidal estimates at halved steps, then applies Richardson repeatedly (first column = Simpson, etc.). Gaussian quadrature (A) is a different scheme using optimal nodes (Week 7); Monte-Carlo (B) and the plain midpoint rule (D) are unrelated.

Q5. Your input data is known to only 1% accuracy, yet you refine the step size until the truncation error is 10⁻¹². The smart conclusion from an error-budget view is…
A. the final answer is now accurate to 10⁻¹²
B. you should refine the step even further
C. round-off is now the only error left
D. the extra refinement is wasted — the 1% input error dominates the budget
Show answer

D. Total error is bounded by the sum of terms, so the 1% modelling/input error swamps the 10⁻¹² truncation term. The answer is no better than ~1% (so A is false), more refinement is pointless (B), and round-off is not the limiting term either (C).
