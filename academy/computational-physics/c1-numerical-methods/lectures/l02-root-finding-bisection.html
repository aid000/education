Root Finding I — Bisection & Bracketing

When a physics problem reduces to "where does this quantity hit zero?", bisection is the patient, never-fails workhorse that always corners the answer.

🎯 Learning Objectives

  • Recognize when a physics problem reduces to solving f(x) = 0 for a root.
  • Use a sign change and the Intermediate Value Theorem to bracket a root.
  • State the bisection algorithm and explain why it is guaranteed to converge.
  • Quantify bisection's linear, error-halving convergence and predict the iteration count.
  • Choose robust stopping criteria on interval width and function value, and run bisection in Python/SciPy.

2.1When Physics Becomes "Find Where f(x) = 0"

An astonishing fraction of physics computations end at the same question: for what value of x does some quantity vanish? A particle is in equilibrium when the net force is zero. A projectile lands when its height returns to zero. An object reaches terminal velocity when gravity exactly balances drag, so the net force — and acceleration — is zero. In each case you rearrange the physics into a single function and hunt for its root:

find x* such that  f(x*) = 0x* is a root (or zero) of f. Equilibria, resonances, threshold energies, and steady states are all roots of a well-chosen f.

Most such equations are transcendental — they mix polynomials with exponentials, trig, or logs (think mg = b v + c v² for drag, or tan(ka) = κ/k for a quantum well) — and there is no algebraic formula for the answer. You cannot "solve for x" by hand. Instead you build a function whose zero is the answer and let a numerical method walk toward it.

The simplest, most dependable of those methods is bisection. It is slow but it has a property no fancier method guarantees: if you start it correctly, it cannot fail. To understand why, we first need the idea of a bracket.

2.2Bracketing a Root with the Intermediate Value Theorem

Suppose f is continuous on an interval [a, b], and it is negative at one end and positive at the other. Then somewhere between a and b the curve must cross zero — there is no way to get from below the axis to above it, without a break, without touching it. This is the Intermediate Value Theorem (IVT), and it is the entire foundation of bracketing:

if f(a) · f(b) < 0  (opposite signs)  then a root x* lies in (a, b)The product being negative is the compact way to say "the signs differ." Continuity is required.

An interval [a, b] with f(a)·f(b) < 0 is called a bracket: it provably traps a root. We do not yet know where the root is inside it — only that it is in there somewhere. The whole game of bisection is to shrink a bracket while keeping the root trapped, so our uncertainty about x* steadily collapses.

AnalogyBracketing is a guessing game of "higher or lower." A friend picks a number between 1 and 100; each time you guess, you learn whether the target is above or below. You never see the number directly, but every answer halves the range you still have to search. Bisection plays exactly this game against a continuous function — the sign of f is the "higher or lower" hint.
Common mistakeThe IVT only applies to continuous functions. If f has a jump or a pole (a vertical asymptote, like tan x near pi/2), a sign change can occur with no root at all — the function leaps from large negative to large positive across the discontinuity. Always confirm your function is continuous on [a, b] before trusting a sign change.

2.3The Bisection Method & Its Guaranteed Convergence

Bisection is the "higher or lower" game made into an algorithm. Start with a bracket [a, b] where f(a) and f(b) have opposite signs. Then repeat:

  • Compute the midpoint m = (a + b) / 2 and evaluate f(m).
  • If f(a) and f(m) have opposite signs, the root is in the left half → set b = m.
  • Otherwise the root is in the right half → set a = m.
  • Either way the bracket is now half as wide, and still contains a root.

Because each step discards exactly half the interval, the width after n steps is the original width divided by 2ⁿ:

w_n = (b - a) / 2ⁿ  ⟹   |x_n - x*| ≤ (b - a) / 2ⁿ⁺¹Reporting the midpoint x_n = (a+b)/2 puts the true root within half the current width — a rigorous error bound, free of charge.

This is linear convergence with rate 1/2: each iteration buys one more bit of accuracy (one binary digit), or about log₁₀ 2 ≈ 0.30 decimal digits. To gain a factor of ten in accuracy you need about 3.3 steps. We can solve directly for the number of iterations needed to reach a tolerance τ:

n ≥ log₂( (b - a) / τ )Round up. Bisection lets you predict the exact iteration count before you run it — a rare and reassuring guarantee.

2.4Stopping Criteria: When Is "Close Enough"?

An iterative method needs a stopping rule. Bisection offers two complementary ones, and good code uses both:

  • Interval width. Stop when (b − a) < τ_x. Because the root is trapped, this directly bounds how far the reported x can be from x* — it is a guarantee about the answer.
  • Function value. Stop when |f(m)| < τ_f. This says "the residual is tiny," which matters when you care that the physics equation is nearly balanced.

To handle roots of very different magnitudes (a root near 10⁻⁹ vs one near 10⁹), professional code combines an absolute and a relative tolerance on x:

stop when  (b - a) < τ_abs + τ_rel · |m|Absolute tolerance dominates near zero; relative tolerance scales the demand for large roots. SciPy uses exactly this form (xtol, rtol).
Common mistakeDo not stop on |f(m)| alone. For a function with a steep slope, |f| can be large even when x is extremely close to the root; for a flat function, |f| can be tiny while x is still far off. And never loop "until f(m) is exactly 0" — round-off means it almost never hits zero, so the loop can spin forever. Always cap the iteration count and prefer the interval-width test as your primary guarantee.
✦ Worked Example — terminal velocity of a falling sphere

A sphere falls under gravity with quadratic drag. At terminal velocity the net force is zero: f(v) = mg − ½ ρ C_d A v² = 0. Take mg = 4.0 N, ½ ρ C_d A = 0.25 (SI units), so f(v) = 4 − 0.25 v². (The exact root is v* = √(4/0.25) = √16 = 4.0 m/s — known here so we can check.) Bracket on [0, 10] and bisect.

  1. Check the bracket: f(0) = 4 − 0 = +4 (> 0); f(10) = 4 − 0.25·100 = −21 (< 0). Opposite signs ⟹ a root is trapped in [0, 10]. Width w = 10.
  2. Iteration 1: m = 5. f(5) = 4 − 0.25·25 = −2.25 (< 0). Same sign as f(10), so the root is in the left half → new bracket [0, 5].
  3. Iteration 2: m = 2.5. f(2.5) = 4 − 0.25·6.25 = +2.44 (> 0). Root is in the right half → [2.5, 5].
  4. Iteration 3: m = 3.75. f(3.75) = 4 − 0.25·14.06 = +0.48 (> 0) → [3.75, 5]. Iteration 4: m = 4.375, f = −0.78 → [3.75, 4.375], straddling the true 4.0.
  5. How many steps for τ = 10⁻³? n ≥ log₂(10 / 10⁻³) = log₂(10⁴) ≈ 13.3 → 14 iterations. After 14 steps the width is 10/2¹⁴ ≈ 6×10⁻⁴ < 10⁻³, so v* = 4.000 m/s to three decimals — guaranteed, with no formula for the root needed.

🛠️ Hands-On: bisection by hand and with SciPy

The free Python + NumPy/SciPy stack runs everything in this specialization. If you set it up in Week 1 you can skip the install; otherwise do it once below and reuse it every lecture.

⬇ Install Python + NumPy / SciPy (one-time setup)

With Python 3 installed (from python.org or your package manager), create an environment and install the scientific stack:

python3 -m venv compphys-env

compphys-env\Scripts\activate         # Windows (PowerShell)

Verify: run python -c "import scipy; print(scipy.__version__)" — a version string means you're set.

Write bisection from scratch to feel the guarantee, then compare against SciPy's battle-tested brentq on the same terminal-velocity problem.

# bisection.py — Lecture 2
import numpy as np
from scipy.optimize import brentq

# Terminal velocity: net force f(v) = mg - 0.5*rho*Cd*A*v**2
def f(v):
    return 4.0 - 0.25 * v**2          # exact root at v* = 4.0 m/s

def bisect(f, a, b, xtol=1e-3, maxit=100):
    fa, fb = f(a), f(b)
    if fa * fb > 0:
        raise ValueError("f(a) and f(b) must have opposite signs")
    for k in range(maxit):
        m  = 0.5 * (a + b)
        fm = f(m)
        if (b - a) < xtol or fm == 0.0:   # width test is the real guarantee
            return m, k
        if fa * fm < 0:                    # root in left half
            b, fb = m, fm
        else:                              # root in right half
            a, fa = m, fm
    return 0.5 * (a + b), maxit

root, iters = bisect(f, 0.0, 10.0, xtol=1e-3)
print(f"bisection: v* = {root:.6f} m/s in {iters} iterations")  # ~4.0 in 14
print("scipy brentq:", brentq(f, 0.0, 10.0))                    # 4.0, far fewer evals

# Predict the iteration count before running:
print("predicted n:", int(np.ceil(np.log2((10 - 0) / 1e-3))))   # 14

Try widening the bracket to [0, 1000] and predict the new iteration count with the log₂ formula before you run it. Then plot f(v) with Matplotlib and mark the root — seeing the single sign change makes the bracket obvious.

🔗 Where this is heading

Bisection is reliable but slow — one bit per step. Next week (Lecture 3) we trade some of that safety for speed with Newton's method and the secant method, which use slope information to converge quadratically or superlinearly, then learn how Brent's method fuses bisection's guarantee with that speed (the engine behind SciPy's brentq). Root finding underlies far more than it seems: equilibrium and steady-state solving feed into the ODE work of Course 2, implicit time-steppers (Course 4) solve a root at every step, and shooting methods turn boundary-value problems into nested root finds. The bracketing mindset — trap the answer, then squeeze — recurs throughout the Quantum and Plasma tracks whenever you locate energy eigenvalues or marginal-stability thresholds.

5 questions · click "Show answer" to check yourself.

Q1. Which condition guarantees (for a continuous f) that a root lies in the interval [a, b]?
A. f(a) and f(b) are both positive
B. f(a) · f(b) < 0 (the endpoints have opposite signs)
C. f(a) = f(b)
D. |f(a)| = |f(b)|
Show answer

B. Opposite signs plus continuity invoke the Intermediate Value Theorem, trapping a root. Both-positive (A) or equal values (C) give no such guarantee, and equal magnitudes (D) can share the same sign.

Q2. After n bisection steps, the width of the bracket compared to the starting width (b − a) is…
A. (b − a) / n
B. (b − a) · 2ⁿ
C. (b − a) − n·τ
D. (b − a) / 2ⁿ
Show answer

D. Each step halves the interval, so after n steps it is divided by 2ⁿ. Dividing by n (A) is far too slow; multiplying by 2ⁿ (B) grows it; (C) describes no real process.

Q3. Bisection's convergence is best described as…
A. linear — it gains a fixed number of bits per step (rate 1/2)
B. quadratic — the number of correct digits doubles each step
C. exponential blow-up
D. it does not converge for transcendental equations
Show answer

A. The error is multiplied by 1/2 each step — linear convergence, ~0.30 decimal digit per iteration. Quadratic (B) describes Newton's method, not bisection; it always converges given a valid bracket, so (D) is wrong.

Q4. Why is stopping on only |f(m)| < τ_f a poor sole criterion?
A. |f(m)| is impossible to evaluate
B. A steep f can have large |f| even when x is very close to the root; a flat f can have tiny |f| while x is far off
C. It makes bisection converge quadratically
D. It always stops one step too early
Show answer

B. The residual |f| and the x-error are linked by the slope, so |f| alone is an unreliable proxy for accuracy in x. The interval-width test gives a direct bound on the answer. (A), (C), and (D) are simply false.

Q5. A root is bracketed in [0, 16]. About how many bisection steps reach a tolerance of τ = 10⁻³ on the interval width?
A. about 4
B. about 1000
C. about 14
D. about 50
Show answer

C. n ≥ log₂((b − a)/τ) = log₂(16 / 10⁻³) = log₂(16000) ≈ 13.97, round up to 14. Four steps (A) only reaches width 1; 1000 (B) and 50 (D) badly overshoot what halving requires.

✓ What you learned

  • Many physics problems — equilibrium, terminal velocity, thresholds — reduce to solving f(x) = 0 with no closed-form answer.
  • A sign change f(a)·f(b) < 0 on a continuous f brackets a root via the Intermediate Value Theorem.
  • Bisection halves the bracket each step while keeping the root trapped, so it cannot fail given a valid bracket.
  • Convergence is linear: width = (b−a)/2ⁿ, and n ≥ log₂((b−a)/τ) predicts the iteration count exactly.
  • Use both stopping criteria — interval width (the real guarantee) and function value — and always cap the iterations.
