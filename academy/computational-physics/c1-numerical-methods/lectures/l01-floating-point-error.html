Week 1 · Lecture 1

Floating-Point Arithmetic & Numerical Error

A computer can't store most numbers exactly. Knowing exactly how it fails is the first skill of every computational physicist.

🎯 Learning Objectives

  • Explain how floating-point numbers are stored and define machine epsilon.
  • Distinguish round-off error from truncation error.
  • Compute absolute and relative error and state what "order of convergence" means.
  • Recognize catastrophic cancellation and why a smaller step is not always better.
  • Use NumPy to observe machine epsilon and the round-off / truncation trade-off in a finite-difference derivative.

1.1Why a Computer Can't Store Most Numbers

There are infinitely many real numbers between 0 and 1, but a computer word has finitely many bits. So almost every real number is rounded to the nearest one a computer can represent. The standard format, IEEE 754 double precision, splits 64 bits into a sign, an exponent, and a 52-bit fraction (mantissa):

The spacing between representable numbers near 1.0 is the machine epsilon:

ε = 2−52 ≈ 2.22 × 10−16The gap between 1.0 and the next larger representable double — the relative resolution of the number system.
AnalogyFloating point is scientific notation with a fixed number of digits — like a calculator that shows 16 figures and no more. Just as 1/3 becomes 0.333…3 (truncated) on that calculator, most numbers get nudged to the nearest one the format can write down. Machine epsilon is the size of one "tick" on that ruler near 1.0.

1.2Two Kinds of Error: Round-off vs Truncation

Numerical results carry two fundamentally different errors, and telling them apart is the heart of this course:

  • Round-off error comes from finite precision — every stored number and every operation is rounded by up to about ε. It is a property of the hardware and grows as you do more arithmetic.
  • Truncation error comes from the method — you replace an exact limit, derivative, or infinite series with a finite approximation (a step size h, a finite number of terms). It shrinks as you refine the method.

We measure error two ways. Absolute error is |approx − exact|; relative error is that divided by |exact| — the one that maps to "significant digits." A method's order of convergence p says how fast truncation error falls as you refine:

error ≈ C · hp  ⟹   halving h cuts the error by 2pA first-order method (p = 1) halves error when h halves; a second-order method (p = 2) quarters it.

1.3Catastrophic Cancellation

The most dangerous round-off effect is catastrophic cancellation: subtracting two nearly-equal numbers. The leading digits cancel, leaving a small result whose remaining digits are mostly round-off noise.

1.2345678 − 1.2345600 = 0.0000078Two numbers known to 8 digits; their difference keeps only ~2 meaningful digits — the rest is noise.
Common mistakeTwo classics to avoid forever: (1) testing floats with == — e.g. 0.1 + 0.2 == 0.3 is False, because none of those store exactly; compare with a tolerance instead. (2) Assuming a smaller step h always gives a more accurate derivative — past a point, cancellation makes it worse, as we'll see next.

1.4The Trade-off: a Finite-Difference Derivative

Estimate a derivative with the forward difference f′(x) ≈ [f(x+h) − f(x)] / h. Two errors fight as you shrink h:

E(h) ≈ (h/2)·|f″|  +  2ε·|f| / hFirst term = truncation (falls with h). Second term = round-off from cancelling f(x+h) − f(x) (grows as h → 0).

Truncation wants h small; round-off wants h large. The total is minimized in between — and (a tidy result) the two terms are equal at the optimum:

h* ≈ √ε ≈ 1.5 × 10−8   with min error ≈ √ε ≈ 10−8A forward difference loses about half your digits — no matter how carefully you choose h.
✦ Worked Example — the best step for a derivative

Estimate f′(1) for f(x) = sin x with a forward difference. The exact value is cos(1) ≈ 0.5403. Find the step h that minimizes total error, and the error you'll get.

  1. Truncation error: (h/2)|f″(x)|. Here f″ = −sin, so |f″(1)| = sin 1 ≈ 0.841.
  2. Round-off error: ≈ 2ε|f(x)| / h, with |f(1)| = sin 1 ≈ 0.841 and ε ≈ 2.22×10⁻¹⁶.
  3. Minimize the sum: setting the derivative of E(h) to zero gives h* = 2√(ε·|f|/|f″|). With |f| = |f″|, this is h* = 2√ε ≈ 3.0×10⁻⁸.
  4. Minimum error: at h* the two terms are equal, each ≈ √ε·0.841, so total ≈ 2.5×10⁻⁸ — about half the 16 digits are gone.
  5. Takeaway: picking h = 10⁻¹² ("smaller must be better!") would give a worse answer than h ≈ 10⁻⁸. The central difference (Week 5) does better — error ~ ε^(2/3) ~ 10⁻¹¹ — by making truncation second-order.

🛠️ Hands-On: watch the error bottom out

The free Python + NumPy/SciPy stack runs everything in this specialization. Week 1 setup: install it once (below), then reuse it every lecture and for the project.

⬇ Install Python + NumPy / SciPy (one-time, Week 1 setup)

With Python 3 installed (from python.org or your package manager), create an environment and install the scientific stack:

python3 -m venv compphys-env
source compphys-env/bin/activate     # macOS / Linux
compphys-env\Scripts\activate         # Windows (PowerShell)
pip install numpy scipy matplotlib jupyter

Verify: run python -c "import numpy; print(numpy.__version__)" — a version string means you're set. (Numba is optional and only added later for speed.)

First see machine epsilon and the famous 0.1 + 0.2 surprise, then sweep the step size and watch the derivative error fall, bottom out near √ε, and rise again.

# floating_point.py — Lecture 1
import numpy as np

eps = np.finfo(float).eps
print("machine epsilon:", eps)          # 2.220446049250313e-16
print(0.1 + 0.2 == 0.3)                 # False
print(repr(0.1 + 0.2))                  # 0.30000000000000004

x = 1.0
exact = np.cos(x)                        # f'(x) = cos(1) = 0.5403...
for h in [1e-2, 1e-4, 1e-6, 1e-8, 1e-10, 1e-12]:
    approx = (np.sin(x + h) - np.sin(x)) / h
    print(f"h={h:.0e}   error={abs(approx - exact):.2e}")
# error falls to ~1e-8 near h=1e-8, then RISES as round-off takes over

Replace the forward difference with the central difference (np.sin(x+h) - np.sin(x-h)) / (2*h) and rerun. Its best error is far smaller — predict where the new minimum sits before you look (hint: truncation is now ∝ h²).

🔗 Where this is heading

Every method in this specialization is a negotiation between truncation and round-off. ODE solvers (Course 2) accumulate per-step truncation error over thousands of steps; eigenvalue and linear-solver accuracy (Course 3) is amplified by a matrix's condition number; PDE schemes (Course 4) trade step size against stability through the CFL condition; and Monte-Carlo estimates (Course 5) carry a statistical error that falls only as 1/√N. The same vocabulary — order, convergence, conditioning — recurs throughout the Quantum, Plasma, and Quant tracks. Learn to think in error budgets now and every later result becomes trustworthy.

❓ Lecture 1 Quiz

5 questions · click "Show answer" to check yourself.

Q1. Machine epsilon for IEEE 754 double precision (≈ 2.2×10⁻¹⁶) represents…
A. the smallest positive number a double can store
B. the largest number before overflow
C. the spacing between 1.0 and the next representable double (relative resolution)
D. the truncation error of Simpson's rule
Show answer

C. ε = 2⁻⁵² is the gap between 1.0 and the next double — the relative precision. The smallest positive double (A) is a far tinier ~10⁻³⁰⁸ (denormalized).

Q2. Replacing a derivative by [f(x+h) − f(x)]/h introduces which kind of error from the method itself?
A. truncation error
B. round-off error
C. overflow
D. no error
Show answer

A. Truncating the Taylor series at finite h is truncation error (∝ h here). Round-off (B) is the separate finite-precision error that grows as h → 0.

Q3. In Python, 0.1 + 0.2 == 0.3 evaluates to…
A. True
B. False — none of these store exactly, so compare with a tolerance
C. a syntax error
D. True only on 64-bit machines
Show answer

B. 0.1 + 0.2 stores as 0.30000000000000004. Never test float equality with ==; use abs(a − b) < tol (or np.isclose).

Q4. For a forward-difference derivative, making the step h smaller and smaller will…
A. always reduce the total error toward zero
B. only affect speed, not accuracy
C. have no effect on the error
D. reduce error until round-off dominates near h ≈ √ε, then increase it
Show answer

D. Truncation falls with h but round-off (∝ 1/h) eventually takes over; total error bottoms out around h ≈ √ε ≈ 10⁻⁸ and then rises.

Q5. A method has error ≈ C·h². If you halve the step size h, the error is reduced by a factor of about…
A. 4
B. 2
C. 8
D. unchanged
Show answer

A. A second-order method (p = 2) improves by 2ᵖ = 2² = 4 when h is halved. (First-order would improve by 2; fourth-order by 16.)

✓ What you learned

  • How doubles store numbers and that machine epsilon ε = 2⁻⁵² ≈ 2.2×10⁻¹⁶ is the relative resolution.
  • The difference between round-off error (finite precision) and truncation error (the method).
  • Absolute vs relative error, and order of convergence: error ≈ C·hᵖ, so halving h gains a factor 2ᵖ.
  • Catastrophic cancellation — and never testing floats with ==.
  • The truncation–round-off trade-off: a forward difference is best near h ≈ √ε with error only ~10⁻⁸, observed in NumPy.
