Random Numbers & Monte Carlo Basics

When a problem is too tangled to solve with a formula, you can throw random darts at it — and, astonishingly, the average of those darts converges on the exact answer.

🎯 Learning Objectives

  • Explain what a pseudo-random number generator is and why seeding makes a stochastic program reproducible.
  • Transform uniform random numbers into any distribution using the inverse-transform method.
  • State the core Monte Carlo idea: estimate an expectation by averaging samples.
  • Derive and interpret the 1/√N scaling of Monte Carlo error and explain why it is dimension-independent.
  • Use NumPy's modern Generator API to draw reproducible random numbers and run a first Monte Carlo estimate.

1.1Pseudo-Random Numbers & Seeding

A computer is a deterministic machine: given the same inputs it always produces the same outputs. So it cannot generate "true" randomness on its own. Instead it runs a pseudo-random number generator (PRNG): a function that, from an internal state, produces a number that looks random and then updates the state for the next call. The stream is fully determined, yet it passes statistical tests for uniformity and independence well enough to stand in for randomness.

Symbolically, a PRNG advances its state s and emits a value u in the interval [0, 1):

sn+1 = f(sn),   un = g(sn) in [0, 1)The same starting state s0 (the "seed") always reproduces the identical stream u0, u1, u2, ...

The starting state is called the seed. Set the same seed and you get the exact same sequence of "random" numbers every run. This is not a bug — it is the single most important habit in stochastic computing. A reproducible seed means a colleague can rerun your simulation and get your figure to the last digit, a bug can be replayed deterministically, and a paper's results can be audited. Modern generators (NumPy uses PCG64 by default) have enormous period and excellent statistical quality; the old rand()-style linear congruential generators are best avoided for serious work.

AnalogyA PRNG is like a very long, pre-printed deck of cards shuffled once at the factory. The seed tells you which card to start dealing from. Two people who start at the same card deal the identical hands forever — so "random" here means "unpredictable unless you know the seed," not "uncaused."

1.2Sampling Any Distribution: the Inverse-Transform Method

A PRNG hands you uniform numbers on [0, 1). But physics rarely wants uniform draws — you might need exponentially distributed decay times, or radii weighted by area. The inverse-transform method turns a uniform draw into a sample from any distribution whose cumulative distribution function (CDF) you can invert.

Let a target distribution have CDF F(x) = P(X ≤ x), which rises monotonically from 0 to 1. If U is uniform on [0, 1), then setting X = F-1(U) produces a sample drawn from exactly that distribution:

draw U ~ Uniform[0,1),  then  X = F-1(U)Because P(X ≤ x) = P(F-1(U) ≤ x) = P(U ≤ F(x)) = F(x), the result has the desired CDF.

The recipe: pick a uniform height U on the vertical axis, slide horizontally until you hit the CDF curve, and read off the x. Steep parts of the CDF (where probability is dense) capture more of the uniform heights, so more samples land there. For the exponential distribution with rate λ, F(x) = 1 - e-λx, which inverts to a clean closed form:

X = -(1/λ) · ln(1 - U)  (or equivalently -(1/λ)·ln U)One uniform draw becomes one exponentially distributed waiting time — the workhorse for radioactive-decay and queueing simulations.
Common mistakeThe inverse-transform method needs an invertible CDF. For the Gaussian (normal) distribution there is no elementary closed form for F-1, so people sometimes invert a crude approximation and get a subtly wrong tail. Don't reinvent it: use a dedicated generator (NumPy's standard_normal, built on the Box–Muller / ziggurat methods). Reserve hand-rolled inverse transform for distributions whose inverse CDF you actually know in closed form.

1.3The Core Monte Carlo Idea

Here is the whole philosophy in one line: any quantity you can write as an average can be estimated by sampling. Suppose you want the expected value of some function h of a random variable X drawn from a distribution p:

I = E[h(X)] = ∫ h(x) p(x) dxAn integral against a probability density is just an average of h over draws from p.

Rather than evaluate that integral analytically, draw N independent samples X1, ..., XN from p and take the plain arithmetic mean:

I ≈ ÎN = (1/N) ∑i=1..N h(Xi)The Law of Large Numbers guarantees ÎN -> I as N -> infinity.

The estimator ÎN is itself random — run it twice with different seeds and you get slightly different numbers — but it is unbiased: its expected value is exactly I, and it converges to I as N grows. This is the engine behind Monte Carlo integration, particle-transport codes, financial option pricing, Bayesian inference, and statistical-physics simulations of magnets and fluids. A classic toy version: estimate π by throwing random points into a square and counting the fraction that land inside the inscribed quarter-circle — that fraction times 4 estimates π.

1.4Why Monte Carlo Error Scales as 1/√N

How accurate is the estimate? Each term h(Xi) is an independent draw with some variance σ2 = Var[h(X)]. The estimator is their mean, and the variance of a mean of N independent terms is the single-sample variance divided by N:

Var[ÎN] = σ2 / N  =>   standard error = σ / √NThe typical size of the random error is the square root of the variance — it falls only as one over root N.

This is the famous 1/√N law, a direct consequence of the Central Limit Theorem: to cut the error in half you must do four times the work; for one more decimal digit (10x smaller error) you need 100x the samples. That sounds slow, and for low-dimensional smooth integrals it is — a deterministic rule like Simpson's beats it easily.

The magic is what the formula does not contain: the dimension d. A grid-based rule needs about kd points to keep k points per axis, so its cost explodes in high dimensions (the "curse of dimensionality"). Monte Carlo error is σ/√N regardless of whether x lives in 1 dimension or 1000. That is why Monte Carlo dominates high-dimensional problems: path integrals, lattice field theory, 3N-dimensional partition functions, and 50-asset financial portfolios.

✦ Worked Example — estimating π and sizing the run

You throw N = 10,000 uniform random points into the unit square and count how many fall inside the quarter-circle x² + y² ≤ 1. Estimate π, and figure out how many samples you'd need to expect an error around 0.01.

  1. The estimator: each point is a "hit" with probability p = (area of quarter-circle)/(area of square) = (π/4)/1 = π/4 ≈ 0.7854. So π̂ = 4 · (hits/N).
  2. Run it: suppose 7,830 of the 10,000 points are hits. Then π̂ = 4 × (7830/10000) = 4 × 0.7830 = 3.132. True π = 3.1416, so the error here is about 0.010.
  3. Predict the error. Each hit is a Bernoulli trial with variance p(1-p) = 0.7854 × 0.2146 ≈ 0.1686. The fraction's standard error is √(0.1686/N); multiply by 4 (since π̂ = 4·fraction): SE(π̂) = 4·√(0.1686/N) = 1.642/√N.
  4. Check N = 10,000: SE = 1.642/√10000 = 1.642/100 = 0.0164. Our observed error 0.010 is well within one standard error — consistent.
  5. Size the run for SE ≈ 0.01: set 1.642/√N = 0.01 -> √N = 164.2 -> N ≈ 27,000. To halve that error to 0.005 you'd need 4× more, about 108,000 samples — the 1/√N tax in action.

🛠️ Hands-On: seed it, sample it, estimate π

The free Python + NumPy / Matplotlib stack runs everything in this course (Numba is optional, added later for speed). Week 1 setup: install it once below, then reuse it every lecture and for the project.

⬇ Install Python + NumPy / Matplotlib (one-time, Week 1 setup)

With Python 3 installed (from python.org or your package manager), create an environment and install the scientific stack:

python3 -m venv mcphys-env
source mcphys-env/bin/activate        # macOS / Linux
mcphys-env\Scripts\activate            # Windows (PowerShell)
pip install numpy matplotlib jupyter

Verify: run python -c "import numpy; print(numpy.__version__)" — a version string means you're set. (numba is optional and only added later for speed.)

First create a seeded Generator so the run is reproducible, draw uniforms and an inverse-transform exponential, then estimate π and print its standard error.

# monte_carlo_basics.py — Lecture 1
import numpy as np

rng = np.random.default_rng(seed=42)     # reproducible: same seed -> same stream

# uniform draws on [0,1)
u = rng.random(5)
print("uniforms:", u)

# inverse-transform: exponential waiting times, rate lambda = 2.0
lam = 2.0
x = -np.log(rng.random(100_000)) / lam   # X = -ln(U)/lambda
print("exp mean (should be 1/lam = 0.5):", x.mean())

# Monte Carlo estimate of pi
N = 1_000_000
pts = rng.random((N, 2))                 # N points in the unit square
inside = (pts[:, 0]**2 + pts[:, 1]**2) <= 1.0
frac = inside.mean()
pi_est = 4 * frac
se = 4 * np.sqrt(frac * (1 - frac) / N)   # standard error of the estimate
print(f"pi ~ {pi_est:.4f}  +/- {se:.4f}   (true {np.pi:.4f})")
# re-running with the SAME seed prints the EXACT same numbers

Try it: change the seed and watch the estimate wobble by about one standard error. Then quadruple N and confirm the error roughly halves — the 1/√N law, live.

🔗 Where this is heading

These three ideas — seeded generators, inverse-transform sampling, and the 1/√N average — are the foundation for the whole course. Week 2 turns the π-dartboard into general Monte Carlo integration and introduces importance sampling, which shrinks σ (not N) to beat the 1/√N tax. Later weeks build Markov-chain Monte Carlo (the Metropolis algorithm) to sample the Boltzmann distribution of the Ising model and other statistical-physics systems where you can't invert the CDF. The same machinery reappears across the specialization: stochastic differential equations in the Quant track, quantum Monte Carlo for many-body ground states, and Bayesian inference everywhere data meets models.

❓ Lecture 1 Quiz

5 questions · click "Show answer" to check yourself.

Q1. Why do we say a computer's random numbers are "pseudo-random"?
A. They are drawn from real atmospheric noise
B. They are produced by a deterministic algorithm from an internal state, but pass statistical tests for randomness
C. They are biased toward small values
D. They cannot be reproduced from run to run
Show answer

B. A PRNG is a deterministic function of its state that only mimics randomness. A is false (no physical noise source); C is false (good PRNGs are uniform); D is the opposite of the truth — fixing the seed makes them perfectly reproducible.

Q2. You set np.random.default_rng(seed=42) and run your simulation twice. What happens?
A. The two runs produce completely independent, different streams
B. The second run errors because the seed is already used
C. Both runs produce the identical sequence of random numbers
D. The seed only affects integers, not floats
Show answer

C. A fixed seed sets the starting state, so the stream is identical every run — the basis of reproducibility. A describes unseeded behavior; B is false (reusing a seed is fine and intended); D is false (the seed governs every draw, ints and floats alike).

Q3. To sample from a distribution with CDF F using one uniform draw U, the inverse-transform method computes…
A. X = F-1(U)
B. X = F(U)
C. X = U / F
D. X = 1 - U
Show answer

A. Inverting the CDF at a uniform height gives a sample with that CDF, since P(F-1(U) ≤ x) = F(x). B applies the CDF forward (wrong direction); C is dimensionally meaningless; D just reflects the uniform and stays uniform.

Q4. A Monte Carlo estimate has a standard error of 0.02 with N = 10,000 samples. About how many samples do you need to bring the error down to 0.005?
A. 20,000
B. 40,000
C. 80,000
D. 160,000
Show answer

D. Error ∝ 1/√N, so cutting error by a factor of 4 (0.02 -> 0.005) requires 4² = 16× more samples: 16 × 10,000 = 160,000. A (2×) and B (4×) and C (8×) all underestimate because they ignore the square in the 1/√N law.

Q5. Why is Monte Carlo integration especially attractive for high-dimensional problems?
A. Its error always reaches machine precision
B. Its 1/√N error rate does not depend on the dimension d, unlike grid rules whose cost grows like kd
C. It needs no random numbers at all
D. It converges faster than Simpson's rule in one dimension
Show answer

B. The standard error σ/√N contains no d, while grid methods suffer the curse of dimensionality (kd points). A is false (statistical error never reaches machine epsilon); C is absurd; D is backwards — in 1D smooth problems Simpson's rule beats Monte Carlo.

✓ What you learned

  • A PRNG is a deterministic algorithm whose state-driven stream mimics randomness; the seed makes runs reproducible.
  • The inverse-transform method turns a uniform draw into any distribution via X = F-1(U), e.g. exponential times as -(1/λ)ln U.
  • The core Monte Carlo idea: any expectation I = E[h(X)] is estimated by the sample mean of h over random draws.
  • Monte Carlo's standard error is σ/√N — cut error in half costs 4× the work, and the rate is independent of dimension.
  • NumPy's modern default_rng Generator draws reproducible samples and lets you compute the standard error directly.
