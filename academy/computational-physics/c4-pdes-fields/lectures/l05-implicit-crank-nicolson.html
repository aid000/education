Week 5 · Lecture 5

Implicit Methods & Crank-Nicolson

When the explicit step demands a punishingly small Δt, you stop guessing the future from the past and instead solve for it — trading a linear system per step for the freedom to march as boldly as accuracy allows.

🎯 Learning Objectives

  • Explain the difference between explicit and implicit time-stepping and why implicit schemes evaluate spatial derivatives at the new time level.
  • Derive the backward-Euler scheme for the heat equation and show by von Neumann analysis that it is unconditionally stable.
  • State the Crank-Nicolson scheme as the average of forward and backward Euler, and explain why it is second-order accurate in time and stable.
  • Recognize that one implicit step requires solving a tridiagonal linear system and use the Thomas algorithm to do it in O(N) work.
  • Reason about the stability-vs-accuracy-vs-cost trade-off and choose a scheme for a given problem.

5.1Explicit vs Implicit: Who Knows the Future?

Last week we discretized the 1-D heat equation ut = α uxx with the FTCS (forward-time, centered-space) scheme and found a harsh price: the CFL-type stability limit forced the diffusion number r = αΔt/Δx² ≤ 1/2. Halving the grid spacing Δx quarters the allowed time step. For a fine spatial mesh that is ruinous.

The root cause is that FTCS is explicit: the new value uin+1 is written purely in terms of old, already-known values at time level n. Each new point is a plain formula you evaluate — fast, but it only "sees" information that has had time Δt to travel one grid cell, so a too-large step lets errors outrun the physics and blow up.

explicit (FTCS):  uin+1 = uin + r ( ui+1n − 2uin + ui−1n )Right-hand side uses only time level n — nothing to solve, but stability demands r ≤ 1/2.

An implicit scheme instead evaluates the spatial second derivative at the new time level n+1. Now the unknown uin+1 appears on both sides and is coupled to its new neighbors. You can no longer read it off; you must solve for all the new values together. That coupling is exactly what buys stability: every point feels every other point instantly, mimicking the infinite signal speed of diffusion.

AnalogyExplicit stepping is like predicting tomorrow's weather using only today's measurements and a fixed rule — quick, but if you leap too far ahead the forecast diverges into nonsense. Implicit stepping is like saying "find the temperatures tomorrow that are self-consistent with each other and with today." You solve a puzzle whose pieces all constrain one another, so no single piece can run away. The puzzle costs effort, but the answer never explodes.

5.2Backward Euler and Unconditional Stability

The simplest implicit scheme is backward Euler (BTCS: backward-time, centered-space). Keep the centered second difference but evaluate it at time n+1:

uin+1 − uin = r ( ui+1n+1 − 2uin+1 + ui−1n+1 )r = αΔt/Δx². The three unknowns at level n+1 are coupled — this is one row of a linear system.

Rearranging so all the unknowns sit on the left gives, for each interior node i,

−r ui−1n+1 + (1 + 2r) uin+1 − r ui+1n+1 = uinA tridiagonal system A un+1 = un, with diagonal 1+2r and off-diagonals −r.

To test stability we use von Neumann analysis: substitute a Fourier mode uin = Gn ei k x and solve for the amplification factor G, the amount each mode is multiplied by per step. Using the identity 2 − 2cos(kΔx) = 4 sin²(kΔx/2), backward Euler gives:

G = 1 / ( 1 + 4r sin²(kΔx / 2) )The denominator is ≥ 1 for every wavenumber k and every r > 0, so |G| ≤ 1 always.

Because |G| ≤ 1 for all step sizes and all modes, backward Euler is unconditionally stable. You may take Δt as large as you like and the solution will never blow up. This is the whole point of going implicit: stability is no longer a leash on Δt.

Common mistake"Unconditionally stable" does not mean "accurate for any Δt." Backward Euler is only first order in time (error ∝ Δt). A huge step gives a stable but badly smeared, inaccurate answer — sharp features get artificially damped. Stability keeps the run from exploding; it says nothing about how close you are to the true solution.

5.3Crank-Nicolson: Second-Order and Stable

Forward Euler evaluates the spatial term entirely at time n; backward Euler entirely at n+1. Both are first-order in time because they are "lopsided." The Crank-Nicolson scheme takes the symmetric average of the two — it evaluates the second derivative as the mean of its values at n and n+1:

(uin+1 − uin) / Δt = (α/2) [ δxx uin+1 + δxx uin ]δxx ui = (ui+1 − 2ui + ui−1)/Δx² is the centered second difference. Averaging the two levels centers the scheme in time.

Centering in time at the midpoint n+1/2 is what makes the truncation error symmetric and cancels the leading O(Δt) term, leaving second-order accuracy in both time and space: error ∝ Δt² + Δx². Collecting unknowns to the left with r = αΔt/Δx² gives another tridiagonal system, now with a non-trivial right-hand side:

−(r/2) ui−1n+1 + (1+r) uin+1 − (r/2) ui+1n+1 = (r/2) ui−1n + (1−r) uin + (r/2) ui+1nBoth sides are tridiagonal; the left matrix A is solved once per step against a known right-hand vector.

Von Neumann analysis of Crank-Nicolson gives an amplification factor that is the ratio of the forward and backward factors:

G = ( 1 − 2r sin²(kΔx/2) ) / ( 1 + 2r sin²(kΔx/2) )For any r > 0 the magnitude |G| ≤ 1, so Crank-Nicolson is also unconditionally stable.

So Crank-Nicolson keeps backward Euler's unconditional stability and upgrades the time accuracy from first to second order — the best of both worlds, at the same per-step cost of one tridiagonal solve.

Common mistakeCrank-Nicolson is unconditionally stable but not unconditionally non-oscillatory. For high-frequency modes when r is large, G approaches −1: stable, yet the mode flips sign each step, producing decaying "wiggles" near sharp initial data. Backward Euler damps these instead (its G stays in [0,1)). If your initial condition is discontinuous, expect ringing from Crank-Nicolson unless you keep r modest or smooth the start.

5.4The Cost of Going Implicit: Solving a Tridiagonal System

Implicit schemes are not free: every step you must solve A un+1 = b for the whole vector of unknowns at once. For the 1-D heat equation that matrix A is tridiagonal — nonzero only on the main diagonal and the two adjacent diagonals — because each node couples only to its immediate neighbors.

A general dense solve costs O(N³), which would make implicit stepping hopeless. But a tridiagonal system is solved by the Thomas algorithm (a specialized Gaussian elimination) in just O(N) operations — one forward sweep to eliminate the sub-diagonal, one backward sweep to back-substitute:

cost per step:  explicit ~ O(N)  |   implicit (tridiagonal) ~ O(N)Same per-step order. The implicit step has a larger constant (a solve, not a formula), but allows a far larger Δt.

So the real comparison is total cost to reach a final time T. Explicit: many cheap steps (Δt ≤ Δx²/2α). Implicit: few expensive steps (Δt set by accuracy, not stability). When the stability limit is much smaller than the accuracy you need, implicit wins decisively. When you need fine time resolution anyway (e.g. a fast-moving wave), explicit's cheaper step can be competitive.

✦ Worked Example — one backward-Euler step by hand

Heat equation on 5 nodes (i = 0..4), spacing Δx = 0.25, with fixed ends u0 = u4 = 0 (Dirichlet). Diffusivity α = 1. Initial interior values u10 = 0, u20 = 1, u30 = 0 (a spike). Take a step Δt = 0.0625 with backward Euler and find the new interior values.

  1. Diffusion number: r = αΔt/Δx² = 1·0.0625 / 0.0625 = 1.0. (Explicit FTCS would be unstable here since r > 1/2 — but backward Euler is fine.)
  2. Build the 3×3 system for the interior unknowns. Each row: −r ui−1 + (1+2r) ui − r ui+1 = ui0. With 1+2r = 3 and r = 1, and boundary terms = 0:
    3u1 − u2 = 0 ;  −u1 + 3u2 − u3 = 1 ;  −u2 + 3u3 = 0
  3. Symmetry: the spike is symmetric, so u1 = u3. From row 1: u2 = 3u1.
  4. Substitute into row 2: −u1 + 3(3u1) − u1 = 1 → 7u1 = 1 → u1 = u3 = 1/7 ≈ 0.1429.
  5. Center: u2 = 3·(1/7) = 3/7 ≈ 0.4286. Check: the peak dropped from 1 to 0.43 and the neighbors rose from 0 to 0.14 — heat spread outward and total stayed bounded. Stable and physical even though r = 1.

🛠️ Hands-On: backward Euler vs Crank-Nicolson on a diffusing spike

Uses the free Python + NumPy/SciPy/Matplotlib stack from the Week 1 setup (see the install <details> in Lecture 1 — no new tools needed here). We build the tridiagonal matrices once with scipy.sparse and use its banded solver, which runs the Thomas algorithm internally.

# implicit_heat.py — Lecture 5
import numpy as np
import scipy.sparse as sp
import scipy.sparse.linalg as spla
import matplotlib.pyplot as plt

N  = 201                       # grid points on [0,1]
dx = 1.0 / (N - 1)
alpha, dt, T = 1.0, 1e-3, 0.05
r  = alpha * dt / dx**2        # ~10  -> explicit would explode!
nsteps = int(T / dt)

x = np.linspace(0, 1, N)
u = np.where(np.abs(x - 0.5) < 0.05, 1.0, 0.0)   # a narrow box (sharp data)

# interior tridiagonal builders (Dirichlet u=0 at both ends)
main = np.ones(N); off = np.zeros(N - 1)

def tridiag(d, o):             # build sparse tridiagonal
    return sp.diags([o, d, o], [-1, 0, 1], format="csc")

# backward Euler:  (I + r*L) u^{n+1} = u^n,  L = -tridiag(2,-1)/...
A_be = tridiag((1 + 2*r) * main, -r * off)
# Crank-Nicolson:  A_cn u^{n+1} = B_cn u^n
A_cn = tridiag((1 + r) * main, -(r/2) * off)
B_cn = tridiag((1 - r) * main,  (r/2) * off)

def fix_bc(M):                 # pin boundary rows to identity
    M = M.tolil(); M[0, :] = 0; M[0, 0] = 1
    M[-1, :] = 0; M[-1, -1] = 1; return M.tocsc()

A_be, A_cn = fix_bc(A_be), fix_bc(A_cn)

u_be, u_cn = u.copy(), u.copy()
for _ in range(nsteps):
    u_be = spla.spsolve(A_be, u_be)                 # one O(N) solve
    rhs  = B_cn @ u_cn; rhs[0] = rhs[-1] = 0.0
    u_cn = spla.spsolve(A_cn, rhs)

plt.plot(x, u_be, label="backward Euler")
plt.plot(x, u_cn, label="Crank-Nicolson")
plt.legend(); plt.xlabel("x"); plt.ylabel("u"); plt.show()
# Both stay bounded at r~10 (explicit FTCS would diverge instantly).
# Watch CN show faint ringing near the box edges; BE is smoother but more damped.

Experiment: shrink dt until r ≤ 0.5 and add a third curve using explicit FTCS — confirm all three now agree, and that above r = 0.5 only the implicit pair survives. Then time the loops (Python's time.perf_counter) and compare total cost to reach T for each scheme.

🔗 Where this is heading

Implicit time-stepping is the workhorse of stiff field simulation. Next week (Lecture 6) we make these tridiagonal systems honest by handling real boundary conditions — Dirichlet, Neumann, and periodic — which change the corner entries of A. In 2-D and 3-D the matrix is no longer tridiagonal but sparse-banded; operator-splitting methods like ADI (alternating-direction implicit) restore a sequence of cheap tridiagonal solves. The very same θ-method family (θ = 0 explicit, θ = 1 backward Euler, θ = 1/2 Crank-Nicolson) reappears in Course 2's stiff ODE solvers, and Crank-Nicolson is the standard integrator for the time-dependent Schrödinger equation in the Quantum track — there its unitarity keeps probability conserved exactly. The sparse linear solves you meet here are the bridge to Course 3's iterative methods (conjugate gradient, multigrid) once the grids get large.

Q1. What fundamentally distinguishes an implicit scheme from an explicit one for the heat equation?
A. It uses a finer spatial grid
B. It evaluates the spatial derivative term at the new time level n+1, coupling the unknowns
C. It ignores the boundary conditions
D. It is always faster per step
Show answer

B. Implicit schemes evaluate uxx at level n+1, so the new unknowns are coupled and must be solved together. A is unrelated (grid choice is independent). C is false — boundaries still matter. D is wrong: an implicit step is more expensive per step (it requires a solve), not less.

Q2. Backward Euler for the heat equation is "unconditionally stable." This means…
A. the solution is accurate for any Δt
B. it conserves energy exactly
C. |G| ≤ 1 for every mode and every Δt, so it never blows up regardless of step size
D. it requires no linear solve
Show answer

C. Its amplification factor G = 1/(1 + 4r sin²(kΔx/2)) has magnitude ≤ 1 for all r and all k. A confuses stability with accuracy (it's only first-order accurate). B is false — it is dissipative, not conservative. D is false — it still needs a tridiagonal solve.

Q3. The Crank-Nicolson scheme is best described as…
A. the average of forward Euler and backward Euler, giving second-order accuracy in time
B. the same as FTCS but with a smaller step
C. a purely explicit scheme
D. a method that is only first-order in space
Show answer

A. Crank-Nicolson averages the spatial term at n and n+1 (the θ = 1/2 case), centering it in time for O(Δt²) accuracy. B is wrong — it is a distinct, implicit scheme. C is wrong — it is implicit (needs a solve). D is wrong — the centered second difference is second-order in space.

Q4. Why is one backward-Euler (or Crank-Nicolson) step on the 1-D heat equation still only O(N) work despite needing a linear solve?
A. The matrix is dense, so an O(N³) solve is unavoidable
B. The matrix is tridiagonal and the Thomas algorithm solves it in O(N)
C. It avoids solving any system by inverting term by term
D. NumPy caches the answer from the previous step
Show answer

B. Each node couples only to its two neighbors, so A is tridiagonal; the Thomas algorithm (a banded Gaussian elimination) solves it in O(N). A is the opposite — it is not dense. C makes no sense — the coupling cannot be inverted entry-by-entry. D is fabricated; the right-hand side changes each step.

Q5. You must reach a final time T on a very fine spatial mesh where the explicit stability limit forces an absurdly small Δt. Which scheme is the natural choice, and why?
A. Explicit FTCS, because each step is a plain formula
B. Explicit FTCS with r exactly equal to 1, to maximize the step
C. No method can handle a fine mesh efficiently
D. An implicit scheme (e.g. Crank-Nicolson), since its unconditional stability lets Δt be set by accuracy, not the CFL-type limit
Show answer

D. When the stability limit is far stricter than the accuracy you need, an implicit scheme's unconditional stability lets you take big steps and win on total cost. A loses because the tiny forced Δt means a huge step count. B is wrong — r = 1 violates the r ≤ 1/2 explicit limit and diverges. C is false — implicit methods exist precisely for this case.

✓ What you learned

  • Explicit vs implicit: explicit reads the new value from old neighbors; implicit evaluates the spatial term at n+1, coupling all unknowns so they must be solved together.
  • Backward Euler (BTCS) has amplification factor G = 1/(1 + 4r sin²(kΔx/2)), so |G| ≤ 1 always — it is unconditionally stable, but only first-order in time.
  • Crank-Nicolson averages forward and backward Euler (θ = 1/2): second-order in time and space and still unconditionally stable, at the same per-step cost.
  • An implicit step requires solving a tridiagonal system, done in O(N) by the Thomas algorithm — same per-step order as explicit but with a bigger constant.
  • The real choice is a stability–accuracy–cost trade-off: implicit wins when the explicit stability limit is far smaller than the step accuracy actually demands.
