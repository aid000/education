Week 5 · Lecture 5

Prompting II — Structure, Long Context & Tree-of-Thoughts

Week 4 made the model understand you. Now you make it organize its work, check itself, and explore several paths before committing to one.

🎯 Learning Objectives

  • Demand structured output (JSON, tables, fixed templates) and explain why it makes answers easier to use and verify.
  • Use decomposition — break one hard request into a chain of smaller, checkable steps.
  • Trigger self-critique and reflection so the model finds its own errors before you do.
  • Explain how tree-of-thoughts extends chain-of-thought by exploring and pruning multiple branches.
  • Place information well inside a long context window and run a disciplined prompt-iteration loop.

5.1From Free Text to Structure

In Week 4 you learned the four levers of a good prompt: specificity, roles, few-shot examples, and chain-of-thought. Those make the model understand the task. This lecture is about shaping the shape of the answer and the process the model uses to reach it.

The single highest-leverage upgrade is to stop accepting free-flowing prose and instead ask for a structured output: a JSON object, a markdown table, a numbered checklist, or a fixed template with labelled fields. Structure helps in three ways:

  • Machine-usable — a JSON object drops straight into code, a spreadsheet, or another prompt. Prose has to be parsed by hand.
  • Verifiable — if you asked for five fields and got four, the gap is obvious. Missing reasoning hides inside paragraphs.
  • Steering — naming the fields tells the model exactly what to think about. "Give me risk, mitigation, and owner for each item" forces all three to exist.

Remember from earlier weeks that a model is a next-token predictor. When the visible text so far is {"summary": ", the most probable continuation is a sentence that closes the quote — so a partially-specified format strongly biases what comes next. That is exactly why showing the skeleton works.

AnalogyAsking for free text is like asking a contractor "tell me about the kitchen job." Asking for structure is handing them a form: line items, quantities, unit cost, total. Same expertise — but now nothing is forgotten, and you can add up the column yourself to check the math.

5.2Decomposition — One Big Ask Becomes Many Small Ones

Hard requests fail silently when crammed into one shot: "Read this 20-page contract, find the risky clauses, rewrite them, and draft an email to the vendor." The model does some of each and excels at none. Decomposition splits the job into a chain where each step has one clear deliverable that you (or the next step) can check.

one hard prompt  ⟶  [ extract ] → [ analyze ] → [ rewrite ] → [ draft ]Each arrow is a checkpoint. An error caught at "extract" never propagates to "draft."

Decomposition pairs naturally with structure: have step 1 emit a JSON list of clauses, feed that list into step 2, and so on. This is also the conceptual bridge to agents (Week 6) — an agent is essentially a model that decomposes a goal into steps and then executes them with tools.

5.3Self-Critique & Reflection

A model that writes an answer in one pass cannot "look back" the way you can. But you can ask it to. Self-critique (also called reflection) is a two-stage move: first produce a draft, then in a second turn ask the model to find flaws in its own draft and revise.

Why does this help at all, if it's the same model? Because critiquing and generating are different tasks. When the draft is already in the context window, the model can now spend its prediction effort on the narrower question "what is wrong with this?" — which often surfaces gaps the first pass papered over. Useful framings:

  • "List 3 things that could be wrong or missing, then fix them."
  • "Check this against the requirements I gave; mark each as met or not."
  • "Where might a careful reader disagree? Strengthen those parts."
Common mistakeSelf-critique is not a fact-checker. A model can confidently "verify" a wrong claim and call it correct — its critique is still generated text, not ground truth. For anything load-bearing (numbers, citations, code that runs), check against a real source or actually run it. Reflection improves structure, completeness, and reasoning; it does not guarantee truth. We return to this in Week 9 (Hallucinations & Ethics).

5.4Chain-of-Thought → Tree-of-Thoughts

Chain-of-thought (Week 4) walks a problem in a single straight line of reasoning. That works until the first step is a guess — then the whole chain is locked into one possibly-wrong path. Tree-of-thoughts (a research framing introduced around 2023; treat the specifics as a prompting pattern, not a fixed product feature) generalizes this: at each step, generate several candidate "thoughts," evaluate them, keep the promising branches, and prune the rest.

CoT:  A → B → C → answer     ToT:  A ⟶ {B₁, B₂, B₃} → evaluate → expand bestA chain commits to one path; a tree explores branches and backtracks when one looks weak.

You do not need special software to use the idea. A plain-chat recipe: "Brainstorm 3 distinct approaches to X. For each, list one strength and one weakness. Pick the best and explain why. Then fully develop only that one." That is tree-of-thoughts in miniature — and it shines on puzzles, planning, and problems where the first idea is often not the best.

5.5Working With Long Context

Modern models accept large context windows — the running total of tokens (your instructions + pasted documents + the conversation so far) the model can attend to at once. Windows have grown dramatically; as of 2026, flagship models commonly advertise context windows in the hundreds of thousands of tokens, with some offering ~1 million — verify the exact limit against current official sources, since it changes frequently and differs by model and tier.

A bigger window is not a free lunch. Two durable rules:

  • Position matters. Models tend to use information at the start and end of a long input more reliably than material buried in the middle (the "lost-in-the-middle" effect reported in research). Put your actual question and the most critical material near the edges.
  • Delimit your sources. Wrap pasted documents in clear markers — e.g. <document>…</document> — and refer to them by name. This stops the model from confusing the instructions with the data.
AnalogyA long context window is like a witness who just read a 300-page report and now has to answer from memory. They recall the opening and the conclusion crisply, but page 147 is a blur. So you put the question at the top, the key exhibit at the bottom, and you label every exhibit — instead of trusting them to remember the middle.

5.6Prompt Iteration — Treat It Like an Experiment

Great prompts are rarely written; they're tuned. The discipline is the same scientific loop you've met all course: change one thing, observe, decide. Random rewrites that change five things at once teach you nothing, because you can't tell which change helped.

draft → run → diagnose the gap → change ONE lever → re-runThe levers, in rough order of impact: clearer task → an example or two → structure → reasoning request (CoT/critique).

When an output disappoints, name the failure before you fix it: Was it the wrong format? Missing information? A skipped step? An unstated assumption? Each failure maps to a specific lever — and keeping a short log of what you changed and what happened turns prompting from guesswork into a repeatable skill.

✦ Worked Example — turning a vague ask into a structured, self-checked prompt

Goal: get a usable comparison of three laptops from messy pasted notes. Watch the prompt evolve one lever at a time.

  1. v1 (vague): "Compare these laptops." → Result: a wandering paragraph; no clear winner, fields inconsistent.
  2. Diagnose: the failure is format and completeness, not understanding. Apply the structure lever.
  3. v2 (structured): "Compare them as a markdown table with columns: model | price | weight | battery | best-for. If a value is missing in my notes, write unknown — do not guess." → Now every laptop has the same fields, and gaps are explicit instead of invented.
  4. Add reasoning (decompose + CoT): append "Then, in 2 sentences, recommend one for a student who values portability, and say why." → A justified pick, not just data.
  5. Add self-critique: in a second turn: "Re-read my original notes. Did you put any value in the wrong row or invent a number? List corrections, then output the fixed table." → Catches a swapped battery figure.
  6. Takeaway: three small, named changes — structure, then reasoning, then reflection — turned an unusable blob into a checkable, decision-ready answer. None required a longer or cleverer single sentence; they required the right lever each time.

❓ Lecture 5 Quiz

6 questions · click "Show answer" to check yourself.

Q1. The main advantage of asking for structured output (e.g. JSON or a fixed table) is that it…
A. makes the model think faster
B. guarantees the facts are correct
C. makes answers machine-usable, easy to verify, and steers what the model includes
D. removes the need to give any instructions
Show answer

C. Structure makes output parsable, exposes missing fields, and names what to think about. It does not guarantee truth (B) — that still needs checking.

Q2. Decomposition means…
A. splitting one hard request into a chain of smaller, checkable steps
B. deleting parts of the prompt to make it shorter
C. letting the model choose its own topic
D. compressing the context window
Show answer

A. Each step has one clear deliverable you can verify before it feeds the next — and it's the conceptual bridge to agents.

Q3. Which statement about self-critique / reflection is accurate?
A. It turns the model into a reliable fact-checker
B. It improves structure, completeness, and reasoning, but does not guarantee the facts are true
C. It only works with a second, larger model
D. It makes hallucinations impossible
Show answer

B. A critique is still generated text — it can "approve" a wrong claim. Use it to tighten reasoning and completeness; verify load-bearing facts separately.

Q4. How does tree-of-thoughts differ from plain chain-of-thought?
A. It avoids reasoning entirely
B. It only works on math problems
C. It uses a bigger context window
D. It explores several candidate branches, evaluates them, and prunes the weak ones instead of committing to one line
Show answer

D. Chain-of-thought is a single path; tree-of-thoughts branches, scores, and backtracks — useful when the first step might be a wrong guess.

Q5. When pasting a long document into a big context window, a good practice is to…
A. bury the question in the exact middle of the text
B. put the question and key material near the start/end and clearly delimit the source
C. remove all paragraph breaks
D. assume position never matters
Show answer

B. Models use the edges of a long input more reliably than the middle ("lost-in-the-middle"); delimiters like <document> separate data from instructions.

Q6. The core discipline of prompt iteration is to…
A. rewrite everything at random until something works
B. always make the prompt longer
C. change one lever at a time, observe the effect, and log it
D. never change the first draft
Show answer

C. Like any experiment: vary one thing so you can attribute the result. Diagnose the failure (format? missing info? skipped step?) and pick the matching lever.

✓ What you learned

  • Structured output (JSON, tables, templates) makes answers machine-usable, verifiable, and steerable.
  • Decomposition turns one overloaded prompt into a chain of small, checkable steps — the bridge to agents.
  • Self-critique & reflection sharpen reasoning and completeness, but never replace real fact-checking.
  • Tree-of-thoughts extends chain-of-thought by proposing, scoring, and pruning multiple branches.
  • Place key material at the edges of a long context, delimit sources, and run a one-lever-at-a-time iteration loop.
