Week 2 · Lecture 2

How Models Learn — Tokens, Training & Prediction

A frontier model is, underneath, a machine that does one thing astonishingly well: guess the next token. Everything else emerges from that.

🎯 Learning Objectives

  • Explain what a token is and how text becomes a sequence of numbers a model can process.
  • Describe an embedding — a learned vector that places meaning in geometric space.
  • State the core training task: next-token prediction, and how it is scored and improved.
  • Distinguish the three stages of building a model: pretraining → fine-tuning → RLHF.
  • Give an intuitive reason why a next-token predictor generalizes to tasks no one programmed.

2.1From Text to Tokens: the Model's Alphabet

A language model never sees letters or words directly. Text is first chopped into tokens — chunks that are usually a common word, a word-piece, or a few characters. A rough rule of thumb (English): about 1 token ≈ 4 characters ≈ ¾ of a word, so a token count is a little larger than a word count. Each distinct token in the model's fixed vocabulary (often tens of thousands of entries) is assigned an integer ID.

Why not just use words, or just characters? Words make the vocabulary explode (and fail on anything unseen); single characters make sequences very long and force the model to relearn spelling constantly. Sub-word tokenization is the practical middle ground — it can spell out any string yet keeps common words compact.

Common mistake"One word = one token" is not reliable. Numbers, code, emoji, and non-English text often use several tokens each. This is why the same idea can cost more tokens in one language than another, and why a model may miscount letters in a word — it never saw the letters, only the chunk. When you hear about a context window of, say, "200K tokens," that is tokens, not words — divide by roughly 0.75 to estimate words.

2.2Embeddings: Turning IDs into Meaning

An integer ID like 11241 carries no meaning — 11241 isn't "more" than 262. So the first thing the model does is look each ID up in a giant table and replace it with a learned vector of numbers called an embedding. An embedding is a point in a high-dimensional space (hundreds to thousands of dimensions), and crucially the geometry is learned: tokens used in similar ways end up near each other.

token ID → embedding vector ∈ ℝdd is the model's embedding dimension. "king" and "queen" land near each other; "king" and "banana" land far apart.
AnalogyThink of embeddings as a map of meaning. Just as a city's latitude/longitude place it near similar cities, an embedding places a token near tokens it behaves like. The model doesn't memorize definitions; it learns where each word "lives" so that nearby words can be substituted and relationships (king→queen mirrors man→woman) show up as the same direction on the map.

From there, the Transformer's attention mechanism (Week 1) lets each token's vector get updated by looking at the others around it, so the embedding for "bank" can shift toward "river" or "money" depending on context. The output is a context-aware vector for the last position — ready to make a prediction.

2.3The Whole Game: Predict the Next Token

Here is the single task the model is trained on. Given a sequence of tokens, output a probability for every token in the vocabulary being the next one. That's it. The final layer produces a score for each vocabulary entry; a softmax turns those scores into probabilities that sum to 1.

P(next = t | "The cat sat on the ___")The model outputs a probability for every token; "mat" might get 0.31, "floor" 0.12, "roof" 0.04, and so on.

To train it, you take real text, hide the next token, ask the model to predict it, and measure how surprised it was by the true answer. That surprise is the loss (cross-entropy): low when the model gave the true token high probability, high when it didn't. Every parameter is then nudged by gradient descent to make the true token a little more likely next time. Repeat across trillions of tokens.

loss = − log P(true token)Confident & correct → loss near 0. Confident & wrong → large loss. Training minimizes the average loss.

To generate text, you flip it around: predict the next token, append it, and feed the longer sequence back in to predict the one after that. This step-by-step append loop is called autoregressive generation. A temperature setting controls how adventurously it samples: near 0 it almost always takes the highest-probability token (focused, repetitive); higher values let lower-probability tokens through (more varied, more error-prone).

Note — why it can "make things up"The model optimizes for plausible next tokens, not for truth. A confident, fluent, completely wrong sentence has exactly the statistical shape of a correct one, so nothing in the basic objective forbids it. This is the root of hallucination — covered in depth in Week 9. Treat fluent output as a draft to verify, not as a citation.

2.4Three Stages: Pretraining → Fine-Tuning → RLHF

A useful assistant isn't built in one shot. It's grown in three stages, each changing what the model is good at:

1 · Pretraining — learn the world from raw text

The model does next-token prediction over an enormous, broad corpus (web text, books, code). This is by far the most compute-intensive stage and where almost all of the model's knowledge and language ability comes from. The result is a base model: fluent and knowledgeable, but it just continues text — ask it a question and it might continue with more questions.

2 · Fine-tuning (instruction tuning) — learn to be helpful

Continue training on a smaller, curated set of instruction → good-response examples. Same next-token mechanism, narrower data. Now the model learns the format of being an assistant: when given an instruction, produce a direct, helpful answer rather than rambling.

3 · RLHF — learn human preferences

Reinforcement Learning from Human Feedback. Humans (and increasingly AI graders) rank competing responses; those rankings train a reward model, and the assistant is then optimized to produce responses the reward model scores highly. This is what makes outputs feel helpful, honest, and harmless — tone, refusals, and following nuanced preferences. (A related newer variant trains models to produce step-by-step reasoning before answering; more in Week 3.)

2.5Why Does a Next-Token Predictor Generalize?

It seems too simple. How can "guess the next token" produce something that translates, summarizes, codes, and reasons? The intuition: to predict the next token well across all of human text, you are forced to learn the structures behind the text.

To finish "The capital of France is ___" you need facts. To finish "2 + 2 = ___" you need arithmetic. To finish a sentence in correct French you need grammar. To finish "Therefore, the murderer was ___" in a mystery you need to track plot and motive. The training objective never names these skills — but the only way to keep the loss low across billions of varied examples is to internalize them. Capabilities are a side effect of compression: squeezing the patterns of all that text into a fixed set of weights.

This also explains in-context learning: if you show the model a couple of examples in the prompt, it can often continue the pattern without any retraining — because "continue the established pattern" is exactly what a next-token predictor is built to do. It's why prompting (Weeks 4–5) works at all.

AnalogyImagine a student forced to predict the last word of every sentence in a vast library. To get good, they can't just memorize — there isn't room. They must compress: learn that physics passages obey physics, that dialogue follows characters, that lists stay parallel. The "skills" we admire in a model are the compression artifacts of a relentless fill-in-the-blank drill.
Limit — generalization isn't understandingGeneralization is real but bounded. Models are strongest on patterns close to their training distribution and weakest on truly novel reasoning, fresh facts after their cutoff, and tasks needing reliable, verifiable truth. "It generalized" never means "it can't be wrong." Always pair capability claims with their limits — a habit we keep all course long.
✦ Worked Example — trace one prediction step

Walk a single next-token step for the prompt "The sky is", then estimate token usage. (Numbers are illustrative — the goal is the chain of reasoning, not exact values.)

  1. Tokenize: "The sky is" → roughly 3 tokens: The,  sky,  is (the leading space is part of the token).
  2. Embed: each ID becomes a vector; attention lets "is" attend to "sky" and "The," producing one context-aware vector for the final position.
  3. Score the vocabulary: the output layer scores every token. Say  blue → 0.46,  clear → 0.11,  falling → 0.05, …(thousands more, all summing to 1 after softmax).
  4. Sample: at temperature ≈ 0 the model emits  blue (the top choice); at higher temperature it might pick  clear. Append it → "The sky is blue".
  5. Repeat (autoregressive): feed "The sky is blue" back in to predict the next token, and so on until a stop token.
  6. Estimate usage: a 300-word reply ≈ 300 ÷ 0.75 ≈ 400 tokens. Both your prompt and the reply count toward the context window and any usage limits.

No new install needed — you'll use a free chatbot tier plus a short Python/Jupyter check. (Reminder: the one-time Python + Jupyter setup lives in Week 1.)

A. Probe a model about its own tokens (free tier of Claude, ChatGPT, or Grok). Paste each prompt and note what you observe:

  • "How many letter r's are in strawberry? Spell it out one letter at a time first." — note whether spelling it out helps. (It often does — it forces character-level work the tokenizer hid.)
  • "Give me 5 words close in meaning to bank (money sense), then 5 for bank (river sense)." — you're watching context steer the embedding.
  • Send the same creative prompt twice. Different each time? That's sampling above temperature 0.

B. Count tokens locally (Jupyter). A tiny, offline-friendly check of the "~¾ word per token" rule using a common open tokenizer:

# tokens_demo.ipynb — Lecture 2  (pip install tiktoken, once)
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")   # a widely-used BPE tokenizer

for text in ["The sky is blue.",
             "Tokenization",
             "internationalization",
             "🚀 café 2026"]:
    ids = enc.encode(text)
    print(f"{len(text.split()):>2} words | {len(ids):>2} tokens | {text!r}")
    print("   ids:", ids)
# Notice: long/rare words split into several tokens; emoji & accents cost extra.
# Watch the words-to-tokens ratio hover near 0.75 for plain English.

🔗 Where this is heading

Everything downstream in this course rests on the machinery here. What models can do (Week 3) is the menu of skills that emerge from next-token prediction at scale. Prompting (Weeks 4–5) is the art of steering that predictor — few-shot examples exploit in-context learning; chain-of-thought asks it to spend tokens reasoning before answering. Agents (Weeks 6–7) wrap the same predictor in a loop with tools and memory so it can act, not just talk. And limits and hallucinations (Week 9) trace directly back to one fact from this lecture: the objective rewards plausibility, not truth.

6 questions · click "Show answer" to check yourself.

Q1. A token in a language model is best described as…
A. always exactly one English word
B. a chunk of text (often a word-piece) mapped to an integer ID from a fixed vocabulary
C. a single character, always
D. the model's final answer
Show answer

B. Tokens are sub-word chunks (roughly ¾ of a word in English) each with an integer ID. They are neither strictly words (A) nor strictly characters (C).

Q2. What is an embedding?
A. the loss value during training
B. the probability the model assigns to the next token
C. a learned vector that places a token in a high-dimensional "meaning space"
D. the temperature setting
Show answer

C. Each token ID is looked up as a learned vector; similar tokens land near each other, turning meaning into geometry. The ID itself carries no magnitude meaning.

Q3. The fundamental task a language model is trained on is to…
A. predict the probability of the next token given the preceding ones
B. look up answers in a stored database
C. translate every input into French
D. compress images
Show answer

A. Next-token prediction, scored by cross-entropy loss, is the whole training game. Other abilities emerge from doing it well, not from a database lookup (B).

Q4. Which stage gives a model most of its broad knowledge?
A. RLHF
B. instruction fine-tuning
C. the tokenizer
D. pretraining on a large, broad text corpus
Show answer

D. Pretraining is the compute-heavy stage where knowledge and language ability are acquired. Fine-tuning adds helpfulness; RLHF aligns to preferences.

Q5. RLHF (Reinforcement Learning from Human Feedback) primarily…
A. teaches the model new factual knowledge from scratch
B. shapes responses toward human-preferred behavior (helpful, honest, harmless) using ranked feedback
C. shrinks the model's vocabulary
D. removes the need for tokens
Show answer

B. RLHF trains a reward model from human (or AI) rankings and optimizes the assistant toward preferred responses — tone, refusals, following nuance — not bulk new knowledge.

Q6. A model can produce a fluent, confident statement that is simply false because…
A. it is deliberately lying
B. its training objective rewards plausible next tokens, not verified truth
C. the tokenizer is broken
D. embeddings cannot represent facts
Show answer

B. Plausible-looking wrong text has the same statistical shape as correct text, so the basic objective doesn't forbid it — the root of hallucination (Week 9). Always verify.

✓ What you learned

  • Tokens are sub-word chunks (≈¾ word in English) turned into integer IDs from a fixed vocabulary.
  • Embeddings are learned vectors placing tokens in a meaning space where geometry encodes similarity and relationships.
  • The core task is next-token prediction, scored by cross-entropy loss and run autoregressively (with temperature) to generate text.
  • Models are built in three stages: pretraining (knowledge) → fine-tuning (helpfulness) → RLHF (alignment).
  • They generalize because predicting all of human text forces compression of its underlying structures — but generalization is bounded, and plausibility ≠ truth.
