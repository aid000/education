Prompting I — Clarity, Roles, Few-Shot & Chain-of-Thought

A model can only answer the question you actually asked. The fastest way to get better output is almost never a better model — it's a clearer prompt.

🎯 Learning Objectives

  • Write specific, context-rich prompts and explain why vagueness forces the model to guess.
  • Use role prompting to set audience, tone, and depth.
  • Steer format and style with few-shot examples instead of long instructions.
  • Trigger chain-of-thought reasoning for multi-step problems and know when it helps.
  • Give the model "an out" so it admits uncertainty instead of hallucinating.

4.1Specificity: the Model Fills Every Gap You Leave

Recall from Week 2 that a language model works by repeatedly predicting the most likely next token given everything before it. Your prompt is that "everything before." When the prompt is vague, the model has no way to know what you meant — so it falls back on the most statistically average continuation. Ask "write about dogs" and you get a bland, generic essay, because that is the average of everything the model ever saw about dogs.

A useful prompt narrows the space of likely answers down to the one you want. Four levers do most of the work: task (what to produce), context (background and constraints), audience (who it's for), and format (how the answer should look).

AnalogyPrompting is like briefing a brilliant new freelancer who has read almost everything but has never met you and can't ask follow-up questions. "Make me a logo" gets you a guess. "Make a minimalist wordmark logo for a kids' coding camp called Bitlings, friendly and rounded, in two colors, as an SVG" gets you something usable. The talent is the same — the brief is everything.

4.2Role Prompting: Set the Voice and the Depth

One of the cheapest ways to add context is to tell the model who it should be and who it's talking to. A role steers vocabulary, depth, and assumptions all at once, because it pulls the model toward the region of its training data that matches that role.

"Explain recursion."
vs.
"You are a patient CS tutor. Explain recursion to a 12-year-old
using one everyday analogy, then a 5-line Python example."The role + audience + format do far more than the extra words suggest.

Roles are powerful but not magic. Telling a model "you are a world-class cardiologist" makes it sound more like medical writing; it does not give it new facts or make it safe to rely on for medical decisions. Use roles to shape style and framing, never to manufacture authority the model doesn't actually have.

Common mistakeDon't confuse persona with competence. "Act as a senior security auditor" improves the framing and checklist of an answer, but the model can still miss real vulnerabilities or invent fake ones. A role changes how it answers, not what it knows. Always keep the limits and hallucination caveats from Week 3 in mind.

4.3Few-Shot: Show, Don't Just Tell

Often the easiest way to specify a format is to demonstrate it. A few-shot prompt includes a handful of input→output examples before the real request. The model infers the pattern from the examples and continues it — no rules-lawyering required. (A prompt with zero examples is zero-shot; one example is one-shot.)

This works because next-token prediction is, at heart, pattern continuation. Two or three clean, consistent examples often beat a paragraph of instructions, especially for classification, extraction, and rigid output shapes.

Review: "Loved it, came early!" → Sentiment: positive
Review: "Broke in a week." → Sentiment: negative
Review: "It's fine, nothing special." → Sentiment: ?The model continues the established pattern and answers: neutral.

4.4Chain-of-Thought: Ask for the Work

For anything multi-step — arithmetic, logic puzzles, planning — a model that answers in one shot often guesses wrong, because it's committing to a final token before "thinking." Chain-of-thought (CoT) prompting fixes this by asking the model to reason step by step before giving the answer. The classic trigger is literally adding "Let's think step by step." (introduced by Wei et al. and colleagues around 2022).

Why it works: each reasoning token the model writes becomes part of the context for the next token. Spreading the work across many intermediate steps gives the model more "room" to get each small step right, rather than forcing the whole computation into a single prediction.

Bad: "What's 17 × 24?" → "408" (often wrong)
Good: "What's 17 × 24? Show each step." →
"17 × 24 = 17 × 20 + 17 × 4 = 340 + 68 = 408"Intermediate steps become context that supports the final token.
AnalogyAsking for the answer alone is like demanding a chess player blurt out a move in half a second. Chain-of-thought is "take your time and think out loud." A grandmaster who reasons through the position plays far better than one forced to move instantly — even though it's the same player.

CoT shines on reasoning tasks but adds length and cost, and it is overkill for simple lookups or rewrites. Many newer "reasoning" models do a version of this internally; even so, explicitly asking for steps still helps you see and check the logic — which matters for trust.

4.5Giving the Model an Out

A model trained to be helpful will, by default, try to answer everything — even when it doesn't know. That default is a major source of hallucinations: confident, fluent, wrong. The fix is simple and underused: explicitly permit "I don't know."

Add a sentence like: "If the document doesn't contain the answer, say 'Not stated' rather than guessing." This gives the model an acceptable, low-pressure path that isn't a fabricated answer. Pair it with a request to cite or quote its source, and you make unsupported claims easy to catch.

"Answer ONLY from the text below. If the answer isn't there,
reply exactly: 'Not stated.' Quote the sentence you used."An explicit "out" + a citation requirement sharply reduces confident fabrication.
Note · this never fully removes hallucinationGiving an out reduces made-up answers; it does not eliminate them. Models can still misread a source or cite the wrong line. Treat AI output as a fast, fallible draft — verify anything that matters, exactly as you'll practice in Week 9 (Limits, Hallucinations & Ethics).
✦ Worked Example — rebuilding a weak prompt, one lever at a time

Goal: turn three messy customer emails into a clean status table. Watch each technique from this lecture earn its place.

  1. Start vague: "Summarize these emails." → You get three loose paragraphs in random formats. Unusable for a spreadsheet.
  2. Add specificity + format: "For each email, extract the customer name, the issue, and whether it's resolved. Output a Markdown table with columns Name | Issue | Status." → Now it's tabular, but "Status" wording is inconsistent ("done", "fixed", "pending").
  3. Add a role + audience: "You are a support-ops analyst preparing a daily standup table for a busy manager." → Tone tightens; entries get terse and scannable.
  4. Add few-shot to lock the vocabulary: show one example row whose Status is exactly one of Open / Resolved / Waiting. → Every row now uses only those three labels.
  5. Add an out: "If an email doesn't state whether it's resolved, put 'Open' and add (unclear) — never guess a resolution." → Ambiguous emails stop being silently marked Resolved.
  6. Result: a consistent, trustworthy table from the same model — improved entirely by the prompt, no fine-tuning, no better model. That is the whole point of Prompting I.

🛠️ Hands-On: A/B your prompts and log the wins

You only need a free-tier chat account on any one assistant (Claude, ChatGPT, or Grok all work) and the Jupyter you set up in Week 1 — no new installs. The skill is comparing prompts deliberately, not collecting tools.

Exercise — run the same task four ways in your chat assistant and paste the outputs into a notebook log:

  1. Zero-shot, vague: "Classify this review: It arrived late but works great."
  2. + Specificity/format: add "Reply with only one word: positive, negative, or mixed."
  3. + Few-shot: prepend two labeled example reviews in that exact format.
  4. + Chain-of-thought: "Think step by step about each clause, then give the final label."

Keep a structured prompt log so you can see which lever changed the output. A Jupyter cell makes a tidy record:

# prompt_log.py — Week 4 prompt journal (no API needed; paste outputs by hand)
log = [
    {# 1. baseline
     "technique": "zero-shot",
     "prompt": "Classify this review: It arrived late but works great.",
     "output": "...paste model reply...",
     "good?": False},
    {# 2. add specificity + format constraint
     "technique": "specific+format",
     "prompt": "...one word: positive/negative/mixed...",
     "output": "...",
     "good?": True},
    {# 3. few-shot, 4. chain-of-thought ... add rows the same way},
]

for row in log:
    print(row.get("technique"), "->", row.get("good?"))
# Goal: SEE which lever fixed the output. That habit is the real skill.

Stretch: add a 5th run with "an out" — tell the model to answer "unclear" if a review is genuinely ambiguous — and feed it a deliberately vague review to test it.

🔗 Where this is heading

These five levers — specificity, roles, few-shot, chain-of-thought, and giving an out — are the manual basics. Next week (Prompting II) we scale them up: structured output (JSON/schemas) for feeding other programs, working in long context windows without burying your instructions, self-critique (asking the model to check its own work), and tree-of-thoughts, which explores several reasoning branches instead of one. By Weeks 6–7 these same prompts become the building blocks of agents that reason and act in a loop — so the clarity habits you build now pay off everywhere downstream.

❓ Lecture 4 Quiz

6 questions · click "Show answer" to check yourself.

Q1. Why does a vague prompt like "write about dogs" tend to produce bland output?
A. The model refuses ambiguous prompts
B. With no constraints, the model falls back on the most statistically average continuation
C. Short prompts are always rejected
D. The model can only write about topics in its system prompt
Show answer

B. Your prompt is the context for next-token prediction. Without task, audience, or format constraints, the most likely continuation is the generic average of everything it saw.

Q2. What does role prompting ("You are a patient CS tutor…") actually change?
A. It gives the model new facts it didn't have
B. It makes the model's answers guaranteed correct
C. It shapes style, depth, and framing, not the underlying knowledge
D. It permanently fine-tunes the model
Show answer

C. A persona steers how the model answers — vocabulary, depth, tone — by pulling toward matching training data. It does not add competence or guarantee accuracy.

Q3. A prompt that includes two labeled input→output examples before the real request is called…
A. few-shot prompting
B. zero-shot prompting
C. role prompting
D. retrieval prompting
Show answer

A. A handful of examples = few-shot (zero examples = zero-shot, one = one-shot). The model infers and continues the demonstrated pattern.

Q4. Why does "Let's think step by step" often improve answers to multi-step problems?
A. It switches the model to a faster mode
B. It deletes earlier mistakes from memory
C. It contacts a calculator service
D. Each reasoning token becomes context for the next, giving room to get small steps right
Show answer

D. Chain-of-thought spreads the work across intermediate tokens instead of forcing the whole computation into a single prediction — and lets you check the logic.

Q5. Which prompt addition best reduces confident, made-up answers?
A. "Be as confident as possible."
B. "If the answer isn't in the text, reply 'Not stated' instead of guessing."
C. "Always give a definitive answer."
D. "Make the answer longer."
Show answer

B. Giving the model an explicit "out" — permission to say it doesn't know — provides a low-pressure path that isn't fabrication. It reduces, though never fully removes, hallucination.

Q6. Your customer-status table keeps using inconsistent labels ("done", "fixed", "pending"). Which technique most directly locks the vocabulary to exactly Open / Resolved / Waiting?
A. Raising the temperature setting
B. Adding a longer role description
C. Few-shot — show an example row using only the three allowed labels
D. Asking it to think step by step
Show answer

C. A concrete example demonstrating the exact allowed values is the strongest, simplest way to pin down output format and vocabulary.

✓ What you learned

  • Specificity — task, context, audience, and format each remove a cloud of average answers; the prompt is the model's only brief.
  • Role prompting shapes voice and depth, but not knowledge or correctness.
  • Few-shot examples specify a format by demonstration — usually stronger than prose rules.
  • Chain-of-thought ("think step by step") helps multi-step reasoning and lets you check the work.
  • Giving the model an out ("say 'Not stated'") cuts confident fabrication — but never fully removes hallucination.
