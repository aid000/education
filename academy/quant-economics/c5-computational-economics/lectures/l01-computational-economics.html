Computational Economics: Why & How

The most interesting economic models have no formula you can solve by hand — so we teach the computer to find the answer instead.

🎯 Learning Objectives

  • Explain why most modern economic models have no closed-form solution and must be solved numerically.
  • Walk through the computational modeling workflow: model → discretize → solve → validate → interpret.
  • Describe at a high level how floating-point numbers work and where rounding error comes from.
  • Identify the free core toolkit — NumPy, SciPy, QuantEcon — and what each is for.
  • Write a reproducible numerical experiment by fixing seeds, pinning versions, and recording inputs.

1.1Why Economics Needs Computation

A first economics course teaches you to solve models: take a derivative, set it to zero, and read off the optimum. That works because the models are deliberately simple — linear demand, quadratic cost, a single agent. The moment a model becomes realistic, the clean algebra disappears. Add a borrowing constraint, uncertainty about future income, many heterogeneous households, or a nonlinear policy rule, and there is no formula x = ... waiting at the end.

Consider a household choosing how much to save each year to smooth consumption over an uncertain lifetime. The optimal savings rule must satisfy the Euler equation, which equates the marginal utility of consuming a dollar today with the expected, discounted marginal utility of saving it:

u'(ct) = β · E[ (1 + r) · u'(ct+1) ]The consumption Euler equation: marginal utility now equals discounted expected marginal utility next period. For realistic u and uncertainty, c is implicit — there is no closed form.

For all but a few textbook utility functions, you cannot rearrange this into an explicit consumption function. The unknown is a function (how much to consume at every wealth level), and it appears on both sides inside an expectation. The only way forward is to approximate the function on a grid and let an algorithm iterate until both sides agree. Computational economics is the discipline of turning models like this into numbers — and it is how nearly all frontier macro, finance, and policy analysis is actually done.

AnalogyClosed-form solutions are like finding the exact area of a circle with πr². Numerical methods are like measuring an irregular lake by overlaying a fine grid and counting squares: you never get a tidy formula, but with a fine enough grid you get an answer as accurate as you need. Almost every interesting "lake" in economics has no formula.

1.2The Computational Modeling Workflow

Solving a model on a computer is not a single step — it is a pipeline, and each stage introduces decisions and possible errors you must control. The standard workflow has five stages:

Model writes the economics as equations (objectives, constraints, equilibrium conditions). Discretize replaces continuous objects — a wealth level, a probability distribution, time itself — with finite grids and finite sums the computer can store. Solve runs an algorithm (optimization, root-finding, fixed-point iteration) until it converges. Validate checks that the answer is right: does it satisfy the original equations, is it stable as the grid gets finer? Interpret turns numbers back into economics — plots, comparative statics, policy conclusions.

Common mistakeTreating a converged solver as a correct solution. "Converged" only means the algorithm stopped changing — it can happily converge to a wrong answer if your grid is too coarse, your tolerance too loose, or your equations have a typo. Always validate by checking residuals (how badly the original equation is violated) and by re-running on a finer grid. Skipping validation is the #1 source of silently wrong published results.

1.3Floating-Point Arithmetic & Numerical Error

Computers do not store real numbers. They store floating-point approximations — a fixed number of binary digits, like scientific notation in base 2. The standard double-precision format keeps about 15–16 significant decimal digits. Everything beyond that is rounded away, so each stored number carries a tiny relative error of about 2.2 × 10⁻¹⁶, called machine epsilon:

fl(x) = x · (1 + δ),   |δ| ≤ εmach ≈ 2.2e-16Every real number x is stored as a nearby float; the relative rounding error δ is bounded by machine epsilon. Most of the time this is invisible — but it compounds.

The classic surprise: 0.1 + 0.2 does not equal 0.3 in floating point, because 0.1 has no exact finite binary representation. The result is 0.30000000000000004. This is why you never test a == b for computed floats — you test abs(a - b) < tol for a small tolerance.

Two failure modes dominate practical work. Catastrophic cancellation: subtracting two nearly equal numbers wipes out the significant digits and amplifies the leftover error — a real danger in finite-difference derivatives. Error accumulation: tiny per-step errors compound over millions of iterations. Good numerical code is written to keep these in check (e.g. summing small-to-large, reformulating subtractions, choosing stable algorithms).

AnalogyFloating point is like measuring with a ruler marked only to the millimeter. One measurement is fine. But if you add up ten thousand measurements, the rounding at each mark accumulates into a visible error — and if you subtract two lengths that are almost identical, the millimeter noise can be larger than the true difference itself. Numerical analysis is the craft of keeping the ruler honest.

1.4The Free Toolkit & Reproducible Experiments

The entire course runs on a free, open-source Python stack — no licenses, all installable with one pip command. Each library has a clear job:

  • NumPy — fast arrays and vectorized math. The foundation everything else builds on; loops over arrays become single C-speed operations.
  • SciPy — the numerical workhorse: optimization, root-finding, integration, interpolation, linear algebra, statistics.
  • QuantEcon — economics-specific tools: Markov chains, dynamic programming solvers, and tested implementations of standard models.
  • CVXPY — describe a convex optimization problem in math-like syntax and let a solver handle it (used for portfolio and equilibrium problems later).
  • Matplotlib — plotting, for the Interpret stage.

A numerical result is only science if someone else can reproduce it. Reproducibility rests on three habits: (1) fix the random seed so stochastic simulations repeat exactly; (2) pin library versions so the code behaves the same next year; (3) record every input (parameters, grid sizes, tolerances) alongside the output. A run that cannot be repeated is a number you cannot defend.

Common mistakeForgetting to set the random seed before a Monte Carlo simulation, then reporting a result that changes every run. If your headline number wobbles when you re-run the script, you have a reproducibility bug — not a finding. Set rng = np.random.default_rng(0) once, at the top, and draw all randomness from it.
✦ Worked Example — estimate π with a reproducible Monte Carlo

A classic numerical experiment: throw random darts at the unit square [0,1]×[0,1] and count how many land inside the quarter-circle of radius 1. The fraction inside approximates the quarter-circle's area, π/4, so 4× that fraction estimates π. We do it reproducibly and report the error.

  1. Set the seed: create rng = np.random.default_rng(0) so the experiment repeats exactly. This is step (1) of reproducibility.
  2. Draw points: sample N = 1,000,000 pairs (x, y) uniformly in the unit square.
  3. Test the condition: a point is inside the quarter-circle when x² + y² ≤ 1. Count how many satisfy it — say 785,402.
  4. Estimate: the inside fraction is 785,402 / 1,000,000 = 0.785402, so π ≈ 4 × 0.785402 = 3.141608.
  5. Report the error: the true value is 3.141593, so the absolute error is about 1.5 × 10⁻⁵. Monte Carlo error shrinks like 1/√N, so to gain one more digit you need ~100× more points — a key reason we care about efficient methods later in the course.

🛠️ Hands-On: your first reproducible experiment

This whole specialization uses the free Python scientific stack. Week 1 setup: install it once (below), then reuse it for every lecture and the course project.

⬇ Install Python + NumPy + SciPy + QuantEcon + CVXPY + Matplotlib (one-time, Week 1 setup)

With Python 3 installed, create an isolated environment and install the stack:

python3 -m venv econ-env
source econ-env/bin/activate       # macOS / Linux
econ-env\Scripts\activate          # Windows (PowerShell)
pip install numpy scipy quantecon cvxpy matplotlib jupyter

Verify: run python -c "import numpy, scipy, quantecon, cvxpy; print('ok')" — printing ok means you're set.

Now run the π experiment from the worked example. Note the seed: re-running this script gives the exact same estimate every time — that is reproducibility in action.

# monte_carlo_pi.py — Lecture 1
import numpy as np

rng = np.random.default_rng(0)     # (1) fix the seed -> repeatable
N = 1_000_000

xy = rng.random((N, 2))            # N points in the unit square
inside = (xy[:, 0]**2 + xy[:, 1]**2) <= 1.0
pi_est = 4 * inside.mean()         # 4 x (fraction inside quarter-circle)

print(f"pi estimate = {pi_est:.6f}")
print(f"abs error   = {abs(pi_est - np.pi):.2e}")

# floating-point reality check:
print(0.1 + 0.2 == 0.3)            # False!
print(abs((0.1 + 0.2) - 0.3) < 1e-12)   # True -- compare with a tolerance

Try bumping N to 100,000,000 and watch the error fall by roughly 10× (the 1/√N rate). Then change the seed and confirm the estimate moves — proof that the seed is what locks the run down.

5 questions · click "Show answer" to check yourself.

Q1. Why do most realistic economic models require numerical (computational) solution?
A. Economists are not good at algebra
B. They have no closed-form solution — the unknown is often an implicit function
C. Computers are always faster than algebra
D. Numerical answers are always exact
Show answer

B. Once you add constraints, uncertainty, or heterogeneity, there is no formula to solve — e.g. the Euler equation defines consumption implicitly. A is dismissive and false; C is irrelevant (speed isn't the reason); D is the opposite of true — numerical answers are approximate.

Q2. In the five-stage workflow, what does the "Discretize" stage do?
A. Turns numbers back into economic conclusions and plots
B. Writes the economics as equations and constraints
C. Replaces continuous objects with finite grids and sums the computer can store
D. Checks that the solution satisfies the original equations
Show answer

C. Discretization swaps continuous wealth levels, distributions, or time for finite grids. A is the Interpret stage; B is the Model stage; D is the Validate stage.

Q3. Why does 0.1 + 0.2 == 0.3 evaluate to False in Python?
A. Python rounds all numbers up
B. 0.1, 0.2, and 0.3 have no exact finite binary representation, so tiny rounding errors remain
C. Python uses base-10 internally and miscounts
D. Addition is not defined for floats
Show answer

B. These decimals are infinite repeating fractions in binary, so they're stored as nearby approximations and the sum is off by ~1e-16. A is false (it rounds to nearest, not up); C is false (floats are base 2); D is nonsense.

Q4. A colleague says "my solver converged, so the answer is correct." The best response is:
A. Convergence only means the algorithm stopped changing; you must still validate residuals and refine the grid
B. Correct — convergence guarantees the true solution
C. Convergence is impossible in floating point, so the claim is meaningless
D. Only QuantEcon solvers can converge correctly
Show answer

A. A solver can converge to a wrong answer on a coarse grid or with a buggy equation, so you validate independently. B is the dangerous myth this lecture warns against; C is false (algorithms converge routinely); D is made up.

Q5. Which single step most directly makes a Monte Carlo simulation reproducible?
A. Using more sample points
B. Plotting the result with Matplotlib
C. Switching from NumPy to SciPy
D. Fixing the random seed (e.g. np.random.default_rng(0))
Show answer

D. A fixed seed makes the pseudo-random draws repeat exactly, so the run is identical every time. A reduces error but not run-to-run variation; B and C affect output/speed, not reproducibility of the randomness.

✓ What you learned

  • Most realistic models have no closed-form solution, so we approximate them numerically.
  • The computational workflow is model → discretize → solve → validate → interpret, with validation looping back.
  • Computers use floating-point arithmetic, so rounding error, cancellation, and accumulation are real and must be managed.
  • The free toolkit — NumPy, SciPy, QuantEcon, CVXPY, Matplotlib — covers arrays, numerics, economics, optimization, and plots.
  • A result is only science if it's reproducible: fix seeds, pin versions, record inputs.
