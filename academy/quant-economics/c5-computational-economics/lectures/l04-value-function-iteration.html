Value Function Iteration

When you can't solve the Bellman equation by hand, you let a computer chase its fixed point — one sweep over the state space at a time.

🎯 Learning Objectives

  • Explain why most dynamic programs have no closed-form value function and must be solved numerically.
  • Discretize a continuous state space into a finite grid and evaluate the Bellman operator on it.
  • State why the Bellman operator is a contraction mapping and how that guarantees convergence.
  • Implement value function iteration (VFI) from scratch in NumPy and extract the optimal policy.
  • Use QuantEcon helpers to set up grids and discretize shocks, and benchmark VFI's accuracy and speed.

4.1Why We Iterate

Last week you met the Bellman equation: the value of being in state s equals the best immediate reward plus the discounted value of where you land next. For a saver choosing how much capital k to carry forward, with consumption c = available resources minus saving, it reads:

V(k) = max over k' of [ u(c) + β V(k') ],  c = f(k) - k'V is the value function; u is utility; β in (0,1) is the discount factor; k' is next period's capital.

The trouble is that V appears on both sides. Except for a handful of lucky functional forms (log utility with Cobb-Douglas production is the famous one — Week 5), there is no formula for V you can write down. So we do the next best thing: we treat the equation as a fixed-point problem and solve it the way you'd solve x = cos(x) — by repeated substitution. Guess a value function, plug it into the right-hand side, and read off an updated value function on the left. Repeat until the guess stops changing.

That loop is value function iteration. Each pass is one application of the Bellman operator T, which takes a candidate value function and returns an improved one:

(T V)(k) = max over k' of [ u(f(k) - k') + β V(k') ]T maps functions to functions. A fixed point of T — a V with T V = V — solves the Bellman equation.

VFI is the workhorse behind quantitative models of saving, investment, job search, optimal stopping, inventory control, and dynamic pricing. Whenever an economist asks "how should an agent behave over time facing uncertainty?", VFI is usually the first numerical tool they reach for.

4.2Discretizing the State Space

A computer can't store a function defined on a continuum of capital levels. So we replace the continuous state with a finite grid of representative points, say N = 200 values of k from a low to a high bound. The value function becomes an array V[i] — one number per grid point — and the operator T becomes a loop over that array.

For each grid point k[i], evaluating (T V)[i] means searching over the same grid for the best choice of next capital k[j]:

(T V)[i] = max over j of [ u(f(k[i]) - k[j]) + β V[j] ]The inner max ranges over feasible j (those with f(k[i]) - k[j] > 0); the argmax j is the policy.

The figure shows one such sweep: at a fixed current state, we scan every candidate next-state, score it, and keep the winner.

Common mistakeDon't make the grid too coarse to "save time." With only 20 points, the policy can only ever pick one of 20 savings levels, so the recovered policy looks like a staircase and the value function is biased. The fix is a denser grid (or interpolating V between grid points). Conversely, an absurdly fine grid wastes effort because VFI cost grows like N² per iteration — every state searches over every candidate.

4.3Why Iteration Converges: The Contraction Mapping

Why should hammering the same operator over and over settle down? Because T is a contraction mapping. Measure the distance between two value functions by their largest pointwise gap, the sup-norm. The key fact is that applying T shrinks that gap by a factor of exactly β:

|| T V - T W || ≤ β · || V - W ||,   0 < β < 1Blackwell's sufficient conditions (monotonicity + discounting) guarantee this for the Bellman operator.

This is the discrete-time cousin of a result you've seen: a map that pulls points closer together has exactly one fixed point, and you reach it from any starting guess. So VFI converges to the unique solution V* no matter where you begin — even from V = 0. Better still, convergence is geometric: the error after n iterations is bounded by βⁿ times the initial error.

|| V_n - V* || ≤ βⁿ · || V_0 - V* ||Each iteration multiplies the remaining error by β. Smaller β (more impatience) means faster convergence.
AnalogyThink of focusing a camera that auto-corrects toward sharp. Each tap of the focus ring moves you a fixed fraction of the way to perfectly crisp, never overshooting. After enough taps the image is indistinguishable from sharp — and it didn't matter how blurry you started. The discount factor β is "what fraction of the remaining error each tap removes"; T is the tap.

4.4From Value to Policy

VFI gives you the value function V*, but for forecasting and simulation you usually want the policy function — the rule that says, in each state, what the agent actually does. The policy is just the argmax that the Bellman operator computes on its final sweep:

σ*(k) = argmax over k' of [ u(f(k) - k') + β V*(k') ]σ* maps each state to the optimal next-state (here, optimal capital to carry forward).

Because V* is the fixed point, one more pass of T while recording the argmax yields the optimal policy. Once you have σ*, you can simulate: start at some k₀, apply k₁ = σ*(k₀), then k₂ = σ*(k₁), and watch the economy converge to its steady state. That simulated path is what economists actually compare against data.

A practical note on stopping: don't iterate forever. Halt when successive value functions barely move — when the sup-norm of the change drops below a tolerance such as 10⁻₆. The contraction bound even lets you translate that gap into a guaranteed bound on distance to the true V*.

stop when  max over i of | V_{n+1}[i] - V_n[i] |  <  tolA standard convergence criterion. The error in V* is then at most tol · β / (1 - β).
✦ Worked Example — one VFI iteration by hand

Take a tiny cake-eating problem with a 3-point grid of remaining cake k ∈ {0, 1, 2}, utility u(c) = c (linear, just for arithmetic), feasibility c = k - k' ≥ 0, and discount β = 0.9. Start from V₀ = (0, 0, 0). Compute one application of T at each state.

  1. State k = 0: the only feasible k' is 0, giving c = 0. Score = u(0) + 0.9·V₀[0] = 0 + 0 = 0. So (TV₀)[0] = 0, policy k' = 0.
  2. State k = 1: feasible k' ∈ {0,1}. Choosing k'=0 gives c=1, score = 1 + 0.9·0 = 1; choosing k'=1 gives c=0, score = 0. Max is 1; policy k' = 0.
  3. State k = 2: feasible k' ∈ {0,1,2}. k'=0 gives c=2, score = 2; k'=1 gives c=1, score = 1; k'=2 gives 0. Max is 2; policy k' = 0.
  4. After one sweep: V₁ = (0, 1, 2). The value rose because the operator finally "saw" the rewards from eating cake.
  5. Iterate again: now continuation values are nonzero. At k=2, eating all now scores 2, but eating 1 now and saving 1 scores 1 + 0.9·V₁[1] = 1 + 0.9 = 1.9 < 2 — so with linear utility and β<1, eating sooner still wins. With concave utility the smoothing motive would kick in and the policy would spread consumption out. Repeating T drives V toward the fixed point V* = (0, 1, 2) here, where it stops changing.

🛠️ Hands-On: VFI from scratch + QuantEcon helpers

We use the free course stack — Python + NumPy + QuantEcon (plus Matplotlib to plot). The full one-time install lives in the Week 1/Week 2 setup lecture (a pip install quantecon numpy scipy matplotlib in a virtual environment); reuse that environment here — no new tools are introduced this week.

We solve an optimal-growth model with log utility u(c)=log c and Cobb-Douglas production f(k)=kα. QuantEcon's helpers give us a clean log-spaced grid; the rest is a plain NumPy fixed-point loop.

# vfi_growth.py — Lecture 4: value function iteration from scratch
import numpy as np
import quantecon as qe

alpha, beta = 0.4, 0.96         # capital share, discount factor
grid = np.linspace(1e-4, 8.0, 300)   # discretized capital state

def f(k):                        # production function
    return k ** alpha

def bellman_operator(V):
    TV  = np.empty_like(V)
    pol = np.empty_like(V)
    for i, k in enumerate(grid):
        c = f(k) - grid                       # consumption for each k' choice
        feasible = c > 0                       # can't consume negative
        value = np.full_like(grid, -np.inf)
        value[feasible] = np.log(c[feasible]) + beta * V[feasible]
        j = np.argmax(value)                  # best next-capital index
        TV[i], pol[i] = value[j], grid[j]
    return TV, pol

# iterate the contraction to its fixed point
V = np.zeros_like(grid)
for it in range(1000):
    TV, policy = bellman_operator(V)
    err = np.max(np.abs(TV - V))              # sup-norm change
    V = TV
    if err < 1e-6:                            # converged
        print(f"converged in {it} iterations, error={err:.2e}")
        break

# policy[i] is optimal capital to save when current capital is grid[i]

Run it and you should converge in a few hundred iterations. QuantEcon also ships a polished optimal_growth example and a compute_fixed_point driver — swap in qe.compute_fixed_point(bellman_operator, V) to get the same answer with built-in tolerance handling. ❓ Lecture 4 Quiz

5 questions · click "Show answer" to check yourself.

Q1. Why must most dynamic programs be solved by value function iteration rather than algebra?
A. Because computers are faster than humans at addition
B. Because the value function appears on both sides of the Bellman equation and rarely has a closed form
C. Because the discount factor is always unknown
D. Because utility functions are never differentiable
Show answer

B. V is defined implicitly in terms of itself, so except for special forms there is no formula — we solve the fixed point numerically. A confuses speed with necessity; C is false (we set β); D is false (utility is usually smooth).

Q2. What does "discretizing the state space" mean in VFI?
A. Rounding all payoffs to whole numbers
B. Removing the discount factor from the model
C. Replacing the continuous state with a finite grid of representative points
D. Converting utility into a probability distribution
Show answer

C. A computer stores V as a finite array, so we sample the continuum at grid points. A confuses the state with payoffs; B and D are unrelated to discretization.

Q3. The Bellman operator T is a contraction with modulus β. What does that guarantee?
A. A unique fixed point reached from any starting guess, with geometrically shrinking error
B. That T has many fixed points depending on the initial guess
C. That convergence requires β > 1
D. That the value function must be linear
Show answer

A. A contraction (0<β<1) has a unique fixed point and iterates converge geometrically from anywhere. B contradicts uniqueness; C is backwards — β<1 is what makes it a contraction; D is unrelated.

Q4. A standard rule for stopping VFI is to halt when…
A. the policy first becomes positive
B. exactly 100 iterations have run
C. consumption equals capital
D. the sup-norm change between successive value functions falls below a tolerance
Show answer

D. We stop when V stops moving, i.e. max|V_{n+1}-V_n| < tol; the contraction bound then bounds the distance to V*. A fixed iteration count (B) ignores actual convergence; A and C are not convergence criteria.

Q5. Once VFI has converged to V*, how do you obtain the optimal policy function?
A. Take the derivative of V* with respect to β
B. Average V* across all grid points
C. Record the argmax over next-states on a final application of the Bellman operator
D. Invert the value-function array
Show answer

C. The policy is the maximizing choice in the Bellman update; one extra sweep over V* recording argmax gives σ*. A, B, and D are arbitrary operations with no decision-theoretic meaning.
