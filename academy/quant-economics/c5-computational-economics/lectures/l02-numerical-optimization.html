Numerical Optimization for Economics

Most economic models end in "maximize this, subject to that" — and when the algebra runs out, the computer climbs the hill for you.

🎯 Learning Objectives

  • Explain why economics is full of optimization problems and when we must solve them numerically rather than by hand.
  • Build intuition for gradient descent and Newton's method as two ways of "climbing the hill" of an objective function.
  • Use scipy.optimize.minimize to solve an unconstrained problem and read its output.
  • Set up a constrained problem with the Lagrangian and the first-order conditions.
  • Solve a consumer's utility-maximization problem numerically and check it against the analytical answer.

2.1Why Economics Is an Optimization Machine

Almost every actor in an economic model is solving a maximization or minimization problem. A consumer maximizes utility subject to a budget. A firm maximizes profit, or equivalently minimizes cost for a target output. An econometrician minimizes a sum of squared residuals to fit a model. A central planner maximizes welfare. The unifying mathematical object is:

maxx f(x)  or  minx f(x)f is the objective (utility, profit, negative loss); x is the choice variable (a bundle, a price, a parameter vector).

In your calculus courses you solved these by hand: take the derivative, set it to zero, solve. That works for textbook functions. But real models have objectives with no closed-form solution — a likelihood with dozens of parameters, a utility function with frictions, an equilibrium condition you can only evaluate by running code. When the algebra runs out, we hand the problem to a numerical optimizer: an algorithm that starts from a guess and iteratively improves it until it finds the peak (or valley).

Note one convention that trips everyone up: optimizers are written to minimize. To maximize f(x) you minimize -f(x). The peak of utility is the valley of negative utility — same point, flipped sign.

AnalogyThink of the objective function as a foggy mountain landscape and you are a hiker who can only see the ground right under your feet. You can't see the summit. But you can feel which way the slope tilts. A numerical optimizer is a strategy for repeatedly stepping uphill using only local slope information — never needing a map of the whole mountain.

2.2Climbing the Hill: Gradient Descent & Newton's Method

Consider minimizing a smooth function f(x). At any point, the gradient ∇f (the vector of partial derivatives) points in the direction of steepest increase. So to go downhill, we step in the opposite direction. That is gradient descent:

x_(k+1) = x_k - alpha * ∇f(x_k)Step from the current point against the gradient. alpha > 0 is the learning rate (step size).

The step size alpha matters enormously. Too small and you crawl toward the minimum over thousands of iterations; too large and you overshoot and bounce, possibly diverging. Gradient descent uses only first-derivative information, so it knows the direction down but nothing about how the slope is changing.

Newton's method is smarter: it also uses the second derivative — the Hessian H (the matrix of second partials), which measures curvature. It models the function locally as a parabola and jumps straight to that parabola's minimum:

x_(k+1) = x_k - H(x_k)^(-1) * ∇f(x_k)The Hessian inverse rescales the step by curvature, so no manual learning rate is needed.

Because it uses curvature, Newton's method converges quadratically near a minimum — roughly doubling the number of correct digits each step — while gradient descent typically converges linearly. The catch: you must compute and invert the Hessian, which is expensive for high-dimensional problems and can misbehave if the function is far from quadratic. Real solvers (like BFGS) split the difference: they approximate the Hessian from the gradients they've already seen, getting Newton-like speed without the cost.

Common mistakeNumerical optimizers find a local optimum — the nearest valley to where you started, not necessarily the deepest one. If your objective has multiple humps (non-convex), the answer can depend on your starting guess. For convex problems (a single bowl, like the figure) any local minimum is the global minimum, which is why economists work hard to write models in convex form. When in doubt, restart the optimizer from several initial points and compare.

2.3scipy.optimize: Your Workhorse Solver

You will almost never code gradient descent by hand. The free SciPy library bundles battle-tested optimizers behind one function, scipy.optimize.minimize. You hand it: an objective function, a starting guess x0, and (optionally) a method, the gradient, and constraints. It hands back the minimizing x, the objective value there, and convergence diagnostics.

result = minimize(f, x0, method='BFGS')BFGS is a quasi-Newton method: it approximates the Hessian from observed gradients — fast and the sensible default for smooth, unconstrained problems.

Picking a method is mostly about the problem's structure. BFGS for smooth unconstrained problems; Nelder-Mead (a derivative-free "simplex" search) when you can't compute gradients or the function is noisy; L-BFGS-B when variables have simple bounds; and SLSQP when you have equality or inequality constraints (Section 2.4). Always check result.success and result.message — a returned number is meaningless if the solver never actually converged.

2.4Constrained Optimization & the Lagrangian

Economic choices are rarely free — they come with a constraint. A consumer can't spend more than their income; a firm has a production capacity. The canonical problem is:

maxx f(x)  subject to  g(x) = 0f is the objective (utility); g(x) = 0 is the constraint (e.g. you spend exactly your budget).

The trick, due to Lagrange, is to fold the constraint into a single new objective by adding it back with a multiplier lambda:

L(x, lambda) = f(x) + lambda * g(x)The Lagrangian. The multiplier lambda is the new variable that enforces the constraint.

Setting all the partial derivatives of L to zero gives the first-order conditions. The condition ∂L/∂lambda = 0 just re-states the constraint g(x) = 0, while the ∂L/∂x conditions say the gradient of the objective must line up with the gradient of the constraint. Geometrically: at the optimum, the highest indifference curve you can reach just touches the budget line — they are tangent.

AnalogyThe multiplier lambda is not just bookkeeping — it has an economic meaning. It is the shadow price of the constraint: how much your maximum objective would rise if the constraint loosened by one unit. In a budget problem, lambda is the marginal utility of income — the extra happiness one more dollar would buy. That is why Lagrange multipliers show up everywhere from consumer theory to the pricing of resources.

Numerically, you don't have to form the Lagrangian yourself. You pass the objective and the constraint separately to a constrained solver — SLSQP in SciPy, or a convex solver like CVXPY for problems you can write in convex form — and the algorithm handles the multiplier internally. CVXPY is especially nice: you declare variables, write the objective and constraints almost like math, and it certifies a global optimum for convex problems.

Common mistakeMixing up the sign or the direction of the inequality. An optimizer minimizes, so to maximize utility you minimize negative utility — but the constraint itself does not get its sign flipped. And "spend at most your income" (p·x ≤ m) is an inequality; with monotone preferences (more is better) it binds with equality, but writing it as a strict equality when the optimum is interior can make the solver fail. Match the constraint type to the economics.
✦ Worked Example — maximize Cobb-Douglas utility on a budget

A consumer has utility U(x, y) = x0.5 y0.5 over two goods. Prices are px = 2, py = 4, and income m = 100. Find the optimal bundle by hand, then we'll confirm it in code.

  1. Set up the Lagrangian: L = x0.5y0.5 + lambda·(100 − 2x − 4y).
  2. First-order conditions: ∂L/∂x = 0.5·x−0.5y0.5 − 2·lambda = 0 and ∂L/∂y = 0.5·x0.5y−0.5 − 4·lambda = 0.
  3. Take the ratio (divide the two conditions) to cancel lambda: (y / x) = 2/4, so y = x/2. The marginal-rate-of-substitution equals the price ratio.
  4. Plug into the budget 2x + 4y = 100: 2x + 4(x/2) = 2x + 2x = 4x = 100, so x* = 25.
  5. Back out y: y* = 25/2 = 12.5. Utility = 250.5·12.50.5 = √312.5 ≈ 17.68.
  6. Sanity check: for Cobb-Douglas with equal exponents, each good takes half of income — spend 50 on x (50/2 = 25 units) and 50 on y (50/4 = 12.5 units). It matches. The shadow price lambda = 0.5·x−0.5y0.5/2 ≈ 0.0884 utils per dollar.

🛠️ Hands-On: solve it with SciPy & CVXPY

Verify: run python -c "import scipy, cvxpy, quantecon; print('ok')" — printing ok means you're set.

First, the unconstrained-style approach: we substitute the budget into the objective and minimize negative utility with SciPy's constrained solver, then double-check with CVXPY.

# utility_max.py — Lecture 2
import numpy as np
from scipy.optimize import minimize

px, py, m = 2.0, 4.0, 100.0

# maximize U = x^.5 * y^.5  ==> minimize -U
def neg_util(z):
    x, y = z
    return -(x**0.5 * y**0.5)

# budget: px*x + py*y <= m  (SLSQP wants g(z) >= 0)
budget = {'type': 'ineq', 'fun': lambda z: m - px*z[0] - py*z[1]}
bounds = [(1e-6, None), (1e-6, None)]   # goods must be positive

res = minimize(neg_util, x0=[10, 10], method='SLSQP',
               bounds=bounds, constraints=[budget])

print(res.success, res.message)
print("x*, y* =", res.x.round(3))       # -> [25.    12.5]
print("U* =", round(-res.fun, 3))       # -> 17.678

Cobb-Douglas in log form is concave, so the problem is convex once we maximize log-utility. CVXPY can then certify the global optimum:

# same problem, convex form with CVXPY
import cvxpy as cp

x = cp.Variable(pos=True)
y = cp.Variable(pos=True)
# maximize 0.5*log(x) + 0.5*log(y)  (monotone transform of U)
objective = cp.Maximize(0.5*cp.log(x) + 0.5*cp.log(y))
constraints = [px*x + py*y <= m]

prob = cp.Problem(objective, constraints)
prob.solve()
print("x*, y* =", round(x.value, 3), round(y.value, 3))   # -> 25.0 12.5
print("shadow price lambda =", round(constraints[0].dual_value, 4))

Both solvers return (25, 12.5), matching the hand calculation. CVXPY's dual_value on the budget constraint is the Lagrange multiplier — the marginal utility of income. Now change m to 200 and watch the bundle double; change the exponents to 0.7 and 0.3 and watch spending shift toward good x.

🔗 Where this is heading

Optimization is the engine under almost everything that follows. Next week's dynamic programming (the Bellman equation) is optimization stretched across time — you'll maximize over an entire path of choices, solving a small optimization at every state. When you fit models to data later in the track, maximum-likelihood and GMM estimation are just minimize calls on a cleverly chosen objective. And the constrained-solver machinery here reappears in portfolio optimization in the Quant Finance track, where you maximize expected return subject to a risk budget — the very same Lagrangian, with money instead of utility.

5 questions · click "Show answer" to check yourself.

Q1. To maximize a function f(x) using an optimizer that only minimizes, you should minimize…
A. 1/f(x)
B. −f(x)
C. f(x)²
D. |f(x)|
Show answer

B. The minimum of −f(x) occurs at the same x as the maximum of f(x). 1/f (A) and f² (C) change where the extremum sits and break for f ≤ 0; |f| (D) does too.

Q2. The key difference between Newton's method and plain gradient descent is that Newton's method…
A. never needs a starting guess
B. always finds the global minimum
C. uses second-derivative (curvature) information via the Hessian
D. works only on linear functions
Show answer

C. Newton's method scales the step by the inverse Hessian, giving fast quadratic convergence near a minimum. It still needs a starting guess (A) and still only finds a local optimum (B); it's used precisely on nonlinear functions (D).

Q3. A numerical optimizer started from one initial guess returns a minimum. The biggest caveat is that…
A. the result is only a local optimum unless the problem is convex
B. it is always the global optimum
C. it ignores the objective function entirely
D. the step size has no effect on the answer
Show answer

A. Local methods find the nearest valley to the start point; only convexity guarantees it's also global (B is false in general). The optimizer obviously uses the objective (C), and step size strongly affects convergence (D).

Q4. In the Lagrangian L = f(x) + lambda·g(x), the multiplier lambda is best interpreted economically as…
A. the total value of the objective at the optimum
B. the number of constraints
C. the shadow price — how much the optimal objective rises if the constraint loosens by one unit
D. the starting guess for the optimizer
Show answer

C. lambda is the marginal value of relaxing the constraint (e.g. the marginal utility of income). It is not the objective level (A), a count (B), or an initial guess (D).

Q5. For a smooth, unconstrained minimization where you can't easily compute the Hessian, the sensible default SciPy method is…
A. Nelder-Mead, because it's derivative-free
B. linear programming
C. a fixed grid search over all points
D. BFGS, a quasi-Newton method that approximates the Hessian from gradients
Show answer

D. BFGS gets Newton-like speed without forming the true Hessian — the standard default for smooth unconstrained problems. Nelder-Mead (A) is for noisy/non-differentiable objectives and is slower; LP (B) needs a linear problem; grid search (C) is hopeless in more than a few dimensions.
