10.1What "Logical Error Rate Below Physical" Actually Means

Every previous lecture built one piece of this picture: Lecture 4 built the code, Lecture 7 told you when scaling a code should help, Lecture 8 gave you the real noise numbers to test it against. This lecture closes the loop by actually running the comparison: for a given physical error rate p per qubit, does the repetition code's logical error rate — the probability the 3-qubit block ends up decoded wrong after majority vote — come out lower than p itself?

P_logical ≈ 3p²(1−p) + p³    (fails only if ≥2 of 3 qubits flip)From Lecture 4 §4.4 — this is the exact quantity you'll now measure empirically rather than just derive.

The theoretical formula assumes each of the 3 data qubits independently has probability p of flipping during storage (the idle time between a perfect, noiseless encode and a perfect, noiseless syndrome extraction + correction) — a simplification of Lecture 8's full gate-noise picture, but the right simplification to actually test this specific formula against simulation. Running a real Aer noise model that injects exactly that — a probability-p bit-flip on each data qubit's idle period, nothing else — tests whether the simplified theory survives contact with a real stochastic simulator. (Adding gate noise to the encode/syndrome/correction circuitry itself, on top of this idle noise, is a natural extension if you want to push further — Lecture 8's full thermal-relaxation-plus-depolarizing model is exactly what you'd reach for.)

10.2Guided Walkthrough: Repetition Code Meets Realistic Noise

The plan: build the full Week-4 circuit (encode → syndrome → correct), add an explicit idle period on the 3 data qubits between encode and syndrome extraction, attach a bit-flip noise channel to only that idle period, sweep the noise strength across several values, and plot logical vs. physical error rate on the same axes — reproducing Lecture 7's conceptual Fig 7.1, now with real simulated data instead of a cartoon curve.

🛠️ Hands-On: logical vs. physical error rate sweep

Build the full encode/syndrome/correct circuit from Lecture 4, add an explicit idle step on the 3 data qubits right after encoding, attach a bit-flip noise channel to only that idle step (treating encode/syndrome/correction as fast and effectively noiseless by comparison — the standard simplifying assumption for a first pass), sweep the per-qubit idle flip probability, and compare the logical failure rate against the raw physical rate.

# capstone_repetition_under_noise.py — Lecture 10
from qiskit import QuantumCircuit
from qiskit_aer import AerSimulator
from qiskit_aer.noise import NoiseModel, pauli_error

def repetition_circuit():
    qc = QuantumCircuit(5, 5)         # 5 qubits (q0,q1,q2 data; q3,q4 ancilla), 5 classical bits (2 syndrome + 3 data)
    creg = qc.cregs[0]
    qc.x(0)                           # logical |1>_L -- a definite target to check against
    qc.cx(0, 1); qc.cx(0, 2)          # encode: |111>
    qc.id(0); qc.id(1); qc.id(2)      # idle/storage period -- this is where the noise model below injects flips
    qc.cx(0, 3); qc.cx(1, 3)          # syndrome S1 = Z0 Z1 -> ancilla q3
    qc.cx(1, 4); qc.cx(2, 4)          # syndrome S2 = Z1 Z2 -> ancilla q4
    qc.measure(3, 0); qc.measure(4, 1)   # c[0]=S1, c[1]=S2 -- the other 3 bits are still 0 here
    # syndrome-conditioned correction, BEFORE any measurement/sim.run() of the final state --
    # Qiskit 2.0 removed .c_if(), so this uses the control-flow builder instead (see Lecture 4 for the same pattern)
    with qc.if_test((creg, 1)):       # c=1 -> only S1 tripped -> error isolated to q0
        qc.x(0)
    with qc.if_test((creg, 3)):       # c=3 -> both tripped -> error on q1 (shared by S1 and S2)
        qc.x(1)
    with qc.if_test((creg, 2)):       # c=2 -> only S2 tripped -> error isolated to q2
        qc.x(2)
    qc.measure(0, 2); qc.measure(1, 3); qc.measure(2, 4)   # read out corrected data qubits into c[2..4]
    return qc

def majority_vote(bits3):
    return '1' if bits3.count('1') >= 2 else '0'

def run_sweep(p_values, shots=20000):
    results = {}
    for p in p_values:
        nm = NoiseModel()
        idle_flip = pauli_error([('X', p), ('I', 1 - p)])   # exactly the theory's assumption: P(flip)=p per idle qubit
        nm.add_all_qubit_quantum_error(idle_flip, ['id'])    # noise ONLY on the idle gates -- encode/syndrome/correct stay ideal
        sim = AerSimulator(noise_model=nm)
        qc = repetition_circuit()
        counts = sim.run(qc, shots=shots).result().get_counts()
        logical_fails = 0
        for bitstring, n in counts.items():
            data_bits = bitstring[:3]            # leftmost 3 chars = c[4]c[3]c[2] = q2,q1,q0's corrected readout
            if majority_vote(data_bits) != '1':  # target was logical |1>; order doesn't matter for a vote
                logical_fails += n
        results[p] = logical_fails / shots
    return results

p_values = [0.01, 0.05, 0.1, 0.2, 0.3, 0.4, 0.45, 0.5, 0.55, 0.6]
logical_rates = run_sweep(p_values)
for p, p_logical in logical_rates.items():
    print(f"physical p={p:.2f}   logical error rate={p_logical:.3f}   "
          f"{'code wins' if p_logical < p else 'code loses'}")

At small p you should see "code wins" — the logical rate sitting below the physical rate, matching Lecture 4's 3p²(1−p)+p³ prediction closely (because the idle-only noise model above is exactly what that formula assumes: one independent flip chance per data qubit, with everything else ideal). The break-even is exact algebra, not a simulation artifact: 3p²(1−p)+p³ < p rearranges to (2p−1)(p−1) > 0, which holds for p < 0.5 — so the sweep above is built to straddle p=0.5 and you should watch "code wins" flip to "code loses" right around there, reproducing Fig 10.1's crossover directly from your own simulation. That break-even is still far above the realistic gate-error thresholds (10⁻³–10⁻²) Lecture 7 quoted for genuinely scalable codes — this idealized, gate-noise-free version of the repetition code is an optimistic best case, and even it is a much weaker code than something like the surface code.

10.3Connecting Back to the Threshold Theorem

The crossover you just measured is a small, concrete instance of Lecture 7's big idea: a code only helps below some break-even noise level, and makes things worse above it. The repetition code's own break-even point is far higher than the realistic gate-error thresholds (10⁻³–10⁻²) Lecture 7 quoted for genuinely scalable codes like the surface code — which is exactly why real fault-tolerant architectures use codes like the surface code rather than the repetition code for production use. The repetition code was always this course's teaching example — simple enough to fully simulate on a laptop in one sitting, while still showing every qualitative feature (syndrome extraction, correction, a break-even crossover) that the production-grade codes share.

📚 Course Recap — the Full 10-Week Arc

  1. Weeks 1–3 (the problem): real qubits are open systems, not closed ones — decoherence (T1/T2), the Kraus-operator picture of noise channels (bit-flip, phase-flip, depolarizing), and why repeated noise compounds fidelity loss until it's unusable.
  2. Weeks 4–6 (the first fix): the repetition code shows redundancy can detect and correct bit-flip errors without collapsing the encoded state; the stabilizer formalism gives that idea a precise, generalizable language; the surface code extends it to catch bit-flip and phase-flip at once.
  3. Week 7 (the promise): the threshold theorem — below a critical physical error rate, scaling a code suppresses logical error arbitrarily low, which is why fault-tolerant quantum computing is believed possible in principle.
  4. Weeks 8–9 (the reality, and the pragmatic answer): today's hardware numbers sit close to, but not safely below, threshold at scale — so error mitigation (zero-noise extrapolation, readout correction) offers a near-term, no-extra-qubits alternative that doesn't scale forever but helps right now.
  5. Week 10 (closing the loop): you simulated the repetition code under realistic noise end to end and watched the logical-vs-physical crossover appear directly in your own data — the same qualitative story the whole course has been telling, now verified on your own machine.
