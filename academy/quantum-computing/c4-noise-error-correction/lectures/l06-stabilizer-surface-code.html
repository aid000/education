Stabilizer Formalism II: The Surface Code

The repetition code catches bit flips and nothing else. The surface code catches both bit flips and phase flips at once — by arranging qubits on a 2D grid instead of a line.

🎯 Learning Objectives

  • Explain why a code needs both X-type and Z-type stabilizers to catch both bit-flip and phase-flip errors.
  • Describe the surface code's layout: data qubits on a 2D lattice, stabilizers on plaquettes (faces) and vertices.
  • Identify which stabilizer type (X-type or Z-type) detects which error type (Z or X) and why.
  • Describe, qualitatively, the trade-off between lattice size (physical qubits) and logical error rate.
  • Read a small surface-code patch's stabilizer generators as Pauli strings.

6.1The Gap the Repetition Code Left Open

Lecture 4 built a code that handles bit-flip (X) errors well but is completely blind to phase-flip (Z) errors — its stabilizers (Z₁Z₂, Z₂Z₃, from Lecture 5) are built entirely out of Z operators, so they only ever detect disagreements that a Z error would never cause. You could build a mirror-image code with X-type stabilizers that catches phase flips but goes blind to bit flips — but real noise (recall Lecture 2's depolarizing channel) can do both. You need a single code that watches for both at once.

6.2The Surface Code: Data Qubits on a 2D Lattice

The surface code solves this by moving from a 1D line of qubits to a 2D grid. Data qubits sit on the edges of the lattice; each interior vertex hosts a Z-type stabilizer (the product of Z on all edges touching that vertex), and each interior face (plaquette) hosts an X-type stabilizer (the product of X on all edges bordering that face):

vertex stabilizer: Z_a Z_b Z_c Z_d    plaquette stabilizer: X_e X_f X_g X_hEach stabilizer touches only the 4 data qubits immediately around it — "local" checks, which matters enormously for real hardware where only nearby qubits can interact.

Crucially, the two stabilizer types always overlap each other in an even number of qubits (a vertex and an adjacent face share exactly 2 edges), which is exactly what makes a Z-type and an X-type stabilizer commute — a non-negotiable requirement for them to be simultaneously measurable without disturbing each other's outcome.

6.3Why This Catches Both Error Types

A bit-flip (X) error on a data qubit anticommutes with the Z-type vertex checks touching it, flipping their measured eigenvalue from +1 to −1 — exactly the Lecture-5 mechanism, just arranged on a 2D grid instead of a line. A phase-flip (Z) error anticommutes with the X-type plaquette checks instead, flipping those eigenvalues. Because the lattice has both stabilizer types everywhere, every single-qubit error — X, Z, or both at once (a Y error) — trips at least one type of check, somewhere.

AnalogyThink of the repetition code as a single tripwire line that only catches someone moving north-south. The surface code lays tripwires in both directions across a grid — one set catches north-south movement (X errors), the other catches east-west movement (Z errors) — so no single intruder direction slips through both nets at once.

6.4The Trade-Off: More Qubits, Lower Logical Error Rate

The surface code's power scales with its size: a larger lattice (more rows and columns, hence more physical data qubits per encoded logical qubit) suppresses the logical error rate further, because an undetected logical error now requires a whole chain of physical errors to sneak across the lattice without tripping any stabilizer along the way — and longer chains are exponentially less likely as the lattice grows. This qualitative trade-off — pay with more physical qubits, get exponentially better logical protection — is the seed of Week 7's threshold theorem, and it's also this week's discussion prompt below.

🛠️ Hands-On: reading off a small patch's stabilizers

Keeping this conceptual (per this week's scope — no full lattice simulation or decoder yet), just enumerate the stabilizer generators of the tiny 3×3-vertex patch in Fig 6.1 as Pauli strings over its 12 data qubits (labeled d0–d11 by edge position), and sanity-check that each pair of adjacent X-type and Z-type stabilizers shares an even number of qubits — the commutation condition from §6.2.

# surface_patch_stabilizers.py — Lecture 6 (conceptual, no circuit execution)
# 12 data qubits on the edges of a 3x3-vertex, 2x2-face patch (Fig 6.1)
vertex_stabilizers = {
    "top-left vertex":  "Z0 Z4",         # corner vertex: only 2 edges meet here
    "center vertex":    "Z4 Z5 Z8 Z9",   # interior vertex: all 4 edges present
}
plaquette_stabilizers = {
    "top-left face":    "X4 X5 X10 X11",
    "top-right face":   "X1 X2 X7 X9",
}

# overlap check: center vertex (Z4,Z5,Z8,Z9) vs top-left face (X4,X5,X10,X11)
shared = set("Z4 Z5 Z8 Z9".replace("Z","").split()) & set("X4 X5 X10 X11".replace("X","").split())
print("shared qubit indices:", shared, " -> even overlap (2 qubits) keeps them commuting")

The real surface-code decoder (matching up a whole pattern of triggered stabilizers to the most likely error chain) is well beyond this introductory course's scope — the goal here is just the picture: local X- and Z-type checks tiling a 2D lattice, together catching every single-qubit error type.

🔗 Where this is heading

You now have the conceptual picture of a code that catches everything the repetition code missed. Week 7 asks the scaling question directly: if you keep growing the surface code's lattice, does the logical error rate actually keep dropping forever, or is there a point past which more qubits stop helping? That's the threshold theorem.

5 questions · click "Show answer" to check yourself.

Q1. The repetition code (Lecture 4) is blind to phase-flip errors because its stabilizers are…
A. too few in number
B. measured too rarely
C. built from X operators only
D. built entirely from Z operators, which never detect a phase (Z) error
Show answer

D. Z-type stabilizers only flag disagreements in the computational basis, which a Z error never produces — exactly why a single error type needs a matching stabilizer type to be caught.

Q2. In the surface code, data qubits sit on…
A. the edges of a 2D lattice, with vertex and plaquette stabilizers surrounding them
B. a single 1D line, exactly like the repetition code
C. only the corners of the lattice
D. ancilla qubits exclusively
Show answer

A. Data qubits live on lattice edges; each vertex hosts a Z-type stabilizer over its surrounding edges, and each face hosts an X-type stabilizer over its bordering edges.

Q3. A phase-flip (Z) error on a data qubit is detected by…
A. neither stabilizer type — surface codes can't catch Z errors either
B. the vertex (Z-type) stabilizers
C. a classical parity check outside the lattice
D. the plaquette (X-type) stabilizers, since a Z error anticommutes with X-type checks
Show answer

D. X-type plaquette stabilizers flip sign when they overlap a Z error, exactly mirroring how Z-type vertex stabilizers flag X errors.

Q4. Growing the surface code's lattice (more physical qubits per logical qubit) has what qualitative effect?
A. It suppresses the logical error rate further, since an undetected error now requires a longer, less-likely chain of physical errors
B. It has no effect on the logical error rate
C. It increases the logical error rate
D. It removes the need for any stabilizer measurement
Show answer

A. A larger lattice makes it exponentially less likely for a chain of physical errors to sneak across undetected — more physical qubits buys better logical protection, at a real hardware cost.

Q5. Adjacent X-type and Z-type stabilizers in the surface code must share an even number of qubits because…
A. an odd overlap would make the two stabilizers fail to commute, which breaks simultaneous measurement
B. odd numbers are forbidden in quantum mechanics
C. it has no physical significance, it's just a convention
D. it ensures every data qubit is measured directly
Show answer

A. Pauli operators anticommute on each shared qubit; an even number of shared qubits means an even number of anticommutations, which multiply out to an overall commuting pair — exactly what's needed to measure both without disturbing the other's outcome.
