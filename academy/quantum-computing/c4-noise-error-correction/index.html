🛠️ Hands-On Project

Simulate a Repetition / Surface Code Under Noise

Build a small error-correcting code, inject realistic noise (bit-flip, depolarizing, or a calibrated device noise model), run syndrome extraction, and show the logical error rate drops versus the uncorrected physical error rate. You deliver a short report with code and plots. Week 1 includes a one-time install of Qiskit + PennyLane's noise tooling (step-by-step in Lecture 1) — the same toolkit you'll use all course.

Wk 1: install PennyLane + Qiskit noise tools Wk 4: repetition code encode/decode working Wk 8: code running under a realistic noise model Wk 10: report + plots submitted

💬 Discussions

Three checkpoints — weeks 3, 6, 9

  • Week 3: Noise turns a pure state into a mixed one — information isn't destroyed, it leaks into the environment. Why does that distinction matter for whether errors can, in principle, be corrected?
  • Week 6: The surface code buys lower logical error rates by burning far more physical qubits per logical qubit. Why is that trade worth it, and where does it stop being worth it?
  • Week 9: Error mitigation (no extra qubits) and error correction (extra qubits, real redundancy) solve the same problem differently. Why do today's NISQ devices lean on mitigation while future fault-tolerant devices will lean on correction?
