8.1Gradient-Based Methods and the Parameter-Shift Rule

Every gradient-descent step this course has run — Lecture 1's toy circuit, Lecture 4's VQE, Lecture 7's QAOA — used PennyLane's automatic gradients without asking how a real quantum device, which can't run backpropagation the way a classical neural network can, actually produces them. The answer is one of the genuinely elegant quantum-specific tricks in this whole field: the parameter-shift rule.

✦ The Parameter-Shift RuleFor a cost function built from a gate like RY(θᵢ) (and many other common gates), the exact derivative of the cost with respect to θᵢ can be computed from exactly two circuit evaluations, shifted by ±π/2 — no finite-difference approximation, no small-step error, just two clean measurements:
∂⟨H⟩/∂θᵢ = [⟨H⟩(θᵢ+π/2) − ⟨H⟩(θᵢ−π/2)] / 2
This is exact, not approximate — a genuinely quantum-mechanical fact about how these gates' generators work, with no classical finite-difference analog of this cleanliness.

Once you have exact gradients via parameter shift, standard gradient-based classical optimizers become available: plain gradient descent (Lecture 1's choice throughout, for simplicity), or Adam (which adapts its step size per parameter using running estimates of the gradient's mean and variance — generally more robust than plain gradient descent on noisy, multi-parameter landscapes like VQE's and QAOA's).

8.2Gradient-Free Methods: COBYLA, Nelder-Mead

Gradient-based methods have one obvious weakness given Week 5: if you're sitting on a barren plateau, the parameter-shift rule will faithfully compute a gradient that's just... correctly, exactly zero (or indistinguishable from shot noise). No amount of gradient-computation cleverness rescues you from a genuinely flat landscape.

Gradient-free optimizers sidestep the issue by never computing a gradient at all. COBYLA (Constrained Optimization BY Linear Approximation) and Nelder-Mead both work by evaluating the cost function at a handful of nearby points and using the pattern of those values — not derivatives — to decide where to move next. They avoid ever needing an explicit gradient computation — but that's not the same as being immune to barren plateaus: per Arrasmith et al. (2021), the cost-function differences these methods rely on to decide where to move also vanish exponentially on a barren plateau, so gradient-free optimization sidesteps the mechanics of gradient computation without actually escaping the underlying flat landscape. They also typically need more total cost-function evaluations to converge and can get stuck more easily on landscapes with many shallow local structures.

8.3SPSA: Gradient-Free and Noise-Robust

SPSA (Simultaneous Perturbation Stochastic Approximation) sits between the two camps above. Each iteration, instead of evaluating every parameter's shift separately (as full parameter-shift gradients would require), SPSA perturbs all parameters at once in a single random direction, evaluates the cost at only two points, and uses that to estimate a descent direction. This makes each iteration dramatically cheaper for high-dimensional θ (one random direction's worth of evaluations, not one pair per parameter), and it tends to be naturally robust to the shot noise inherent in real quantum hardware measurements — which is exactly why SPSA is a popular choice for NISQ-era VQE and QAOA runs specifically, rather than a general-purpose classical optimization default.

Common mistakeAssuming there's one "correct" optimizer for every hybrid loop. Gradient-based methods (with parameter shift) give exact gradients but can be blind-sided by barren plateaus; gradient-free methods (COBYLA, Nelder-Mead) avoid computing an explicit gradient but are not actually immune to barren plateaus — the cost differences they rely on vanish too — and they converge more slowly; SPSA trades some precision for cheap, noise-robust iterations on real hardware. The right choice depends on qubit count, ansatz depth, and whether you're running on a simulator or noisy real hardware.
✦ Worked Example — parameter-shift by hand, on Lecture 1's circuit

Apply the parameter-shift rule to Lecture 1's exact toy circuit: cost(θ) = ⟨ψ(θ)|Z|ψ(θ)⟩ = cos(θ) for the RY(θ) ansatz. Confirm the parameter-shift formula reproduces the known exact derivative at θ = π/4.

  1. Known exact derivative (by direct calculus): d/dθ[cos(θ)] = −sin(θ). At θ = π/4: −sin(π/4) = −√2/2 ≈ −0.7071.
  2. Parameter-shift evaluations: cost(π/4 + π/2) = cos(3π/4) = −√2/2 ≈ −0.7071, and cost(π/4 − π/2) = cos(−π/4) = cos(π/4) = √2/2 ≈ 0.7071.
  3. Apply the formula: ∂cost/∂θ = [cost(θ+π/2) − cost(θ−π/2)] / 2 = [(−0.7071) − (0.7071)] / 2 = (−1.4142)/2 = −0.7071.
  4. Compare: the parameter-shift result (−0.7071) matches the exact calculus derivative (−0.7071) exactly — not approximately, exactly — confirming the rule's claim of exactness for this gate type.

🛠️ Hands-On: COBYLA via SciPy on the Lecture 6/7 QAOA circuit

Rebuild the p=1 triangle-graph QAOA circuit from Lecture 7, but this time optimize γ, β with scipy.optimize.minimize using COBYLA — a gradient-free method — and compare the final ⟨Hc⟩ to Lecture 7's manual gradient-descent result.

# qaoa_cobyla.py — Lecture 8
import pennylane as qml
from pennylane import numpy as np
from scipy.optimize import minimize

edges = [(0, 1), (1, 2), (0, 2)]
coeffs, obs = [], []
for (i, j) in edges:
    coeffs += [0.5, -0.5]
    obs += [qml.Identity(i), qml.PauliZ(i) @ qml.PauliZ(j)]
# qml.ops.LinearCombination is current PennyLane's replacement for the deprecated qml.Hamiltonian
Hc = qml.ops.LinearCombination(coeffs, obs)
Hm = qml.ops.LinearCombination([1.0]*3, [qml.PauliX(0), qml.PauliX(1), qml.PauliX(2)])

dev = qml.device("default.qubit", wires=3)

@qml.qnode(dev)
def qaoa_cost(params):
    gamma, beta = params[0], params[1]
    for q in range(3):
        qml.Hadamard(wires=q)
    qml.ApproxTimeEvolution(Hc, gamma, 1)
    qml.ApproxTimeEvolution(Hm, beta, 1)
    return qml.expval(Hc)

def neg_cost(params):
    return -float(qaoa_cost(params))           # SciPy minimizes; we want to maximize <Hc>

result = minimize(neg_cost, x0=[0.4, 0.8], method="COBYLA",
                   options={"maxiter": 100})
print(f"COBYLA best gamma,beta = {np.round(result.x, 3)}")
print(f"COBYLA best <Hc> = {-result.fun:.3f}   (true max = 2.0)")

COBYLA should land near the same ⟨Hc⟩ Lecture 7's manual gradient descent found — often in fewer lines of orchestration code, since SciPy handles the iteration loop internally, but typically at the cost of more total circuit evaluations under the hood.
