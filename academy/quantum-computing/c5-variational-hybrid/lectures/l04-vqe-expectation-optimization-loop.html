VQE II: Expectation Values & the Optimization Loop

Lecture 3's toy Hamiltonian had one Pauli term. Every real molecule's Hamiltonian has several — and a quantum device can't measure a sum directly. This week fills in the practical detail that's usually glossed over.

🎯 Learning Objectives

  • Explain why a real device must measure each Pauli term of H = Σᵢ cᵢPᵢ separately, not all at once.
  • Describe the basis-rotation trick needed to measure X and Y terms using a Z-basis measurement device.
  • Walk the complete VQE loop: prepare → measure each term → combine into ⟨H⟩ → classical update → repeat.
  • Work through measuring H = Z₀ + X₀X₁ term by term for a specific ansatz state.
  • Build and run that 2-term VQE loop in PennyLane for a few optimization steps.

4.1Why You Can't Just "Measure H"

Lecture 3 wrote ⟨H⟩ as a single number without dwelling on how a real circuit produces it. Here's the detail: a quantum device's native measurement is in the Z basis — it tells you, per qubit, whether the outcome was |0⟩ or |1⟩. If H = Σᵢ cᵢPᵢ is a sum of several different Pauli strings, there's no single circuit measurement that reads off all of them simultaneously, because different Pᵢ terms generally don't commute with each other.

H = Σᵢ cᵢ Pᵢ    ⟨H⟩ = Σᵢ cᵢ ⟨Pᵢ⟩Expectation value is linear, so ⟨H⟩ is just the weighted sum of each term's own expectation value — but each ⟨Pᵢ⟩ must be measured in its own separate run of the circuit.

The practical recipe: for each Pauli term Pᵢ, prepare |ψ(θ)⟩ fresh, measure ⟨Pᵢ⟩ (many shots, same θ), record the result, then move to the next term. Once you have every ⟨Pᵢ⟩, combine them with their coefficients cᵢ to get ⟨H⟩. This is more circuit runs per optimization step than Lecture 3's one-term toy suggested — a real cost that scales with how many Pauli terms your Hamiltonian has.

4.2Measuring X and Y Terms: Basis Rotation

There's one more wrinkle. A Z-basis measurement directly reads out ⟨Z⟩-type terms, but what about a term like X₀ or Y₁ Z₂? The trick: rotate the qubit before measuring so that the thing you want to know about gets mapped onto the Z axis, then measure in the (now native) Z basis.

  • To measure ⟨X⟩: apply a Hadamard gate, then measure in the Z basis. H maps the X-eigenstates to the Z-eigenstates, so the Z-basis outcome now reports what the X-basis outcome would have been.
  • To measure ⟨Y⟩: apply a slightly different single-qubit rotation (equivalent to H composed with a phase gate) before the Z-basis measurement, for the same reason.
  • To measure ⟨Z⟩: no rotation needed — it's already native.

For a multi-qubit Pauli string like X₀X₁, apply the X-basis rotation independently to each qubit it touches before measuring both in the Z basis, then multiply together the ±1 outcomes per shot. This basis-rotation step is exactly why real VQE implementations group and tag Pauli terms by which basis rotation they need — it's bookkeeping, but it's essential bookkeeping that the toy one-term example from Lecture 3 let you skip entirely.

4.3The Full VQE Loop

Putting everything from Lectures 1–4 together, here is VQE's actual loop, run once per optimizer iteration:

1) prepare |ψ(θ)⟩  →  2) measure each ⟨Pᵢ⟩ (with basis rotation as needed)  →  3) combine into ⟨H⟩=Σᵢcᵢ⟨Pᵢ⟩  →  4) classical optimizer proposes new θ  →  repeatSteps 1–2 happen on the quantum device (possibly several circuit runs per iteration, one per distinct Pauli term); steps 3–4 happen entirely on a classical computer.

This is identical in spirit to Lecture 1's four-step loop — the only new content is that "measure the cost" (step 2 there) now fans out into several separate quantum measurements before being recombined classically in step 3. PennyLane, as you'll see in the hands-on below, hides most of this bookkeeping behind a single qml.ops.LinearCombination object (the modern name for what older PennyLane code calls qml.Hamiltonian, now deprecated) — but you should now know exactly what it's doing underneath.

Common mistakeAssuming a Hamiltonian with k Pauli terms costs the same to measure as a 1-term Hamiltonian. It doesn't — naively, you need a separate set of circuit shots per distinct term (per distinct required basis rotation), so the measurement cost of VQE scales with how many terms the qubit-mapped Hamiltonian has, not just with qubit count.
✦ Worked Example — measuring H = Z₀ + X₀X₁ term by term

Take a 2-qubit Hamiltonian H = Z₀ + X₀X₁ and a trial state |ψ⟩ = (|00⟩+|11⟩)/√2 (a Bell state). Find ⟨H⟩ by measuring each term separately.

  1. Term 1, ⟨Z₀⟩: measuring qubit 0 in the Z basis on this state gives |0⟩ half the time (+1) and |1⟩ half the time (−1), so ⟨Z₀⟩ = ½(+1) + ½(−1) = 0.
  2. Term 2, ⟨X₀X₁⟩: rotate both qubits into the X measurement basis (Hadamard on each), then measure in Z. For this Bell state, the two qubits' X-basis outcomes are perfectly correlated, giving ⟨X₀X₁⟩ = 1.
  3. Combine: ⟨H⟩ = ⟨Z₀⟩ + ⟨X₀X₁⟩ = 0 + 1 = 1.
⟨H⟩ = ⟨Z₀⟩ + ⟨X₀X₁⟩ = 0 + 1 = 1Two separate measurement settings were required — one native Z-basis run for the Z₀ term, one Hadamard-rotated run for the X₀X₁ term — then combined classically.

🛠️ Hands-On: a real 2-term VQE loop in PennyLane

PennyLane's qml.ops.LinearCombination (the current, non-deprecated replacement for qml.Hamiltonian) handles the term-by-term measurement and basis rotation under the hood. Build H = Z₀ + X₀X₁, attach a small 2-qubit ansatz, and run a few real optimization steps toward whatever ground state this toy Hamiltonian has.

# vqe_two_term.py — Lecture 4
import pennylane as qml
from pennylane import numpy as np

# qml.ops.LinearCombination is current PennyLane's replacement for the deprecated qml.Hamiltonian
H = qml.ops.LinearCombination([1.0, 1.0], [qml.PauliZ(0), qml.PauliX(0) @ qml.PauliX(1)])

dev = qml.device("default.qubit", wires=2)

@qml.qnode(dev)
def cost(params):
    qml.RY(params[0], wires=0)
    qml.RY(params[1], wires=1)
    qml.CNOT(wires=[0, 1])
    return qml.expval(H)                     # PennyLane measures each Pauli term and sums for you

params = np.array([0.4, 0.9], requires_grad=True)
opt = qml.GradientDescentOptimizer(stepsize=0.3)

print(f"start:  params={params}  <H>={cost(params):.4f}")
for step in range(10):
    params = opt.step(cost, params)
    print(f"step {step+1}:  params={np.round(params, 3)}  <H>={cost(params):.4f}")

Watch ⟨H⟩ fall step by step. Behind qml.expval(H), PennyLane is running the exact term-by-term, basis-rotated measurement recipe from §4.1–4.2 — you're just no longer doing the bookkeeping by hand.

🔗 Where this is heading

You now have VQE's complete machinery: ansatz, Hamiltonian, term-by-term measurement, and classical loop. The natural next question is whether this machinery actually scales — and Week 5's answer is sobering: as circuits and parameter counts grow, the gradient-based descent you just watched work can flatten out almost everywhere, a phenomenon called barren plateaus.

Q1. Why can't a quantum device measure ⟨H⟩ for H = Σᵢ cᵢPᵢ in one single measurement setting?
A. Because the different Pauli terms generally don't commute and need different measurement bases, so each must be measured in its own circuit run
B. Because quantum devices cannot measure sums of operators under any circumstances
C. Because H must first be diagonalized by hand
D. Because classical computers cannot add numbers together
Show answer

A. Each Pauli term may need its own basis rotation before the native Z-basis measurement, so distinct terms generally require separate circuit runs.

Q2. To measure ⟨X⟩ on a device whose native measurement is the Z basis, you should…
A. Apply a Hadamard gate before measuring in the Z basis
B. Apply nothing — X is already native
C. Apply a CNOT gate before measuring
D. Measure twice and average
Show answer

A. A Hadamard rotates the X-eigenbasis onto the Z-eigenbasis, so the subsequent native Z-basis measurement reports the X-basis outcome.

Q3. In the full VQE loop, which steps happen on the quantum device versus the classical computer?
A. Everything happens on the quantum device
B. Preparing |ψ(θ)⟩ and measuring each ⟨Pᵢ⟩ happen on the quantum device; combining into ⟨H⟩ and proposing new θ happen classically
C. Everything happens on the classical computer
D. The quantum device proposes new θ values directly
Show answer

B. The quantum/classical split from Lecture 1 is unchanged — only the "measure the cost" step now fans out into several Pauli-term measurements before classical recombination.

Q4. For H = Z₀ + X₀X₁ on the Bell state (|00⟩+|11⟩)/√2, the worked example found ⟨H⟩ equals…
A. 0
B. 1
C. 2
D. −1
Show answer

B. ⟨Z₀⟩ = 0 and ⟨X₀X₁⟩ = 1 on this Bell state, so ⟨H⟩ = 0 + 1 = 1.

Q5. In the PennyLane hands-on code, what is doing the term-by-term basis-rotated measurement work from §4.1–4.2 under the hood?
