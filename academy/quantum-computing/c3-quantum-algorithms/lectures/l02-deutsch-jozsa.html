The Deutsch–Jozsa Algorithm

Scale last week's 1-bit trick up to n bits, and the query-complexity gap stops being cute — it becomes exponential.

🎯 Learning Objectives

  • State the n-bit Deutsch–Jozsa promise problem: f is guaranteed constant or balanced, determine which.
  • Show why a classical deterministic algorithm needs up to 2ⁿ⁻¹ + 1 queries in the worst case.
  • Generalize the phase-kickback + Hadamard trick from Lecture 1 to n qubits using H⊗n.
  • Trace the algorithm's amplitudes for a concrete n=2 balanced oracle.
  • Build and run a 3-qubit Deutsch–Jozsa circuit in Qiskit for a constant and a balanced oracle.

2.1The Promise Problem, Generalized to n Bits

Last week's Deutsch problem used the smallest possible function: one input bit. The Deutsch–Jozsa problem asks the same constant-vs-balanced question about a function of n input bits, f : {0,1}n → {0,1}, under the same kind of promise: you are told in advance that f is constant (f(x) is the same value for all 2n inputs x) or balanced (f(x) = 0 for exactly half of the 2n inputs and 1 for the other half) — never anything in between.

f : {0,1}ⁿ → {0,1}, promised constant or balanced. Decide which.Same two-way promise as Lecture 1, just with n input bits instead of 1 — so there are 2ⁿ possible inputs to think about instead of 2.

The promise is what makes this tractable at all. Without it, distinguishing "constant" from "everything else" from query answers alone is a much harder, unpromised problem. With the promise, the moment you see any two different output values, f cannot be constant — it must be balanced, since those are the only two options left on the table.

2.2Classical Query Complexity: Up to 2ⁿ⁻¹ + 1

A deterministic classical algorithm has no shortcut beyond brute-force querying. The worst case for an adversarial f: query inputs one at a time, and as long as every answer so far has been the same value, f is still consistent with being constant. The adversary can keep answering with that same value for exactly half of all 2n inputs — 2n−1 of them — before being forced to either confirm "constant" or reveal a different value and prove "balanced."

Classical queries needed (worst case, zero error) = 2ⁿ⁻¹ + 1After 2ⁿ⁻¹ identical answers, f could still be constant — one more query is required to settle it either way. This is exponential in n.

This is the whole point of generalizing beyond n=1: at n=1, "20+1 = 2" sounds unremarkable — the same 2 queries you saw last week. But at n=20, that's 219+1 ≈ half a million queries in the worst case, growing exponentially with every additional input bit. Whatever the quantum algorithm costs, if it stays flat as n grows, the gap becomes dramatic fast.

2.3The Quantum Algorithm: One Query, Any n

The quantum algorithm is Lecture 1's trick, generalized bit by bit: replace the single Hadamard on the input register with a Hadamard on every input qubit, written H⊗n (an n-fold tensor product of H). The output/ancilla qubit is still prepared in |−⟩, and the oracle Uf still only needs to be queried once.

H⊗n|0⟩⊗n = (1/√2ⁿ) Σₓ |x⟩   (sum over all x ∈ {0,1}ⁿ)n parallel Hadamards put the n-qubit input register into an equal superposition of all 2ⁿ possible inputs — not n separate superpositions, one joint state covering every x.

Query Uf with the output register in |−⟩, and exactly as in Lecture 1, phase kickback writes (−1)f(x) onto each term of the superposition without touching the output register at all:

U_f [ (1/√2ⁿ) Σₓ |x⟩ ⊗ |−⟩ ] = (1/√2ⁿ) Σₓ (−1)^f(x) |x⟩ ⊗ |−⟩One query touches every one of the 2ⁿ terms simultaneously — the defining move of every algorithm in this course.

Apply H⊗n again to the input register and measure. A short Fourier-style calculation (the amplitude on the all-zeros outcome |0⟩⊗n after the second H⊗n is exactly (1/2ⁿ) Σₓ (−1)f(x)) gives a clean result: if f is constant, every term in that sum has the same sign, so the amplitude on |0⟩⊗n has magnitude 1 and you measure all zeros with certainty. If f is balanced, exactly half the signs are + and half are −, the sum cancels to exactly 0, and you measure anything other than all zeros — never all zeros — with certainty.

AnalogyPicture 2ⁿ identical speakers, one per input x, each playing either an in-phase or an out-of-phase copy of the same tone, according to (−1)^f(x). If f is constant, every speaker is in phase — the tone adds up to maximum volume at the "all zeros" listening point. If f is balanced, exactly half the speakers are flipped out of phase, and at that same listening point they cancel to total silence. One listen (one query, one final Hadamard layer) tells you which situation you're in, no matter how many speakers (how large n) there are.

2.4Reading the Measurement Result

The decision rule is as simple as Lecture 1's, just restated for n bits: measure the input register. All-zeros ⟹ constant. Anything else ⟹ balanced. There is no ambiguity and no probability of error — this is exact, not approximate, exactly like Lecture 1.

Common mistakeIt's tempting to think the quantum speedup here "scales" the way classical brute force does — i.e. that the quantum algorithm is just doing the 2ⁿ⁻¹+1 classical queries faster in parallel. It isn't. The quantum algorithm makes exactly one query regardless of n; the exponential classical cost doesn't get compressed, it gets bypassed entirely by moving the computation into relative phases that interfere before any measurement happens. The "parallelism" is in the phase information carried by superposition, not in simultaneously evaluating 2ⁿ⁻¹+1 classical branches and keeping the answer.
✦ Worked Example — n=2, balanced f(x₁x₀) = x₀ (XOR of nothing but the low bit)

Take n=2 with f(x₁x₀) = x₀ — so f(00)=0, f(01)=1, f(10)=0, f(11)=1: balanced, since exactly two of the four inputs give 0 and two give 1. Confirm the algorithm measures "not all zeros."

  1. Prepare: 2 input qubits in |00⟩, ancilla in |1⟩ → H⊗2 on the input, H on the ancilla gives ½(|00⟩+|01⟩+|10⟩+|11⟩) ⊗ |−⟩.
  2. Apply the oracle (phase kickback, since the ancilla is in |−⟩): each term |x⟩ picks up (−1)^f(x). Here f(00)=0, f(01)=1, f(10)=0, f(11)=1, so the state becomes ½(+|00⟩−|01⟩+|10⟩−|11⟩) ⊗ |−⟩.
  3. Factor the input register: ½(|00⟩−|01⟩+|10⟩−|11⟩) = ½(|0⟩+|1⟩) ⊗ (|0⟩−|1⟩) = |+⟩ ⊗ |−⟩ — note only the second qubit (x₀) carries a sign flip, since only x₀ appears in f.
  4. Apply H⊗2 to the input register: H|+⟩ = |0⟩ on the first qubit, H|−⟩ = |1⟩ on the second qubit. Combined input-register state: |0⟩⊗|1⟩ = |01⟩.
  5. Measure the input register: result is 01 with certainty — not all zeros, so the algorithm correctly reports "balanced," using exactly one query to U_f.

🛠️ Hands-On: Deutsch–Jozsa for n=3

Build the n=3 circuit once, then swap in a constant oracle and a balanced oracle (f(x) = x₀, the parity of just the lowest input bit — balanced because it's 0 for half of all 3-bit strings and 1 for the other half).

# deutsch_jozsa.py — Lecture 2
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

def dj_circuit(n, oracle):
    # qubits 0..n-1 = input register, qubit n = ancilla/output
    qc = QuantumCircuit(n + 1)
    qc.x(n)                      # ancilla starts at |1>
    qc.h(range(n + 1))           # H on every qubit: input -> uniform superposition, ancilla -> |->
    oracle(qc)                   # one query to U_f
    qc.h(range(n))               # undo superposition on the input register only
    return qc

def constant_oracle(qc):
    pass                         # f(x) = 0 for all x: oracle does nothing

def balanced_oracle(qc):
    qc.cx(0, qc.num_qubits - 1)  # f(x) = x0: flip ancilla iff lowest input bit is 1

n = 3
for name, oracle in [("constant", constant_oracle), ("balanced", balanced_oracle)]:
    qc = dj_circuit(n, oracle)
    sv = Statevector.from_instruction(qc)
    probs = sv.probabilities_dict(qargs=range(n))   # measurement odds on the n input qubits
    print(name, "-> P(input register) =", probs)

Expected output: the constant oracle concentrates all probability on '000'; the balanced oracle puts all probability on a non-zero string (here '001', since only x₀ matters) — confirming the all-zeros-vs-not rule for n=3, exactly as derived above for n=2.

🔗 Where this is heading

Deutsch–Jozsa only distinguishes two possibilities (constant vs. balanced) — it throws away the actual output values along the way. Week 3's Bernstein–Vazirani algorithm reuses this exact same circuit shape (H⊗n → oracle → H⊗n → measure) but on a different promise, and gets something much richer out of it: an entire hidden n-bit string, recovered in a single query. Watching the same machinery solve two different problems is the clearest evidence yet that the H⊗n-oracle-H⊗n pattern is a genuine primitive, not a one-off trick.

Q1. The Deutsch–Jozsa promise guarantees that f : {0,1}ⁿ → {0,1} is…
A. either constant or balanced, never anything in between
B. always injective
C. always a linear function
D. unknown — no promise is made
Show answer

A. The promise rules out every function except the two extremes — all-same-output (constant) or exactly-half-and-half (balanced) — which is exactly what makes the problem tractable in one query.

Q2. The worst-case classical query count for the n-bit Deutsch–Jozsa problem is…
A. n
B. 2ⁿ⁻¹ + 1
C. log₂(n)
D. 1, always
Show answer

B. An adversary can answer identically for up to half of all 2ⁿ inputs before being forced to reveal whether f is constant or balanced — one more query past 2ⁿ⁻¹ settles it, giving 2ⁿ⁻¹+1.

Q3. H⊗n applied to |0⟩⊗n produces…
A. a single random n-bit string
B. the state |1⟩⊗n
C. an equal superposition of all 2ⁿ computational basis states
D. a mixed, non-pure state
Show answer

C. n parallel Hadamards put the n-qubit register into a single joint superposition with equal amplitude 1/√2ⁿ on every one of the 2ⁿ basis states.

Q4. In the n=2 worked example with f(x₁x₀)=x₀, measuring the input register after the algorithm gives…
A. 00, with certainty
B. 01, with certainty
C. a uniformly random 2-bit string
D. 11, with certainty
Show answer

B. Tracing the amplitudes shows the input register ends in |+⟩⊗|−⟩, and H⊗2 maps that to |0⟩⊗|1⟩ = |01⟩ with certainty — not all zeros, correctly flagging "balanced."

Q5. The number of oracle queries the quantum Deutsch–Jozsa algorithm needs, as a function of n, is…
A. 2ⁿ⁻¹ + 1, same as classical
B. n
C. log₂(n)
D. exactly 1, for every n
Show answer

D. The whole point of the algorithm: a single query to U_f suffices no matter how large n is, versus a classical cost that grows exponentially in n — an exponential query-complexity separation.
