Query Complexity & the Deutsch Algorithm

The simplest possible quantum speedup: a question a classical computer needs two tries to answer, a quantum computer answers in one.

🎯 Learning Objectives

  • Explain what an oracle is in quantum algorithms — a black-box unitary you can query but not inspect.
  • State the Deutsch problem and show why a classical algorithm needs 2 queries to solve it with certainty.
  • Describe the phase-kickback trick that lets a single quantum query encode f(0) and f(1) simultaneously.
  • Trace the Deutsch circuit's amplitudes step by step for a specific oracle.
  • Build and simulate the Deutsch circuit in Qiskit for both a constant and a balanced oracle.

1.1What an Oracle Is

Every algorithm in this course is built around an oracle: a black-box unitary circuit Uf that computes some function f for you, but whose internal wiring you are not allowed to inspect. You may query it — feed it an input and read the output — as many times as your algorithm calls for, and the whole point of "query complexity" is counting how many queries are actually necessary. This isn't a toy restriction; it models a very real situation: a password checker, a satisfiability instance, or a factoring sub-problem are all functions you can evaluate without understanding why they give the answer they do.

U_f : |x⟩|y⟩ ↦ |x⟩|y ⊕ f(x)⟩The standard oracle shape: an input register |x⟩, an output register |y⟩, and XOR (⊕) combining in f(x). This form is always unitary and reversible, even when f itself isn't invertible.

The function in today's lecture is about as small as a function can be: f : {0,1} → {0,1} — one input bit, one output bit. There are exactly four such functions, and they split into two families: f is constant if f(0) = f(1) (two of the four functions), or balanced if f(0) ≠ f(1) (the other two).

1.2The Classical Query Complexity of the Deutsch Problem

The Deutsch problem asks: given query access to f, is f constant or balanced? Classically, one query is never enough. Querying f(0) alone tells you nothing about f(1) — both a constant and a balanced function are consistent with any single value you see. You must query both f(0) and f(1) and compare them to be certain.

Classical queries needed (worst case, zero error) = 2Query f(0), query f(1), compare. There is no classical shortcut that works for every f — an adversary choosing f after your first query can always force you to be wrong if you stop at one.

This is a deliberately tiny problem — with only 2 possible inputs, "2 queries" sounds unimpressive. Its value is pedagogical: it is the smallest example where a quantum algorithm beats the classical bound, and the trick that makes it work scales up directly into the Deutsch–Jozsa algorithm next week, where the classical cost grows exponentially with the number of input bits while the quantum cost stays at a single query.

1.3The Quantum Trick: Encode f into a Phase, Then Interfere

The quantum algorithm answers with a single query to Uf. The trick has two parts. First, put the output register in the superposition |−⟩ = (|0⟩ − |1⟩)/√2 before querying. A short calculation (do it yourself: apply Uf to |x⟩|−⟩ and expand the XOR) shows that querying with this specific output state never changes the output register at all — it just multiplies the input register by a sign:

U_f ( |x⟩ ⊗ |−⟩ ) = (−1)^f(x) |x⟩ ⊗ |−⟩"Phase kickback": the oracle's answer, f(x), ends up as a ± sign on the input register instead of changing the output register at all.

Second, query with the input register in superposition too: |+⟩ = (|0⟩ + |1⟩)/√2. Because Uf is linear, querying a superposition of inputs kicks back both signs onto both terms in a single pass:

U_f ( |+⟩ ⊗ |−⟩ ) = [ (−1)^f(0) |0⟩ + (−1)^f(1) |1⟩ ] / √2 ⊗ |−⟩One query now carries information about f(0) and f(1) simultaneously, encoded as relative signs on the input register.

If f is constant, the two signs are equal and factor out as an irrelevant global phase, leaving the input register exactly as |+⟩. If f is balanced, the two signs are opposite, and the input register becomes |−⟩ instead. A final Hadamard gate on the input register converts this sign difference into something you can measure directly: H|+⟩ = |0⟩, H|−⟩ = |1⟩. One measurement, zero ambiguity, one query total.

AnalogyThink of f(0) and f(1) as two tuning forks struck at the same instant. Classically you can only listen to one fork at a time, so you need two separate listens to compare their pitches. The phase-kickback trick is like striking both forks together and listening for whether the combined sound reinforces (constant, same pitch) or cancels into silence on one output channel (balanced, opposite pitch) — interference is doing the comparison for you, in parallel, in one listen.

1.4Why This Example Matters

The Deutsch algorithm is not useful on its own — nobody needs to classify a one-bit function faster. Its importance is that it is the minimal working example of the pattern behind every quantum algorithm in this course: encode a classical answer into a phase via an oracle, spread the input into superposition so one query touches every input at once, then use a final transform (here, just Hadamard; later, the full quantum Fourier transform) to turn phase differences into something a measurement can read out as a definite classical bit.

Common mistakeIt's tempting to say the quantum computer "evaluates f(0) and f(1) at the same time" and leave it there, as if superposition were just classical parallelism. That's not quite it — the output register never ends up holding two different values; it stays in |−⟩ throughout. What actually happens is that f's answers are written into relative phases on the input register, and only the final Hadamard converts that hidden phase information into a measurable bit. Skip the Hadamard and you learn nothing; the superposition alone doesn't hand you the answer.
✦ Worked Example — tracing amplitudes for f(x) = x

Take the balanced function f(x) = x (so f(0) = 0, f(1) = 1). Trace the full 2-qubit state through the Deutsch circuit, step by step, and confirm the algorithm correctly reports "balanced."

  1. Prepare: input qubit in |0⟩, output qubit in |1⟩: start state |0⟩|1⟩.
  2. Hadamard both qubits: input → |+⟩ = (|0⟩+|1⟩)/√2, output → H|1⟩ = |−⟩ = (|0⟩−|1⟩)/√2. Combined: ½(|0⟩+|1⟩)⊗(|0⟩−|1⟩) = ½[|00⟩ − |01⟩ + |10⟩ − |11⟩].
  3. Apply the oracle U_f : |x⟩|y⟩ ↦ |x⟩|y⊕f(x)⟩, with f(0)=0 (so |0⟩|y⟩ is unchanged) and f(1)=1 (so |1⟩|y⟩ flips its second qubit): |00⟩→|00⟩, |01⟩→|01⟩, |10⟩→|11⟩, |11⟩→|10⟩. The state becomes ½[|00⟩ − |01⟩ + |11⟩ − |10⟩].
  4. Regroup by factoring the input qubit out: ½[|00⟩−|01⟩−|10⟩+|11⟩] = ½(|0⟩−|1⟩)⊗(|0⟩−|1⟩) = |−⟩⊗|−⟩. The input register has flipped from |+⟩ to |−⟩ — exactly the sign-flip phase kickback predicts, since (−1)^f(0)=1 and (−1)^f(1)=−1 are opposite.
  5. Hadamard the input qubit: H|−⟩ = |1⟩. The full state is now |1⟩⊗|−⟩.
  6. Measure the input qubit: result is 1 with certainty → the algorithm reports balanced, correctly, using exactly one query to U_f.

🛠️ Hands-On: the Deutsch circuit for a constant and a balanced oracle

Verify: run python -c "from qiskit.visualization import plot_histogram; print('ok')" — no import error means you're set. Everything below still runs on the free local simulator.

Build the Deutsch circuit once, then swap in two different oracles: a constant oracle (do nothing — f(x) = 0 for all x) and the balanced oracle from the worked example (f(x) = x, built with a single CNOT).

# deutsch_circuit.py — Lecture 1
from qiskit import QuantumCircuit
from qiskit.quantum_info import Statevector

def deutsch_circuit(oracle):
    # qubit 0 = input, qubit 1 = output
    qc = QuantumCircuit(2)
    qc.x(1)            # output register starts at |1>
    qc.h(0); qc.h(1)   # both registers into superposition
    oracle(qc)          # one query to U_f
    qc.h(0)             # undo superposition on the input register
    return qc

def constant_oracle(qc):
    pass                       # f(x) = 0 for all x: oracle does nothing

def balanced_oracle(qc):
    qc.cx(0, 1)                # f(x) = x: flip output iff input is 1

for name, oracle in [("constant", constant_oracle), ("balanced", balanced_oracle)]:
    qc = deutsch_circuit(oracle)
    state = Statevector.from_label('01').evolve(qc)   # unused start; circuit sets its own init
    sv = Statevector.from_instruction(qc)
    probs = sv.probabilities_dict(qargs=[0])           # measurement odds on the input qubit only
    print(name, "-> P(input qubit) =", probs)

Expected output: the constant oracle leaves the input qubit's measurement probability concentrated at 0; the balanced oracle concentrates it at 1 — matching the worked example exactly, with zero overlap between the two cases.

🔗 Where this is heading

Everything here scales. Week 2's Deutsch–Jozsa algorithm replaces the single input bit with n input bits and asks the same constant-vs-balanced question — classically that costs up to 2n−1 + 1 queries in the worst case, but the exact same phase-kickback-then-Hadamard pattern answers it with one quantum query, regardless of n. Week 3's Bernstein–Vazirani algorithm reuses this circuit shape again to extract an entire hidden bit string in one query. And the Hadamard transform you used to close out today's circuit is itself the simplest case of the quantum Fourier transform you'll meet in Week 6 — the engine behind phase estimation and, eventually, Shor's algorithm.

5 questions · click "Show answer" to check yourself.

Q1. An "oracle" U_f in a quantum algorithm is best described as…
A. a classical lookup table you can read directly
B. a black-box unitary that computes f when queried, with its internal implementation hidden
C. a random number generator
D. a measurement, not a gate
Show answer

B. An oracle is a unitary circuit you may query (feed inputs, read outputs) but may not inspect internally — query complexity counts how many such queries an algorithm needs.

Q2. Classically, determining with certainty whether f : {0,1} → {0,1} is constant or balanced requires…
A. 0 queries — it can be inferred from the problem alone
B. 1 query, always
C. 2 queries in the worst case
D. infinitely many queries
Show answer

C. A single query to f(0) or f(1) alone is consistent with both a constant and a balanced f. You need both values to compare them, so 2 queries are necessary and sufficient classically.

Q3. Preparing the oracle's output register in |−⟩ = (|0⟩−|1⟩)/√2 before querying causes U_f to…
A. leave the output register unchanged but attach a sign (−1)^f(x) to the input register — "phase kickback"
B. collapse the input register to a definite classical value
C. erase all information about f from the circuit
D. make the oracle non-unitary
Show answer

A. This is the phase-kickback trick: with the output register in |−⟩, querying U_f|x⟩|−⟩ returns (−1)^f(x)|x⟩|−⟩ — the output register is untouched, and f's answer appears only as a sign on the input register.

Q4. In the worked example with f(x) = x, after the oracle is applied the input register is left in state…
A. |0⟩
B. |1⟩
C. |+⟩, unchanged from before the query
D. |−⟩
Show answer

D. Since f(0)=0 and f(1)=1 give opposite signs (−1)^f(0)=1 and (−1)^f(1)=−1, the input register flips from |+⟩ to |−⟩. A final Hadamard then turns |−⟩ into the measured outcome |1⟩, correctly reporting "balanced."

Q5. Why does the Deutsch algorithm need a final Hadamard gate on the input register before measuring?
A. it doesn't — measuring |+⟩ or |−⟩ directly already distinguishes constant from balanced
B. to convert the hidden relative-phase difference between |+⟩ and |−⟩ into a directly measurable, definite basis-state outcome
C. to reset the output register back to |0⟩
D. to increase the number of queries to the oracle
Show answer

B. |+⟩ and |−⟩ both give 50/50 measurement odds if measured directly in the {|0⟩,|1⟩} basis — the phase difference is invisible until the Hadamard rotates it into the computational basis, where H|+⟩=|0⟩ and H|−⟩=|1⟩ become distinguishable with certainty.
