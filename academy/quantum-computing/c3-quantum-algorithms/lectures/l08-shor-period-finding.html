Week 8 · Lecture 8

Shor's Period-Finding Subroutine

Factoring an integer turns out to be a disguised period-finding problem — and period-finding is QPE pointed at the right unitary.

🎯 Learning Objectives

  • State the classical number-theory reduction: factoring N reduces to finding the period r of aˣ mod N.
  • Describe how QPE estimates the phase of a modular-exponentiation unitary to find r.
  • Explain the role of continued fractions in extracting r from a phase estimate.
  • Describe how gcd computations recover the factors of N once r is known.
  • Explain, at a high level, why this breaks RSA-style cryptography.

8.1From Factoring to Period-Finding (a Classical Reduction)

Shor's algorithm's genius move is almost entirely classical number theory, with the quantum part doing one specific sub-task. The reduction, stated without derivation: to factor a composite N, pick a random a coprime to N (gcd(a,N)=1), and consider the function f(x) = aˣ mod N. This function is periodic — there is a smallest positive integer r (the order of a modulo N) such that f(x+r) = f(x) for all x. Standard number theory (again, stated, not derived here) shows that once you know r, you can usually recover a nontrivial factor of N via a gcd computation.

f(x) = aˣ mod N is periodic with period r   (f(x+r) = f(x) for all x)This is the exact same "hidden period" shape as Simon's problem from Week 3 — not a coincidence; Simon's problem was historically a stepping stone toward exactly this idea.

So the entire factoring problem reduces to: find r, the period of aˣ mod N. Classically, finding r for a large N is believed to be hard (no known classical algorithm does it in polynomial time) — this classical hardness is exactly what RSA-style cryptography leans on. The quantum speedup lives entirely in this one subroutine.

8.2QPE Finds r by Estimating a Phase

Define the unitary Ua,N : |y⟩ ↦ |ay mod N⟩ (modular multiplication by a). This unitary's eigenstates have eigenvalues of the form e2πik/r for integers k = 0,…,r−1 — the period r is baked directly into the denominator of the eigenphase. Run Week 7's QPE circuit with this Ua,N: the counting register, after the inverse QFT, yields a measured value m such that m/2t is a close estimate of some k/r.

QPE on U_{a,N} → phase estimate θ_est ≈ k/r, for some unknown integer kQPE doesn't directly hand you r — it hands you an estimate of a fraction k/r, with k also unknown. Recovering r from that estimate is a classical post-processing step, next.

This is exactly Week 7's machinery, with no new quantum ideas — the only new work is constructing the controlled modular-multiplication circuit for Ua,N, which is a (nontrivial, but classical-logic-translatable) arithmetic circuit, not a new quantum primitive.

8.3Continued Fractions and gcd: the Classical Clean-Up

Given the estimate θ_est ≈ k/r, the continued fraction algorithm (a purely classical, efficient method for finding the "simplest" fraction close to a given decimal) recovers candidate values of r from θ_est — essentially, it finds small-denominator fractions that best approximate θ_est, and r is extracted as (or a divisor of) one of those denominators. A few repeats of the whole QPE-plus-continued-fractions process (different random a, or verifying candidate r values) reliably pin down the true r with high probability.

Once r is known: compute d = gcd(a^(r/2) − 1, N)  (assuming r is even and a^(r/2) ≠ −1 mod N)d is very likely a nontrivial factor of N — this gcd step is the final, purely classical, polynomial-time computation that turns "we know r" into "we know a factor of N."

Chained together — random a, QPE finds θ_est, continued fractions extract r, gcd extracts a factor — this whole pipeline runs in time polynomial in log N, versus the best known classical factoring algorithms, which run in time sub-exponential but still super-polynomial in log N. That gap is Shor's algorithm's headline result.

8.4Why This Breaks RSA

RSA-style public-key cryptography's security rests on a single computational assumption: that factoring a large N = p·q (product of two large primes) is classically intractable. Every piece of that assumption's hardness — the absence of a known efficient classical factoring algorithm — is exactly what Shor's algorithm defeats, given a sufficiently large, sufficiently error-corrected quantum computer. This isn't a vague "quantum computers are powerful" claim; it's a specific, concrete algorithm with a proven polynomial-time complexity for a problem underlying a huge fraction of deployed internet cryptography (TLS key exchange, digital signatures, and more all commonly rely on RSA or closely related hard problems).

Common mistakeIt's tempting to read "Shor's algorithm breaks RSA" as "all encryption is broken" or "this already works today." Neither is true. First, not all cryptography relies on factoring — post-quantum cryptographic schemes based on different (believed quantum-resistant) hard problems already exist and are being deployed specifically because of this threat. Second, running Shor's algorithm on cryptographically relevant N (thousands of bits) requires a quantum computer with far more qubits and far lower error rates than anything that exists today — this is a motivational, forward-looking result (why the field invests in error correction, Course 4's topic), not a description of a capability that exists right now.
✦ Worked Example — tiny factoring walkthrough, N=15, a=7

A toy-sized instance small enough to trace by hand (no real quantum speedup at this size, but the pipeline is identical).

  1. Pick a=7 (coprime to N=15: gcd(7,15)=1 ✓). Compute 7ˣ mod 15 for x=0,1,2,…: 1, 7, 4, 13, 1, 7, 4, 13, … — the sequence repeats with period r=4.
  2. (QPE's job, conceptually): on real hardware, QPE applied to U7,15 would return a phase estimate close to k/4 for some k ∈ {0,1,2,3}; continued fractions would extract the denominator r=4 from that estimate.
  3. Check r is even: r=4 is even ✓. Compute a^(r/2) mod N = 7² mod 15 = 49 mod 15 = 4. Confirm 4 ≠ −1 mod 15 (i.e. 4 ≠ 14) ✓ — the algorithm proceeds.
  4. Compute the gcd: d = gcd(7² − 1, 15) = gcd(48, 15) = gcd(48,15). 48 = 3·15+3, gcd(15,3)=3. So d=3.
  5. Factor found: 3 divides 15, and 15/3 = 5 — both prime. N=15 = 3 × 5, recovered entirely from the period r=4, exactly as the pipeline in §8.3 predicts.

🛠️ Hands-On: classical period-finding + gcd pipeline for N=15

Simulating the full quantum circuit for even N=15 is possible but heavy; this exercise runs the classical half of the pipeline directly (finding r by brute force, the part QPE replaces efficiently at scale) so you can see exactly what the quantum subroutine is standing in for. Project checkpoint: if you want the full quantum circuit, Qiskit's textbook examples include a complete Shor's-algorithm implementation for N=15 — optional stretch goal this week.

# shor_classical_half.py — Lecture 8
from math import gcd

def find_period(a, N):
    # brute-force period finding -- QPE does this step efficiently on a quantum computer
    x, r = a % N, 1
    while x != 1:
        x = (x * a) % N
        r += 1
    return r

def shor_factor(N, a):
    r = find_period(a, N)
    print(f"a={a}, N={N} -> period r={r}")
    if r % 2 != 0:
        print("r is odd -- pick a different a and retry")
        return None
    candidate = pow(a, r // 2, N)
    if candidate == N - 1:
        print("a^(r/2) = -1 mod N -- pick a different a and retry")
        return None
    d = gcd(candidate - 1, N)
    print(f"gcd(a^(r/2)-1, N) = {d}")
    return d

d = shor_factor(15, 7)
print("nontrivial factor of 15:", d, "-> 15 /", d, "=", 15 // d)

Expected output: period r=4, gcd computation yields d=3, and 15/3=5 — matching the worked example exactly. The brute-force find_period here is the one step Shor's algorithm replaces with QPE to get a polynomial-time runtime for large N; everything after it (continued fractions in the real algorithm, gcd here) is genuinely classical and fast either way.

🔗 Where this is heading

Shor's algorithm is the most dramatic speedup in this course — exponential, for a practically important problem. Week 9 steps back and asks an honest question about everything covered so far: what kind of speedup did each algorithm actually deliver, and for what kind of problem? The answer varies a lot — Deutsch-Jozsa and Bernstein-Vazirani's exponential/linear speedups apply to somewhat artificial oracle promises; Grover's quadratic speedup is genuinely generic but "only" quadratic; Shor's exponential speedup is for a real, important problem but needs hardware far beyond today's. Week 9 puts all of that into the formal language of complexity classes (BQP) so you can state precisely what's been shown.

B. Continued fractions find small-denominator fractions close to the phase estimate; the denominator found is (a divisor of) the sought period r.
